## Ruling proposed

Use one narrow **code veto** list in both programs: the primary's six exact codes, below, and **no invalid-record prefixes**. Require the actual record checks as well; this list is not a substitute for validating the record. The six extra names and seven prefixes do not uniformly establish absence of energy. A genuine anchor or semantic reduction failure must still fail strict validity; an incomplete timeout must still fail completion. No flagged-inclusive line can restore missing/invalid physics.

The governing text is [registration §6](https://github.com/mpmdw/JouleWise/blob/1c458d71d8a048e24b6c3a6b402fe3c34d9f57c3/docs/registrations/bytes_pack_v1.md#L102), especially its two different predicates:

> A run that the harvest excluded, or one without a usable record (missing bundle, output count not 512, non-finite or missing decode energy, re-reduction not succeeded, no decode timing envelope), removes its whole unit …

> … restores every unit excluded by a catalog code, whatever its class … provided each of its runs has a valid energy record. It never restores a run without one: harvest status not succeeded, a missing or unreadable bundle, a strict-validity failure or a token-count mismatch. It is labelled and decides nothing.

[Design Addendum 3 item 8](https://github.com/mpmdw/JouleWise/blob/1c458d71d8a048e24b6c3a6b402fe3c34d9f57c3/docs/design/bytes_pack_design.md#L204) says the twin's narrower restoration is replaced; [Addendum 7 D5](https://github.com/mpmdw/JouleWise/blob/1c458d71d8a048e24b6c3a6b402fe3c34d9f57c3/docs/design/bytes_pack_design.md#L286) expressly includes NUMBER-class catalog exclusions. Neither text says that every roster/model/records/lineage/code/pack/cell name invalidates energy. “Has a valid energy record” is different from “is eligible for the primary line.”

**Important qualification:** “valid” in the table means the energy record can be valid after its concrete checks, not that a different workload belongs in the primary registered result. Actual absent/ambiguous bundle, incomplete output, failed strict validity, failed re-reduction, missing/non-finite energy or missing timing always wins. DC-input unavailability removes the unit only from DC input/rest, as §6 expressly requires.

## Exact proposed aligned list and the deciding text

```python
INVALID_RECORD_CODES = frozenset({
    "member.bytes_missing",
    "member.bytes_ambiguous",
    "member.unreadable",
    "member.status_not_succeeded",
    "member.strict_validation_failed",
    "member.token_count_mismatch",
})
INVALID_RECORD_PREFIXES = ()
```

This is proposed text for the lead; no source constant was edited. Each exact entry is decided in the shared-six table. For every omitted member name and every removed prefix, the deciding text is §6's “restores every unit excluded by a catalog code, whatever its class … provided each … has a valid energy record,” qualified by the specific failure checks in the preceding paragraphs.

The shared semantic rule should say:

> A run has a valid energy record only if its harvest status succeeded; its selected bundle is unique, present, readable and strict-valid; its observed output count is 512; its re-reduction succeeded; and finite decode energy, positive decode duration and the required decode timing envelope/bounds are available. A catalog name does not replace these checks. Primary selection applies all registered catalog exclusions. Flagged-inclusive selection removes the same actual invalid records, restores the other catalog-excluded units, and recomputes the estimate using whole repeats and whole four-member quads.
