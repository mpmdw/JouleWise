# 14a. Citation verification for the related-work section

This file records, for each of the 37 references of `14-related-work.md`, what was fetched on 2026-10-07, what
the fetch confirmed, and the words of the source behind each statement the section makes about it. It was
written by the section's author (Opus 5.5) from the fetch log; the tables in parts 1 and 2 are generated by a
script that refuses to write this file if any quoted source text is not found in the fetched bytes.

How the checking was done.

- Bibliographic fields were read from the registry that holds the locator: Crossref (`api.crossref.org/works/`
  plus the DOI) for DOIs, the arXiv API (`export.arxiv.org/api/query?id_list=`) for arXiv identifiers, and the page
  or file itself for the entries that have only a URL. OpenAlex supplied abstracts where Crossref has none.
- For statements about content, the full text was fetched and read wherever a copy could be had without a login.
  PDF text was extracted with the operating system's PDFKit. For arXiv identifiers the text read is the arXiv
  version named in part 1, not the proceedings version; no difference between the two was looked for.
- All fetches ran between 22:48 and 23:29 UTC on 2026-10-07. The fetched bytes, their text extractions and
  the fetch log are kept outside the repository, in
  `/Users/edr/night-archive/gate-prune/wave-1007b/paper/13/` (`fetch-log.tsv`, `fetch/`). Each log line holds the
  UTC time, the URL, the HTTP status, the byte count and the SHA-256 of the body; part 1 prints the first twelve
  hex digits of that hash.
- Statements of absence ("does not give", "we found none") rest on searches of the extracted text, listed in
  part 4. Text inside figures was not searched.

## Part 7. How to repeat the check

1. For each row of part 1, request the URL shown and compare the fields named in the last column. The Crossref
   and arXiv calls need no key. Two publishers refuse requests that do not look like a browser (SPEC's PDF, Project
   Euclid's PDF); three refuse automated requests altogether (ACM, ScienceDirect, JSTOR).
2. Extract the text of each PDF and search it for the source words of part 2.
3. The author's scripts are in the directory named at the top of this file: `fetch.sh` (one fetch, one log
   line), `pdftext.js` (PDF to text), `check_draft.py` (finds every quotation of the section in the fetched texts
   and prints the registration line behind every source comment) and `gen_14a.py` (writes parts 1 and 2 of this
   file). They are working tools, not part of the repository.
