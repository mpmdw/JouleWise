Notes:
- K and L are the race the generation counter exists for. The timeout fires, then arm() or disarm() takes the lock before the watcher reacquires it. `self._generation != generation` handles this correctly. I forced the race deterministically with a Condition subclass that releases the lock after a timed-out wait.
- My first G case (limit 0.05s, sleep 0.03s) "fired" on both head and main. That was not a spurious fire. Background QoS stretched each sleep past the limit: a sleep of 0.12s measured 0.239s worst case under -b. So it was a genuine overrun, and the case was invalid.
- M (not reachable): only arm() and disarm() call notify, so this cannot happen in the runner today. If some other code notified the condition while the generation was unchanged, head would restart the full limit on each notify. In the test, head fired at 2.30s and main at 0.53s.
- N (pre-existing, unchanged): a limit above threading.TIMEOUT_MAX (about 9.2e9 s) raises OverflowError in the watcher thread, which kills it, and later arms never fire. main behaves the same. Real limits cannot reach this: `test_timeout_seconds` rejects non-finite values, and the overrides are 2400 s.
- One semantic difference with no practical effect: the timer now starts when the watcher thread re-enters `wait()` after the notify, not at `arm()` time. The difference is microseconds to milliseconds. It also trusts the C lock timeout instead of re-checking a clock after waking. CPython's timed lock acquire retries on EINTR against its own monotonic deadline, so this is fine in practice.

## (2) Does Condition.wait(timeout) read a Python-level clock in 3.13? No

- `inspect.getsource(threading.Condition.wait)` on 3.13.18 calls `waiter.acquire(True, timeout)`, `_release_save` and `_acquire_restore`, and no time function. Only `wait_for` uses `_time`. The timeout is enforced inside C (`_thread.lock.acquire`), which sys.monitoring CALL events do not see. The threading.py exclusion in ClockGuard therefore does not come into play.
- Dynamic check. /Volumes/JW-EXT/scratch/tmp-wd-review/tracer.py uses the same CLOCKS set and the same sys.monitoring CALL tracer as test_leaf_whole_window.clock_tracer, across all threads, over 2000 arms and a disarm:
  - head: `{}`
  - main: `{('shard_tests.py', '_TestWatchdog.arm'): 2001, ('shard_tests.py', '_TestWatchdog._watch'): 286}`

## (3) Is the new test meaningful? Only half of it

- Against main's shard_tests (/Volumes/JW-EXT/scratch/tmp-wd-review/mixed): the full new test FAILS, but only on the static check (`'_watchdog_clock' unexpectedly found`).
- With the static loop emptied, the dynamic half PASSES on main ("Ran 1 test ... OK"). The reason: main binds `_watchdog_clock = time.monotonic` at import, so `mock.patch.object(time, "monotonic", traced)` never intercepts it. The dynamic half therefore cannot detect the regression it is named for: a clock read reached through an import-bound alias.
- Minor: the test builds a `_TestWatchdog` in the test process, which leaves an extra daemon thread for the rest of the shard. The other watchdog tests use subprocesses. I found no thread-count test that would trip on it: test_member_pool compares counts before and after within one test.

**Exact fix:** replace the dynamic half with a sys.monitoring tracer run in a subprocess. That is the same mechanism as the ClockGuard inventory, and it avoids leaking a thread. I verified it on both trees using /Volumes/JW-EXT/scratch/tmp-wd-review/proposed_test.py: head OK, main FAILED.

```python
    @unittest.skipUnless(hasattr(sys, "monitoring"), "needs sys.monitoring")
    def test_watchdog_thread_reads_no_clock(self):
        source = inspect.getsource(shard_tests._TestWatchdog)   # keep the static check
        for name in ("monotonic", "perf_counter", "time.time", "_watchdog_clock"):
            self.assertNotIn(name, source)
        code = (
            "import sys, time; sys.path.insert(0, 'scripts'); import shard_tests\n"
            "clocks = {time.time, time.time_ns, time.monotonic, time.monotonic_ns,\n"
            "          time.perf_counter, time.perf_counter_ns}\n"
            "seen = []; m = sys.monitoring; tool = next(n for n in range(6) if m.get_tool(n) is None)\n"
            "m.use_tool_id(tool, 'wd-clock')\n"
            "def called(code, _o, fn, _a):\n"
            "    try:\n"
            "        if fn in clocks and code.co_filename.endswith('shard_tests.py'): seen.append(code.co_qualname)\n"
            "    except TypeError: pass\n"
            "m.register_callback(tool, m.events.CALL, called); m.set_events(tool, m.events.CALL)\n"
            "dog = shard_tests._TestWatchdog(30)\n"
            "for i in range(20): dog.arm('t%d' % i); time.sleep(0.005)\n"
            "dog.disarm(); time.sleep(0.05); m.set_events(tool, 0); print(sorted(set(seen)))\n"
        )
        result = subprocess.run([sys.executable, "-B", "-c", code], cwd=ROOT,
                                capture_output=True, text=True, timeout=25)
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout.strip(), "[]")
```
