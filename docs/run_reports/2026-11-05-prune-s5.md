## Equivalence evidence before and after extraction

Before any production edit, `python3.13 -B -m unittest tests.test_strict_io_contracts`
passed seven tests against the original selected functions. After the final
selection narrowed to 102 bindings, the original-code run passed again (1.765 s).
The first draft caught a `text=` versus `value=` keyword mismatch and excluded
that singleton before extraction. Every extraction commit ran the seven-test
contract module successfully before commit.

The seeded property vectors (seeds 505–511) cover nested JSON, non-ASCII and
astral characters, lone surrogates, NaN/infinities, negative zero, huge integers,
mixed/bad types, duplicate-key order and exact refusal text, key-set errors,
path spellings, random byte buffers and file sizes straddling 1 MiB boundaries.
Durability tests cover output bytes, cleanup, injected open/fsync/close/rename
failures, complete staging contents and file-close-before-rename ordering.

A stronger stack-headroom test then demonstrated that forwarding strict-JSON
numeric callbacks is **not equivalent**: the wrapped input float callback
refused at pressure depth 160 while the original admitted the same scalar JSON.
Those ten original callbacks were restored verbatim; the shared numeric
implementations were removed. The eight-test contract suite passed after the
repair, and the retained regression checks float/int admission at 60 stack
depths for every callback. This is a protected context, despite identical
arithmetic bodies.
