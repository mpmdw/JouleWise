## Implementation

- `scripts/night_chains/align_r1_rehearsal.zsh` is the chain for a normal
  registered `run_night` plan. It requires the WP15 runtime executable,
  validates `sudo -n -l`, proves Automatic restoration before runtime work,
  and installs an EXIT/HUP/INT/TERM restore trap using exactly
  `sudo -n /usr/bin/pmset -c powermode 0`. It consumes only the corresponding
  `powermode 2` command for High Power.
- `scripts/align_r1_rehearsal.py` runs pre/post calibration brackets, 30-minute
  idle soak, 30B and D step tests (the WP15 `step-d` operation is contractually
  the 10k-fed-prefill + 4,096 seeded decode), a ten-minute cooldown after each,
  one X-G contrast, held/gated D spam and benign s1 members, optional D-4bit,
  High Power A-B-A, then authenticated harvest through the same WP15 seam.
- The runtime seam is intentionally narrow and marked: WP15 receives only
  `--r1-kind`, `--output`, and optional `--duration-s`. WP17 does not duplicate
  model, SMC-journal, gate, hold, calibration-custody, or harvest code.
- Both shell and Python layers restore Automatic. Python verifies the narrow
  sudo listing, records `pmset -g custom` before/after every A/B/A setting, and
  restores in context teardown plus an unconditional final attempt. Setup
  refusal, runtime error, KeyboardInterrupt/signal-equivalent abort, normal
  completion, and teardown are covered.
- `registration/r1_slots.json` declares S1-S9, B_D, I_D, T_dead, N_chunk,
  t_decline and class. It remains visibly pending in the committed kit; a
  successful R1 writes a complete replacement only after every slot is finite
  and class is `heavy` or `light`.
