# PR #795: audit 3 on `4eaa14016`, the lead's rules, and what changed

Audit 3 found four HIGH findings and one MED. The four HIGHs share one root: the executor accepted a name or a copy
that its caller controls as authority. That meant a path's spelling, a label on a digest, a link to the manifest, and
a RUN_STATE path. The lead set four rules (P1 to P4). Every input here is generated; no custody, energy, meter or
restricted file was opened.

## The rules, as built

**P1. Physical identity.** Paths are compared by what they are on disk, never by how they are spelled.

- Every registered root and destination refuses a symlink in any component. Each component is `lstat`ed
  (`interim_release.no_symlink_components`, `manifest._plain_path`).
- Containment is decided by the `(st_dev, st_ino)` of each ancestor (`interim_release.physically_within`). On a
  case-insensitive volume, a case variant of the repository's path is therefore the repository.
- `LookLayout` refuses a root that lies inside the repository or holds it.
- `private_temp` refuses a staging directory inside the root or the repository.
- `release.destinations` refuses three things: a custody root inside the repository or holding it, a public root
  that is not inside the repository, and custody and publication sharing a physical directory.
- Stage 2 compares the ledger's custody root with the manifest's by `samefile`.
- `verify_pins` reads the manifest only as a regular file with no link on its path. A committed manifest must also
  lie physically inside the repository. Each pinned file is read only with no link on its path.

**P2. Full hex, explicitly labelled (RL-195 Q2).** A span binds only on an explicit "Offload manifest"
identification whose full 64-hex digest equals the pin (`custody_pins.check_binding`).

- **Identified.** The label's last manifest word is "offload manifest". Only punctuation, `sha256`, a file count or
  a readback's word may stand between it and the digest.
- **Contradiction.** The item may print other digests for the span under a manifest label or as a readback: an
  offload manifest, a look manifest, a bare `manifest`, `SHA256SUMS` or a "readback". Each must agree with the pin,
  in full or in every printed character. One disagreement holds the span.
- **Held, never bound:** an abbreviation alone, a pending digest, a digest under another label, or any mismatch.
  `correct-check` moves a `check_item` only to an item that binds.
- The eight-hex abbreviation is for text shown to a person only; the code no longer has a floor constant.

**P3. Public evidence from `origin/main` only.**

- No look command takes a RUN_STATE path or a git ref:
  - `--run-state` is gone from `cadence_look_manifest.py` (`validate`, `check-inputs`, `correct-check`) and from
    `cadence_look_input_review.py` (`review`, `check`);
  - `--ledger-ref` is gone from `cadence_look_run.py` and `inclusion_34.py`.
- Each committed run and the cold checker first fetch origin's `main` (`manifest.fetch_public`). They then read
  RUN_STATE.md with `git show origin/main:RUN_STATE.md`. A failed fetch refuses.
- The committed LOOKS.json must also be byte-equal to `origin/main`'s (`committed_ledger`). An older commit on main's
  history cannot show as committed a look that main has since spent.
- Tests pass a RUN_STATE through a keyword argument of `main(..., run_state_text=...)`, which the CLI cannot reach.
  The executor's test harness patches the reader in its own process.

**P4. Stage-1 floats.** Two schemas were checked, and they decide what can reach a public file:

- **PUBLIC.json.** Its schema is closed and admits only strings and one integer.
- **LOOKS.json.** The ledger holds no float. A later status adds sha256 fields only.
- **stage1.json.** It is written only at `<registered root>/lm-interim-01/stage1.json`, which lies physically outside
  the repository. Only its sha256 is public: in LOOKS.json, and in PUBLIC.json as `stage1_sha256`.

**The sweep.** Each registered path is tested against a symlink, a case variant and a place inside the repository.
The registered paths are:

- the custody root and its parent;
- the look's directory, a span directory, a fixed input and a fixed output, and the archives directory;
- the staging directory;
- the ledger's custody root and the public root;
- the look manifest and a pinned code file.

The tests are `PhysicalIdentity.test_sweep_a_symlink_on_any_registered_path_refuses`,
`test_sweep_a_case_variant_on_any_registered_path_is_decided_by_physical_identity` and
`test_sweep_a_place_inside_the_repository_refuses_on_any_registered_path`. Two paths must lie inside the
repository: the public root and the manifest. For them a case variant is the same physical place and is accepted.
Every other variant refuses. The case-variant tests skip on a case-sensitive volume, where a case variant is another
directory, as on the hosted CI runners. They ran here on the case-insensitive APFS volume.

  keeps the plain sha256". The disclosure sentence in `custody.disclosure` says "The public file carries the sha256

## Consequences in the tests

- **Real origins in the tests.** Each repository copy (`look_minirepo`) has a local bare origin, and publishing a
  commit pushes to it. A committed run's fetch therefore reads what was published, and a commit that was not
  published is not public.
- **Paths with no link on them.** The tests' temporary repositories and the harness's pin directory are their own
  realpaths, because a system temporary directory may sit behind a link (macOS: `/var`).
- **Binding tests.** The historical public phrasings now hold the span, since none is an explicit "Offload manifest"
  identification in full hex. Tests that bound on an abbreviation or a bare `manifest` label now expect HELD, and
  the corrections use full-hex items.
