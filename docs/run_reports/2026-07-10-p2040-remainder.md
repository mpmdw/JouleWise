## Per-Unit Status

### FIX-7a — complete in worktree

- Added exported `ConfigKeyWarning(UserWarning)` with code
  `unknown_config_key`, exact dotted paths, deterministic lexicographic
  emission, and schema-0.1 warn-and-ignore wording.
- Central allowlists cover the root plus `model`, `quantization`,
  `hardware_target`, `workload_profile`, `interconnect`, `sampling`, and
  `run_metadata`. Non-object typed sections still fail as `SchemaError`
  without child inspection.
- Construction warnings reach stderr through Python's warning channel and are
  retained as structured diagnostics. Controller bundles always write a
  `metadata.json.config_warnings` list; ignored values themselves are never
  preserved.
- Diagnostic state is excluded from config equality/representation and
  `to_dict()`. All pinned normalized-config hashes remain byte-identical.
- Exported config JSON Schema now declares
  `x-joulewise-unknown-key-policy: warn-and-ignore` and does not set
  `additionalProperties: false`.

### FIX-7b — complete in worktree

- `sampling.warmup_seconds` remains schema 0.1 config identity and now executes
  through the injected clock after every active warmup call and alignment
  capture, before warmup completion/measured-run/sampling markers.
- Positive settling waits are runtime-logged. Warmup completion metadata
  records `warmup_runs` and `warmup_seconds`; zero performs no additional
  clock advance.
- The production-shaped mock controller test pins active warmup completion at
  +0.05 s, settling start immediately afterward, and measured-run start exactly
  +7.25 s later, outside the measured sampling window.

### FIX-8 / ARC-6 — complete in worktree

- Added `BundleReader.runtime_cleanup_ok() -> bool | None`. Any well-formed
  false cleanup completion dominates; all-true is true; absent/non-boolean
  evidence is null.
- Added nullable `MeasurementQuality.runtime_cleanup_ok`, its output-schema
  property, reducer propagation, and legacy additive-absence tolerance.
- Successful controller runs now reduce cleanup events to true or false.
  Adapter failure and exception mutations both retain `status=succeeded`, null
  failure reason, and unchanged current-run energy/window semantics while
  emitting false in memory and on disk.
- Controller failures before a normal cleanup completion retain null.
