   gate; not an S-13 table row";

   inside Block 6. Their Block 6 values print with the label `single-source`");
5. any other one-producer key -> "not independently recomputed" (§17-R3: "Where there is one producer,

## STOP items (need a research-lead ruling; the generator does not guess)

1. **RL-99 scope.** The generator applies `single-source` only to values that are fields of B5.make_reported
   or B5.make_floors output for the registered selection (`reported/*`, `floor/*`, and `dominance/*/R`, `R_cm`
   copied from make_floors). The §9.5 lines that rerun make_reported on another unit set, the scaled-allowance
   line and the single-step line get §17-R3's default "not independently recomputed". Both labels mean one
   producer. The lead decides whether RL-99's "cell and floor estimators" covers those lines, and whether
   `dominance/*/R`, `R_cm` count as floor-estimator output. Either answer is a one-line rule change in
   `classify_session`.
2. **The draft's "computed and compared" rows contradicted above** (10 contrast fields and 7 cross_session
   fields). Either §17-R3 prints them as one producer, as generated here, or check_block must be extended
   to produce them. That is a code change, not a label choice. Moving the 4 gate-only fields into the table
   (CHK:103 `exposed`) would make them S-13 rows.
3. **Gate-only wording.** The label "computed and compared inside the option (c) gate; not an S-13 table
   row" is this generator's wording, not registered text.
4. **Copied-disclosure families.** The draft's 8 rows (`monitor_cost` … `block5_codes_carried`, decision 6 (b))
   are not keys in `production_comparison_keys.json`, so they are out of this generator's scope and stay
   hand-entered.
