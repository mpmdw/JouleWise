The script reads `production_comparison_keys.json` and `precision.json`, parses
`joulewise/b6_analysis_check.py::check_block` and RC-B6-1 (`scripts/independent_recompute_b6.py`)
with `ast` (check_block has no importable key table), and imports only RC-B6-1's `decimals_for` and
`quantity_class` for the bar column. It prints each input's SHA-256, so the table is tied to the bytes
at the pinned commit. Line numbers below (CHK = b6_analysis_check.py, RC = independent_recompute_b6.py)
are at `e93ed8144`; the generated table recomputes them from the AST on every run.

Label rules, applied in order:

1. session key is a row of check_block's comparison table (CHK:51, CHK:74, CHK:101-103) ->
   "computed and compared" (decision 6 (a)); block-scope rows (CHK:120-148) -> "§10-§11 arithmetic computed
   and compared; session inputs as labelled at session scope" (RL-102 item 4);
2. the result field behind a printed key is checked inside the gate but is not a table row
   (CHK:96-107: `s_d_j`, `decision_interval_j`, `outcome`) -> RL-103's labels, the check family in Source,
   and the gate's bar (5e-6 absolute on unrounded values, read from `check`'s default at CHK:28; exact for
   the word);
3. per-phase whole-machine line -> the literal RC-B6-1 stamps on it (RC:1177), which check_block also
   lists as `single_implementation` (CHK:151) -> §17-R8 label;
4. one producer, value a field of B5.make_reported / B5.make_floors output for the registered selection
   -> `single-source` (RL-99 item 1: "The ALPHA and BETA cell and floor estimators have no second producer
   inside Block 6. Their Block 6 values print with the label `single-source`"). A key that is a copy of such
   an output (`dominance/<model>/<phase>/<mode>/R`, `R_cm`, copied from `floor["R"]`, `floor["R_cm"]`) takes
   the same label (RL-101);
5. any other one-producer key -> "not independently recomputed" (§17-R3: "Where there is one producer,
   label it 'not independently recomputed'").
