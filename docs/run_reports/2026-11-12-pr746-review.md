## Findings

### 1. MEDIUM: the printed "95% interval" leaves out the pulse-side uncertainty, and the outcome sentence does not say so

The rule assumed each run brings its own calibration capture. In the data every kept run in a session carries one byte-identical capture, so the pulse median is constant in all 2,000 resamples. The results file says this in a paragraph, but the outcome sentence and the PR's headline numbers print a bare "95% interval".

Is the outcome still honest? Yes for the row. As a reviewer sensitivity check only, I resampled the 59 pulses within each capture alongside the runs:

| T | Printed interval (ms) | With pulses resampled (ms) |
|---|---|---|
| Pooled rise | [−3.0, +14.8] | [−6.4, +13.3] |
| Pooled fall | [−7.5, −1.9] | [−9.7, −0.5] |
| GAMMA rise (widest) | [−7.5, +27.4] | [−10.4, +27.6] |

All stay inside the smallest b (44.6 ms), so the reading is row 1 either way.

Fix:
- Add one sentence to the outcome block, and to the §4.2 paragraph when it is written: "The intervals resample inference runs only; each session has a single calibration capture, so the uncertainty of the pulse median is not included."
- Log I2 in `DEVIATION-LOG.md` as a departure from the rule's premise.
- Do not print my sensitivity intervals as results. Rule §6 allows no second estimator; they belong in this review only.

### 2. MEDIUM: the pooled rise T is worded more broadly than its support

- All 51 Qwen3-1.7B request starts are excluded (41 in ALPHA, 10 in GAMMA), because the 1.7B prefill of about 620 ms puts the transition inside the +800 ms window. The pooled rise T rests on 43 Qwen3-8B request starts from BETA (33) and GAMMA (10).
- The pooled pulse reference still includes ALPHA's 59 pulse-on edges, although ALPHA contributes no inference rise. That is not like with like across sessions, and it is not among I1–I12. With pulses from BETA and GAMMA only, the pooled rise T is +2.7 ms instead of +1.8 ms. The reading does not change.
- The sentence "no pulse-to-inference difference … for rises" reads as covering all inference rises. It covers one model in two sessions.

Fix:
- Keep +1.8 ms; the rule's "pooled over the three sessions" is literal.
- Word the rise clause as "for rises (Qwen3-8B request starts only, two sessions; Qwen3-1.7B request starts could not be tested)".
- Add the ALPHA-pulse point as I13, with the +2.7 ms session-matched value beside it.
- Log the failed assumption (a) in `DEVIATION-LOG.md`.
