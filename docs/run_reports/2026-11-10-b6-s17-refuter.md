## Decision 7b: structural answer, not a ruling

**The primary per-phase arithmetic can be reused unchanged; the inspected Block 6 program has not yet wired it in.** Therefore code inspection supports feasibility, but does not establish that the eventual pinned Block 6 line is actually produced that way. I do not select 7b's released-value branch or its fallback.

The inspected B5 program has SHA-256
`d49103e884ccae47242b8efb91ea1f5764e4505a4ad5e54558cc42a399a2e4e0`.
Its complete bytes agree at `ab1e0098d`, `60d3225ee`, `b063b578a`, and the reviewed head. This identifies code available at the analysis/release lineage. I did **not** inspect a release receipt to authenticate its recorded recompute digest; the heavy analysis tag and the recompute's separately recorded digest are distinct evidence. The lead must confirm that this hash is the release-pinned recompute hash before relying on this answer.

The relevant call chain is:

1. `machine_member` (I:2043–2126), called for `prefill` or `decode`, receives member records/edges/clock anchors, meter streams, a journal and `bop`. It performs clock placement, coverage checks and the gross meter calculation. For a phase it returns before the request-only battery addition / idle subtraction (:2098–2105).
2. `sampled_gross` (:1985–1990) takes the sample mean over the half-open phase span and multiplies by phase length.
3. `phase_machine_mean` (:2310–2324) drops a whole unit if a member lacks a finite meter value and uses `diagnostic_estimate` (:2169–2180), then `reported_estimate` (:1281–1297). It retains estimator 1's fixed stratum weights, statistical interval, missing counts, gross share and activity disclosure.
4. The edge-shift orchestration (:2521–2536) reuses the member's original stream, computes four corners using the supplied session `bop` plus the stream residual, and invalidates corners whose unit counts change. It is surrounding code in `add_machine`, not part of `phase_machine_mean` itself; preserving just that named function is insufficient to preserve the entire uncertainty line.

These arithmetic functions have no block-number or Block-5-session assertion and no direct filesystem calls. B6's `Session.member` already constructs `B5.Member` with the session's bound (B6:262–273), and its selection uses `B5.Window.select` (B6:275–281). The required member interface therefore exists in the candidate code. Authenticated decompression and session-specific selection/bounds can be supplied outside the arithmetic functions, preserving their bodies. This is a static interface conclusion, not real-data validation.

However, B6:94–95 defines `WHOLE_MACHINE_NOT_COMPUTED`; B6:558 emits it. The inspected script has zero calls to `B5.machine_member`, `B5.phase_machine_mean`, or `B5.add_machine`. Its present output is consequently no evidence that 7b's same-function condition has been met. I did not inspect or assume any later seat-7 implementation.

The B5 top-level driver is also not a drop-in compressed Block 6 driver: I:2407–2418 searches plain meter streams and returns `not_computed` when only compressed streams exist. Seat 7 must supply the authorized read path and wire the unchanged functions, including the corner logic. DESIGN §8's proposal to compute a new Block 5 value (:852–854) is expressly displaced by RL-25:666–670; it must not be revived through that design reference.
