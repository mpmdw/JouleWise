# PR #795: audit 2 on `98fedf875`, the lead's ruling, and what changed

Audit 2 found five verified HIGH findings. Four share one root: the executor trusted free-form path and list
arguments. The lead ruled that this freedom is removed, not validated. All inputs here are generated; no custody,
energy, meter or restricted file was opened.

## The ruling, as built

**1. A fixed layout, and no path in any command.** `cadence_look_run.py` accepts no path option. The commands are:

- `stage1 [--allow-draft] [--ledger-ref REF] [--ruled-exclusion ...] [--stage-archives] [--level-r]`
- `stage2 --stage1-sha256 HEX [--allow-draft] [--ledger-ref REF] [--level-e]`
- `post-no-maxima`
- `host-id`

Abbreviated options are refused, so a former `--stage1` cannot be taken for `--stage1-sha256`.

The manifest sits at its fixed place in the repository and registers one root, `custody.root`. Every other path is
that root and the look id (`manifest.LookLayout`):

| Fixed place | What |
| --- | --- |
| `<root>/<span id>/` | a roster span's custody copy |
| `<root>/lm-interim-01/roster.json`, `rules_3_4.json` | stage 1's inputs |
| `<root>/lm-interim-01/stage1.json`, `level_r.json` | stage 1's outputs, each created once and never replaced; stage 2 reads `stage1.json` |
| `<root>/lm-interim-01/superseded_stage1.json`, `superseded_level_r.json` | a ruled rerun's kept files |
| `<root>/lm-interim-01/archives/<span id>.tar`, `.SHA256SUMS`, `.marker.json` | pulled archives (`--stage-archives`) |
| `<root>/lm-interim-01/RESTRICTED/` | stage 2's reservation |

Every path is checked before it is used:

- it is absolute and its own realpath;
- no component is a symlink;
- it lies inside its root;
- no name beside it differs from it only in case.

The root must lie outside the repository, where the public roots are.

Staging writes nowhere a look's files or its public report live. An archive is expanded into a fresh private
directory outside the root and the repository, and that directory is removed when the stage ends.

The public result is written only by the reservation step. Stage 2 refuses, before reserving, in two cases:

- a ledger `custody_root` that is not the manifest's root;
- a file beside `RESTRICTED` or `PUBLIC.json` that differs from it only in case.

**2. One source of pins.** The pin list now lives in the manifest itself (`inputs.pins`), and the file that held it
is deleted. Every reader reads it from the manifest:

- `check-inputs`, `pin-inputs` and `correct-check`;
- both stages, which hand the verifier the list's canonical bytes;
- the twin's wrapper;
- the cold review and its checker.

The cold review now takes only `--repo`. It reads each span at `<root>/<span id>`, writes its record once to
`<root>/lm-interim-01/input_review.json` and checks it from there. Its "N of N" is the manifest's N.

**3. Exact, span-keyed binding.** A digest in a RUN_STATE item belongs to the nearest name before it. A name is a
span id, an offload directory such as `cq-<span>-a1`, another series' span or a kit. A span's Check binds only on
the manifest-labelled digests that belong to it. The rules:

- **Exact equality.** A full print must match all 64 hex digits. An abbreviation must print at least eight hex
  digits, every one of which matches.
- **Every one must match.** All the digests the item prints for the span must match. One mismatch holds the span.
- **Ownership.** A digest that belongs to another name never binds.

## Consequences in the tests

- **Translated command lines.** The executor takes no path, so the tests' former command lines are placed on the
  fixed layout by `tests/cadence/look_layout_fixture.py`, which belongs to the tests. Only the test harness names a
  manifest to the executor in place of the repository's. A copy of the repository (`look_minirepo`) carries its own
  root and pins.
- **Stage 2's pins.** Stage 2 now runs under the pins its stage 1 ran under, as a committed look does. A custody
  copy changed between the stages is therefore refused by its pins. The custody-binding backstops behind the pins
  are tested in-process.
- **Invariance.** The pins are in the manifest, so in RL-195's 1.3 test the manifest's sha256 moves with the
  journal's pin, as does `input_sha256`. Both are sha256 fields, and the output is byte-equal with them masked.
