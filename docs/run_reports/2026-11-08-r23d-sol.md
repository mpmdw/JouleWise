  biconditional “ordinal in 1–4 iff role is anchor.” Existing ID validation
  then requires anchors to have the matching `W1:` prefix, rejects an empty
  suffix or extra colon, and rejects prefixes on non-anchors. Analyze checks
  manifest and observed W1 slots; `io.load` checks manifest and export roster;
  `raw.window` checks slots before member reads. The existing anchor diagnostic
  separately enumerates 1–4 to check block completeness; it is not another
  admission validator.

  Frozen R15 roster matching, identity/seed checks, exclusions, retries, fits,
  thresholds and T assignment accounting are unchanged. The CLI still combines
  calibration/W1 records with the T-only load. Removed selection fields were
  ignored by analysis when W1 was present; selection-only inputs still refuse.
  A scorer-code change invalidates earlier threshold freezes through the
  existing loaded-scorer binding; use a freeze made at the candidate head.
- **Release boundary:** Leniency is confined to the trusted in-memory API's
  synthetic mode. File loading and `raw.window` pass `strict=True`
  independently of the document's synthetic flag. The reviewed CLI always
  uses that loader. This conclusion covers these engine/export entry points;
  the forbidden comparator and release scripts were not inspected or executed.
- **Test quality:** Positive K=12 and explicit refusal witnesses exercise both
  manifest and observation paths, raw refusal before member reads, strict IDs,
  synthetic leniency, selection removal, retry reasons, battery streaks and DC
  row structure. These are behavioral assertions, not merely smoke tests.
