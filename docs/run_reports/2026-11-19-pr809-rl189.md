## The route taken for the descriptor path (RL-189 1.2)

**The first route.** No member file is read to find the mirror.

- The invoker calls the frozen `r1_runtime.load_config` on the runtime
  config path that row 0 binds, and requires the returned sha256 to equal
  row 0's.
- It calls the frozen `r1_runtime.read_template` on the template that config
  names for the member, and takes `model.source` from it.
- The member-to-template map (`TEMPLATE_KEYS`) restates the frozen dispatch:
  `model_30b` for the capture predecessor, `d_spam` for Step D, `d_bank` for
  D bank and `x_g` for X-G. D3 tests that map on every run: a member whose
  own `config.json` names another `model.source` fails.
- The read follows links, as the frozen `read_text` does. The issued 30B
  template names a Hugging Face snapshot directory, where `config.json` is a
  link.
- The observation is made when the frozen `_run` returns or raises, and it
  joins that member's row. A member refused before launch has no field. The
  soak ledger and the idle row are unchanged.
- The row holds 64 lowercase hex, `absent` or `unreadable`. An observation
  that cannot be made (no path, an unreadable template, a changed runtime
  config) is `unreadable`. The row is always written.

## The four event-timestamp cases

Suite v2 requires the prefill-start event to equal the turn's start stamp.
The variant this branch carried accepted any start between the start stamp
and the prefill end, after the resolver's decision of 2026-11-18
(`pl-809/resolve-4`): the pinned endpoint stamps the turn before
tokenization.

Both hold under one rule, in `_recompute_turn_boundaries`:

> A prefill start later than the start stamp is accepted only when the
> turn's recorded `tokenize` and `generation_setup` events lie in order
> between the two. With none recorded the two must coincide.

- The pinned producer always records those phases before prefill
  (`mlx_runtime.py:775-842` and `endpoint.py:750-752` at `b2e01464d`), so a
  native stream is judged by order, as the resolver ruled.
- The suite's synthetic streams record none, so a shifted prefill start has
  no witness and is refused (`turn_boundary_recompute`, field
  `prefill_start`).
- This rule is the builder's reading. It meets v2 as issued and is no
  looser than the resolver's decision on a native stream. A re-issue of the
  suite with the resolver's one-line correction would also pass.
