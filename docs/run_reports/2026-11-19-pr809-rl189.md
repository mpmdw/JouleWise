## The four event-timestamp cases

Suite v2 requires the prefill-start event to equal the turn's start stamp.
The variant this branch carried accepted any start between the start stamp
and the prefill end, after the resolver's decision of 2026-11-18
(`pl-809/resolve-4`): the pinned endpoint stamps the turn before
tokenization.

Both hold under one rule, in `_recompute_turn_boundaries`:

> A prefill start later than the start stamp is accepted only when the
> turn records the producer's whole pre-prefill sequence (`tokenize` start
> and end, then `generation_setup` start and end), in order, between the
> two. With none recorded the two must coincide. A partial, repeated,
> reordered or misplaced sequence is refused.

- The pinned producer always records that sequence before prefill
  (`mlx_runtime.py:775-842` and `endpoint.py:749-752` at `b2e01464d`), so a
  native stream is judged by order, as the resolver ruled.
- The suite's synthetic streams record none, so a shifted prefill start has
  no witness and is refused (`turn_boundary_recompute`, field
  `prefill_start`).
- This rule is the builder's reading. It meets v2 as issued and is no
  looser than the resolver's decision on a native stream. A re-issue of the
  suite with the resolver's one-line correction would also pass.

**The window.** `r1_runtime.main` stamps `started_epoch_s` before a segment

- **The mapping.** Each comparison now goes through the frozen

  turn's end (or the episode's opening stamp) and the turn's start. A tool

- **Tool times.** A tool call's monotonic time must agree with its converted

- **Same-clock comparisons.** Two values on one clock still compare

## Audit 2 of 2026-11-21: derive, don't trust

Audit 2 blocked `3b4518497` with four false passes. Suite v3.1 still
reported 0 wrong passes over its 25,083 cases. The lead named one class: X_G
trusted a recorded field, or the absence of an observation, where frozen R1
derives it from the raw journal. The directive has three items, D1 to D3.
Each finding is a named regression, and a generated sweep covers every
derived field in the inventory below.

| Audit finding | Fix | Refusal now |
|---|---|---|
| An unobserved X_G G1 with every copy of its exit slope set to 1,000,000 | D1, D2: the exit view is derived for every gate outcome | `evidence_unverifiable`, field `N5.exit_slope` |
| The idle soak's terminal closed one second after it opened | D1: the soak's window and duration are derived from its records | `member_order` |
| The quiet predecessor's census without `end`, with `end` twice, or reversed | D3: the census structure `Segment.run` writes | `quiet_load`, field `census` |
| Every X_G journal row's session ID set one nanosecond past its opening stamp | D1: the frozen Sidecar re-derives every journal row | `sidecar_derivation`, field `session` |

**D1, derive, don't trust.**

- **Every sensor journal row is written again by the frozen Sidecar.** This
  covers the soak's journal, Step D's two journals, and the D_bank and X_G
  journals.
  - `_replay_frozen_sidecar` drives `thermal.Sidecar` with only what it
    cannot derive: the recorded stamps, the raw reading of each key (value,
    error and the reader's raw fields), the status, and the gate events.
  - Each row it writes must equal the recorded row. That covers the session
    ID (from the opening monotonic stamp), the sequence number, the joined
    error string, `raw`, the reading projection (source, units, values,
    errors) and the closing coverage report.
  - The evaluator's own sidecar check restated the units rule. The frozen
    `thermal.sample` also gives `raw` for a key that is neither a
    temperature nor a fan; the replay now decides that.
- **The gate exit is one derivation, whatever the outcome.**
  `ThermalSession._wait` keeps the exit sample, the release temperatures and
  the exit slope from its final poll: the last visible row, its two
  temperatures, and `slow_slope` over the same rows at the same instant.
  - That joint view is now derived for timed-out, unobserved and deadman
    exits too, not only for releases. The final poll lies at or after the cap
    (timeout), at or after the unobserved limit, or anywhere in the wait
    (deadman, which may also end before any poll).
  - A deadman exit's entry fields are now derived as well. They were skipped.
- **The soak's window and duration are derived.**
  - Every soak journal row lies inside the soak's terminal bracket.
  - The sensor session spans `duration_s` on the monotonic clock, as
    `Segment.idle` loops until it has, and so does the bracket.
  - The archived replay now derives the soak's series from its journal
    instead of taking the receipt's copy.

**D2, no skip on unobserved.**

- **No skipped exit checks.** The exit slope of a timed-out or unobserved gate
  was never compared, and a deadman exit skipped its entry check. Neither is
  skipped now.
- **A null exit slope on a release or a timeout refuses as
  `evidence_unverifiable`.** Every poll of such a wait saw coverage, so frozen
  code always records a number there.
- **An unobserved gate's exit slope must be the frozen reducer's value on the
  final view, null included.** The outcome itself declares the state
  unobservable, and the Part C lines decide whether that is allowed. Only X_G's
  G1 may be unobserved, and it must carry `thermal.state_unobserved` in every
  source. Audit 2's matched-null control passes; the 1,000,000 contradiction
  refuses.

**D3, exactly once.** `Segment.run` takes the process census at `start`,
before the member, and at `end`, after it. Each is taken once, on the load
journal's monotonic clock, around every CPU sample.

- **Quiet members** (the predecessor and Step D) must carry both points,
  once each, in that order, with a span that holds the whole sample series.
  An omission, a duplicate, a reversal or an unknown label refuses.
- **Soak and gated members.** The frozen suite's synthetic soak has only
  `start`, and its gated members have no census. Requiring the producer's full
  structure there would refuse the suite's clean control. So the points
  present must be a duplicate-free prefix of `start`, `end`, and the soak must
  have `start`. This is the open item below.

**The inventory and the sweep.** `tests/align/partc_derived_sweep.py` builds
one clean attempt with the frozen suite's control. For each of 24 inventory
entries it generates mutations that change only the recorded value, so the
record no longer equals its frozen derivation, and calls the evaluator's
derivation on it.

| Group | Entries |
|---|---|
| Sidecar rows | session ID, sequence, schema and module, error string, `raw`, the thermal policy, the reading projection, boundary stamps, coverage, collector error |
| Gates | entry sensors and slope, exit sample, release, exit slope, reference, outcome |
| Load journal | census points, census order and span, the receipt's copy of the journal |
| Windows | member window, Step D's member wall, the soak's window and duration |
| Soak | the series |

- All 443 generated mutations refuse, and every clean record passes. It runs

  `FrozenDifferentialNamedCasesTests.test_every_derived_field_recorded_otherwise_refuses`.
- Receipt-level derivations (token counts, slots, energy, budgets and the

  shape against the frozen oracle.
- The journal-level derivations are the ones audit 2 showed v3.1 does not

**Open for the lead.**

- **Census `end` for the soak, and the census for the gated members.** The
  frozen producer writes both points for every member. The frozen suite's
  synthetic soak has only `start`, and its D_bank and X_G load journals are
  empty. So requiring the full structure there would refuse v3.1's clean
  control. Here they are held to the duplicate-free prefix. A v3.2 fixture
  that writes both points would let the full rule apply everywhere.
- **A null exit slope on an unobserved gate.** The directive says a null
  slope from constant readings is unobservable, not a pass. Here a null that
  the frozen reducer derives on an unobserved gate's final view is accepted as
  that gate's record, because the gate's outcome already says it was
  unobservable. A rule that refused it would refuse nearly every unobserved
  X_G G1, since coverage loss is what makes both the gate unobserved and the
  slope null. X_G's permission for an unobserved G1 would then be void in
  practice.
