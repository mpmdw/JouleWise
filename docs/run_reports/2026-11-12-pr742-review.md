4. **LOW. The two meter checks now take the killed stream's offset from the same function the desk uses.**
   `joulewise/align/w1_prequal.py:1697`, `:1754`.
   The check builds the member span with `kp.raw_offset_ns(first, allow_unclosed=True)` and `km003c.capture_member` (`km003c.py:134`) adds the same value back, so an error in that function cancels.    Fix: take the offset independently, for example `first.header['start_raw_ns'] - first.header['start_mono_ns']` read in the check, or the check process's own `clock_gettime_ns(CLOCK_MONOTONIC_RAW) - monotonic_ns()`.

5. **LOW. The stand-in meter's offset is read with two separate clock calls.**
   `joulewise/align/w1_prequal.py:1551-1552`.
   `OFFSET` is too large by the time between the two calls. If the child is descheduled there, every `rx` sits that far in the future and `MeterLiveness` skips a batch read sooner than that after its scheduled time. A later poll recovers, so the worst case is a slower ready, not a wrong verdict. On Linux, RAW and MONOTONIC also drift apart under NTP slew (parts per million; negligible over these seconds-long windows).
   Fix: none required. If it ever flakes, subtract 1 ms from `OFFSET`.
