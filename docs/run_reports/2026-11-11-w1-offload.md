## Changes

Relative to the base, `scripts/offload_window.py` has **+27/-5 lines**;
`tests/test_offload_window.py` has **+267/-1 lines**. Bound-file diff: **none**.

1. `Gate.verify` repairs a missing second-copy queue entry on its existing-Air-
   receipt return path, while holding its existing per-window lock. It leaves
   an existing queue entry and the Air receipt untouched, and does not enqueue
   a window whose second-copy receipt already exists. Receipt fields and
   verification checks remain unchanged.
2. Before treating a local Air receipt as completed work, `_run_stages` asks
   the Air's `stat` for the local manifest digest. A missing Air receipt makes
   the admission estimate include push/verify again. Once packing/adoption
   succeeds, an explicit remote `receipt_manifest_sha256: null` clears only
   the stale local `receipt-air.json` retry marker before push. This allows a
   newly verified receipt to pass the existing `write_once` check, including
   after an interrupted retry. An unavailable Air preserves the local marker.
   Existing packs/manifests are reused byte for byte; originals stay until
   the unchanged release checks pass. Every resumed run also calls the
   idempotent Air verify, so a lost queue entry can actually be repaired.
3. `_supervised` records `rc: 1`, `outcome: unexpected_error`, and the exception
   type/message before re-raising an ordinary unexpected exception. The child-
   process regression proves that the OS exit code, per-window span, activity
   span and end-journal row agree. Existing refusal/I/O handling is unchanged.
4. Holds appear as `held_reason` in the per-window span/stdout, activity end
   record and end-journal row. `release_held` is preserved. Standalone release
   keeps its existing refusal exit 2 and adds the same reason field for
   `no_air_receipt` and `second_copy_not_confirmed`. No new exit code is added.
