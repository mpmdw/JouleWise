## What changed

### RL-113: the option (c) gate reports first-program-only keys

`scripts/independent_recompute_b6.py` `recompute_block`, lines 1322-1338, after `compare(projected, expected)`:

- `checks["first_program_only"]` (restricted, in `block.option_c`): the sorted list of `{class, session, key}`
  for `table_rows(primary)` minus `table_rows(expected)`. Names only, no values. The class is the one
  `compare()` would use (`run_phase_energy` for run rows, else `quantity_class`). Sorted by
  `(class, session, key)`.
- The public comparator (`block.option_c.comparator.classes`) gains `first_program_only`, a count per class,
  beside `compared`, `passed`, `failed` and `unmatched`.
- These keys do not enter `compared` and do not change `pass`. `compare()` is unchanged. The projection is
  unchanged. A second-side-only key is still projected as `None`, compared and failed.

### RL-114: a GAMMA session with an undefined NEG-8 screen

`joulewise/b6_analysis_check.py` `check_block`, GAMMA branch, lines 78-127:

- When `s.neg8["verdict"] == "undefined"`, no engine inputs are built and `engine.family` is not called for
  that session. So no `contrast/*` key enters the second side's table. No `neg8/*` key enters it either; the
  existing drift guard at line 69 already skipped those.
- In place of the comparison, one `engine_screen_undefined` check per contrast in `r["contrasts"]` (lines
  79-86). It passes only when the first program's `outcome` is `not_resolvable` or `not_estimable`, its
  `D_j` is `None`, and its `decision_interval_j` is `[None, None]`. Otherwise the gate fails with
  `engine_screen_undefined:<cid>`.
- The pairing checks (lines 117-127) still run for that session. The defined-screen path is the old code,
  re-indented under `else:` (`git diff -w` shows only the added lines). The twin is unchanged.

### RL-115: external input pins, with `--inputs`

`scripts/independent_recompute_b6.py` `main`, lines 1706-1720:

- A key in `document["external"]` with no matching argument refuses `external_input_missing`. An argument
  supplied with no key refuses `external_input_unpinned` (today this is a bare `refused: KeyError`). Both
  happen inside the `--inputs` block, before the session pin loop and before any session is read. Only the
  arguments the command has are considered: `loop_attempts`, `loop_state` and `block5` for `block`;
  `loop_attempts` and `loop_state` for `single`.
- When an input is neither pinned nor supplied, the run proceeds. The restricted `inputs` record gains
  `external_supplied`: `{loop_attempts, loop_state, block5}`, three booleans that say whether each argument
  was given. In `single`, `block5` is always `false`.
- Without `--inputs`, nothing changes. The digest check is unchanged and runs after the two new refusals.

## Ambiguities resolved (narrowest reading)

1. **RL-113, public count for a class with no compared row.** The ruling asks for "a count per class, beside
   `compared`, `passed`, `failed` and `unmatched`". Every existing class record gets `first_program_only`
   (0 when there are none). A class that has only first-program keys (for example `contrast_word`,
   `reported` and `floor`, which the second side never holds) gets a new record with
   `compared/passed/failed/unmatched` at 0 and its count, and **no `pass` field**, because `compare()` never
   judged it. The comparator's top-level `pass` is computed inside `compare()` and is untouched. Nothing on
   the R12 line iterates `option_c.comparator.classes`. The alternative was a sibling map beside `classes`.
2. **RL-113, scope of the set difference.** Taken literally: `table_rows(primary)` minus
   `table_rows(expected)`, run-energy rows and block rows included.
3. **RL-114, which contrasts get a guard.** One per key of the first program's `r["contrasts"]` for that
   session. These are the same cell ids the twin path iterates through `r["_selections"]`.
4. **RL-114, the guard's shape.** A single counted `check` per contrast, comparing a boolean to `True`, so
   the family count equals the number of contrasts and the failure reads `engine_screen_undefined:<cid>`.
   The guard reads the fields with `.get`, so a missing field fails the guard instead of raising.
5. **RL-115, "for the arguments the command has".** In `single`, an `external.block5` key is ignored,
   because `single` has no `--block5` and never reads one. An `external` key outside the three names is
   ignored. A document with no `external` object counts as empty: a supplied argument then refuses
   `external_input_unpinned`, where today it would raise a bare `KeyError`.
6. **RL-115, order.** `external_input_missing` is checked before `external_input_unpinned`, and both come
   before the digest check.
7. **RL-115, test placement.** There is no recompute-level wrong-digest test in
   `tests/test_b6_r12_session_fixture.py`. The nearest is the verifier's
   `test_changed_program_loop_pin_refuses_before_shape_tests` (line 1130). The new class sits directly after
   it, at line 1152.
8. **RL-114, the R3 labels: not on this branch.** The three label strings live in `scripts/b6_r3_table.py`
   (`LABEL_CONTRAST`, `LABEL_GATE`, `LABEL_GATE_WORD`, lines 58-65 on
   `origin/analysis/2026-11-12-b6-r3-table` @ `45fc7f9df`). That file is not on the R12 line, and the ruling
   assigns "three label strings and the regenerated table for PR #748" to the R3 table seat. Nothing was
   changed there.

## Open questions and findings for the lead

- **Existing defect, outside these rulings (not fixed).** In a `block` run, a drift-screen reference or
  corpus member that is excluded but still has a usable bundle fails the option (c) gate:
  - `Session.reference` calls `member(..., compared=True)` before it checks exclusion, so the run enters
    `compared_run_ids`.
  - `check_block` (line 54) then computes that run's energies.
  - The first program's `compared_runs` lists only `survivor_ids | corpus_ids`, so the projection gives
    `None`, and the gate fails with `run_phase_energy` failures and `option_c_disagrees`, a stop flag.

  Reproduced on the base (`04eacce2a`): one start reference excluded with `member.status_not_succeeded` in
  a 3-session synthetic block gave 3 failed `run_phase_energy` rows, one excluded run times three phases.
  The RL-114 fixture avoids this by removing the runs instead of excluding them. This is a real-data path
  (any member-level exclusion code on a screen run) and needs a ruling.
- **For the R3 table seat.** The new guard is written so that `b6_r3_table.read_check` (AST walk) does not
  pick it up: the check's actual is a local boolean, and the fields are read with `.get`. So the generator's
  `outcome` rule (`set(fams) == {"engine_refusal", "engine_word"}`) is not tripped, and the generator's
  labels stay as they are until the seat edits the three constants. The `CHK:` line numbers for
  `check_block` shift because of the re-indent, so the table needs regenerating after this lands.
- RL-113 term 5 (the paragraph in the S-14 pin request) and term 7 (the post-run label check on
  `first_program_only`) are the lead's, not code.
