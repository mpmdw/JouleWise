## Portable record workflow

This is a new custody artifact format, not a conversion of existing production
records. The lead must run it at the MBP's authorized finalization boundary,
after successful harvest and before transfer. The records branch is the trust
anchor: a producer string does not authenticate a physical machine. No online
push/freshness check occurs; the caller must provide a genuinely synchronized
remote-tracking records ref and preserve the MBP-authored manifest.

The dedicated export must contain all source bytes, including the pack and any
pack config files under the exported measurement root. Original absolute
locators remain inert text. Example layout (no operator-written targets needed):

```json
{
  "session": "session",
  "measurement_root": "measurement",
  "registration_dir": "measurement/configs/campaigns/align_v4/registration",
  "runs_root": "runs",
  "custody_root": "custody",
  "plan": "plan.json",
  "pack_root": "pack"
}
```

On the MBP, use `--finalize layout.json --inputs EXPORT --output
REPOSITORY/RECORD_DIR/finalize.json`. Add `finalize_manifest` (that
repository-relative path) and `records_ref` (for example
`refs/remotes/origin/records/WINDOW`) to the layout, then run `--repository
REPOSITORY --describe layout.json --inputs EXPORT --output
REPOSITORY/RECORD_DIR/descriptor.json`. Commit both small JSON artifacts
together and push through the lead's normal authorized record procedure. Neither
command commits or pushes automatically. Descriptors without finalize bindings
are inspection inventories and cannot replay as a gate.

On the laptop, with the synchronized records ref already available:

```sh
python3.13 -B scripts/align_v4_record_desk.py \
  --repository REPOSITORY --commit FULL_RECORD_COMMIT \
  --record RECORD_DIR/descriptor.json --inputs EXPORTED_COPY \
  --output NEW_REPORT --workers 2 --profile NEW_PROFILE.json \
  --gate-evidence NEW_GATE_ARTIFACT.json
```

Profile/evidence parent directories must already exist; all outputs stay outside
the immutable export. A passing replay can emit the artifact for
`checks.full_desk_gate.artifact` in the next-arm packet. Put `status: pass` and
an explanatory `basis` alongside it. Copy the two report files and keep their
hashes; if relocating them, update the artifact paths. The arm needs those
small reports and the record Git objects/ref, not the large export. The
validator checks the hashes on the MBP too. A failed/incomplete replay emits no
gate artifact. Existing self-written v1 descriptors must be replaced at the
proper source-finalization boundary; they are not grandfathered into passes.

Landing this code is a code/config change and requires a full desk pass before
