# Independent recompute: parallel member loading

Date: 2026-11-06

## Scope and safety

This change used only `tests.independent_recompute.support.full_pack`, which creates
temporary synthetic archives. No experiment, custody, or restricted path was read.

## Implementation

`scripts/independent_recompute_b5.py` now accepts `--workers N` (`N >= 1`). Before
reduction, it makes a stable, sorted job list of roster and negative-eight corpus
members. A `ProcessPoolExecutor` parses and computes those independent members.
The parent consumes `executor.map` in input order, reattaches each member to its
window reader, and merges file accounting and flags in the same stable order. The
single-worker route executes the identical jobs without starting a child process.
Final flags retain the existing explicit sort before JSON serialization.

XML plist frames now use an Expat event parser which retains only `elapsed_ns`,
`timestamp`, and the CPU/GPU/ANE power values. Other keys and subtrees are not
materialized. Binary plists retain the `plistlib` compatibility fallback. All
placement, validation, rail summation, and label-sanity arithmetic after extraction
is unchanged.

## Determinism proof

`tests/independent_recompute/test_parallel.py` builds one synthetic ALPHA fixture,
runs the actual CLI in fresh subprocesses with worker counts 1, 3, and 10, and
compares the three output files as bytes. The focused command passed:

```text
$ python3 -m unittest tests.independent_recompute.test_parallel
.
----------------------------------------------------------------------
Ran 1 test in 3.009s

OK
```

The pre-existing archive suite also passed (14 tests in 31.067 s), exercising the
selective XML extraction through the broader recomputation behavior.

## Profile

The profile was run on this checkout with Python's `timeit`, using one 16-frame
member generated by `full_pack`; 1,000 complete parses were timed. The old
`plistlib.loads` loop took **2.162921303 s**, while `_plist_measurement` took
**0.678996151 s**: **3.19x faster** for the isolated per-member plist parse.

For context, three whole synthetic ALPHA runs (`full_pack(..., n=10)`, 107
members with deliberately tiny 16-frame plists) produced these best-of-three wall
times: workers=1 **2.083 s**, workers=3 **2.156 s**, workers=10 **2.334 s**.
This tiny fixture is dominated by process startup and the serial reducer, so it is
not evidence of an end-to-end speedup. The measured improvement is specifically
the requested per-member plist parse; the process pool is intended for real,
larger member streams. No real experiment data was used to make a performance
claim.
