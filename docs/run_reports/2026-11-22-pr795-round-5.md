## N2: the frozen admission-closure suite, through the fixed layout

The lead's decision: the suite stays the acceptance. Only its driver and invocation shim change, so that it calls the
executor through the fixed layout the audit-2 ruling requires, and every case's data and expected decision stays
byte-identical.

**What changed.** Only the suite's two driver definitions, `actor` and `Arena`.

- **The layout.** `Arena` writes each case's custody at the copy's registered root (`<root>/<span id>`), and the roster
  and verdicts at their fixed names (`<root>/lm-interim-01/`). It runs `stage1` committed and with no option. The
  manifest, roster and custody are found at their registered places, and public records come from origin/main after a
  fetch.
- **Before each invocation,** `Arena` clears stage 1's two fixed outputs (`stage1.json`, `level_r.json`). It then does
  the lead's pin fill for the custody as it then is:
  - the manifest's one pin list is made from the rostered spans' bytes;
  - a RUN_STATE Check item names each span's offload manifest in full hex;
  - the LOOKS row names the manifest's new sha256;
  - all three are committed and published to the copy's origin, as one commit on the registration commit.

  Each case is therefore its own committed look. No earlier case's pin list stays in the ledger history the executor
  reads: `_ledger_history_rows` shows LOOKS.json at every commit of that history.

  Under RL-194 a case's custody reaches the grammar validator only if it is pinned. Each case changes custody bytes, so
  each case needs its own committed pin list.
- **No memo of committed checks.** `actor` no longer memoizes `verify_pins`, `require_inputs_committed` or
  `ledger_gate` in the large matrix. Each case commits its own pin list, so a memo keyed by arguments would return
  another case's result. Only the immutable code inventory stays memoized.
- **Stream opens.** `actor` attributes a pinned stream that the pin guard (`custody_pins.py`) opens to the reader that
  asked for it. That reader is still `time_fields.py`, as RL-173 E.1 requires.
- **Opens the guard answers.** `actor` observes each open that the pin guard answers itself, as the `open` audit event
  observed every attempt before the guard existed. The guard refuses an absent roster file before any open happens,
  so the stage's attempt to read a missing receipt raised no event. The CI run on `d2aa20bc4` found this: the case
  that deletes the receipt was refused correctly ("runner_receipt.json: absent") but judged "fixture never reached".
