## Implementation

`scripts/align_v4_session.py` contains both changes; `powermode.py` is unchanged.
W-1 reads an injectable installed magistrate plist with `plistlib`, preserves its
interpreter/script, working directory and environment, and constructs exactly
one watchdog command form: the installed program plus `--dry-run --custody-root`.
It has a 30-second subprocess timeout. Missing/unreadable/malformed configuration,
bad output, duplicate decision lines, failed execution and unknown state words
refuse. No checkout watchdog is substituted.

The pre-install call is in `arm_checks`, before the meter probe, `pre_dwell` and
the stamp. Its argv, state, reason and elapsed seconds live under the sole new
arm-record key `watchdog_acceptance`. Refusal:
`watchdog_acceptance: pre_install: <state>: <reason>`.

The single `_watchdog_post_install` call is immediately after a successful shared
installer return, in the same try. The existing installer endpoint retains its
meaning (installer return, excluding the new probe). The added endpoint and
result are `quiet_dwell.watchdog_post_install_end_ns` and
`quiet_dwell.watchdog_post_install`, beside `installer_end_ns` in the existing
`.dwell.json`. A refusal invokes `install_night_agent.sh --plan <this plan>
--uninstall`, then independently authenticates absence of both canonical night
labels using the existing launchctl-print grammar. The existing enclosing
termination-shielded Automatic restore handles any High Power this arm entered.
Post-probe signals also enter the uninstall path. Refusals:

- `watchdog_acceptance: post_install: <state>: <reason>; install undone`
- `watchdog_acceptance: post_install: <state>: <reason>; install_undo_failed: ...`
  names failed/unresolved jobs or the host restore. Uninstall evidence remains
  nested in the post-install result; restore evidence uses the existing path.

W-2 imports owning constants for OFF (driver and receipt implementations,
deduplicated), ON, the privileged network-time query, AC Automatic/High Power,
and the installed frequency helper. Each rule is checked only using
`/usr/bin/sudo -n -l <command> <args...>`. The query is performed only if its
listing admits, through `run_night._leave_network_time`; ON and OFF both admit.
The new prepare-state key `host_privilege_preflight`, beside
`host_state_preflight`, retains listings, the read result and refusal reasons.
The existing host-state test override explicitly skips this production probe.
Refusals are `host_privilege_preflight: sudo_rule_missing: <which>` and
`host_privilege_preflight: network_time_unreadable`. Existing host-lock, kit,
series and frequency refusals are retained. No setter is executed by W-2;
`-setusingnetworktime` necessarily appears as the command being *listed* by sudo.

Existing arm fixtures inject a synthetic watchdog acceptance instead of reading
the account's LaunchAgents. The new module covers the real plist/parser/runner
path and orchestration with fake commands. `scripts/test_timings.json` gains
exactly one scheduling-weight line for that new module.
