## Answers to the brief

- **Restores what it should:** yes for every catchable disposition and the blocked mask. No for interval timers and alarms (M3) and for import-time changes (M2).
- **Only between modules:** yes. Snapshot and restore bracket one `TextTestRunner.run(suite)`; nothing is touched between test methods or classes, and `setUpModule`/`tearDownModule` are inside the bracket.
- **Can it make a test pass that should fail:** I found no way. A test asserting a disposition inside its own module sees the unrestored state. The only tests that flip to green are victims of another module's leak, which is the intent.
- **Changes what CI reports:** MODULE and SHARD SUMMARY lines, counts and exit codes are identical apart from the victims. One new line, `SIGNAL RESTORE …`, which no parser reads (`SHARD_SUMMARY_RE` is the only regex consumer; `ci.yml` uses exit codes). The exception is M1.
- **Host side effects:** none. The new code calls only `signal.getsignal`, `signal.signal` and `signal.pthread_sigmask` on the runner process. It never calls `kill`, `killpg` or `raise_signal`. Unblocking can deliver an already-pending signal to the runner itself (M1).

## Findings

### MEDIUM

**M1. Restoring the mask can kill the shard with no attribution.** `scripts/shard_tests.py:621-626`
- Scenario: a module leaves a signal blocked with one pending (I used SIGUSR1). The guard unblocks it at line 623 before printing at 626. The signal is delivered at its default action and the runner dies.
- Observed: exit 158, last line `MODULE START …leaker`, no `SIGNAL RESTORE`, no MODULE line, no SHARD SUMMARY. Without the guard the same pair passes.
- No module in the tree leaves a mask today (`tests/test_night_agent_install.py:1594-1612` restores its own).
- Fix: build and print the report line before the `SIG_SETMASK`. Better, compute `signal.sigpending() & (current_mask - mask)`, consume each with `signal.sigwait`, and name them in the line (`pending-discarded=SIGUSR1`). `sigtimedwait` does not exist on macOS, so use `sigpending` plus `sigwait`.

**M2. Import-time leaks are not covered, so "closes the class" overstates it.** `scripts/shard_tests.py:687` and `:836` (snapshot), `:671-686` and `:800-835` (import and load-error path)
- The snapshot is taken after `importlib.import_module`. A module-level `signal.signal(...)` becomes the baseline, is never reported, and reaches every later module. The `MODULE LOAD ERROR` path also `continue`s with no restore.
- Observed: a module with `signal.signal(SIGTERM, SIG_IGN)` at import, then a victim asserting SIG_DFL. Victim FAIL, no `SIGNAL RESTORE` line.
- No test module does this today (AST check of the five grep hits: all are inside embedded child scripts).
- Fix: take the snapshot before the `try:` that imports, and call `_restore_signals` on the load-error path too.

### LOW

**L1. Interval timers and alarms are not restored.** `scripts/shard_tests.py:572-590`
- A leaked `setitimer(ITIMER_REAL, 1.0)` kills the shard with SIGALRM in the next module (exit 142), with and without the guard, so this is no regression. A leaked `alarm(100)` was still armed in the next module.
- Production code arms ITIMER_REAL (`joulewise/b5/chain.py:685`, `scripts/offload_window.py:354`, `joulewise/align/r0_runner.py:92`), so a test that escapes one mid-flight is plausible.
- Fix: snapshot `signal.getitimer` for ITIMER_REAL, ITIMER_VIRTUAL and ITIMER_PROF; after the module, disarm any that are newly armed and add `itimer-real` etc. to the line.

**L2. The report is a line nobody is asked to read.** `scripts/shard_tests.py:625-626`
- A leak is now permanently green. The production cause of #741 is still there: `scripts/align_r1_rehearsal.py:1979-1984` skips both `host_lock.release()` and the handler restore when `_write_result` raises, and #743 is test-only. That is outside this PR, but the guard removes the only pressure to fix it.
- Fix: also emit `::warning::` on GitHub Actions, or repeat the leakers in one recap line before SHARD SUMMARY. Consider an opt-in strict mode that fails the leaking module once #743 is in.

**L3. `run_shard`'s guard lines are untested.** `scripts/shard_tests.py:687,691`; `tests/test_shard_split.py:584-618`
- `SignalIsolationTests` drives only `run_units` (the path `ci.yml:253` uses). Deleting the two lines in `run_shard` survives the suite.
- Fix: parametrise the test over both entry points.

**L4. Silent skips.** `scripts/shard_tests.py:588`, `:618-619`
- A failed `signal.signal` restore is swallowed with `continue`, and signals whose handler was `None` at snapshot are neither restored nor reported if a module changes them.
- Fix: append `SIGX=restore-failed` or `SIGX=changed-unrestorable` to the line.
