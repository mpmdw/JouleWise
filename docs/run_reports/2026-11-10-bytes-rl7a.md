## What the commitment check reads

The complete specification and future operator sequence are in
[`docs/design/bytes_commitment.md`](../design/bytes_commitment.md).
The selected analysis checkout defaults to the script checkout; an explicit
`--commitment-repo` must select the analysis checkout whose HEAD is asserted.
The gate reads its Git objects/HEAD/local `refs/remotes/origin/*`, the named push
receipt, local and committed prediction JSON/SHA sidecar, and the committed
registered estimator blob. It reads current canonical
`docs/bytes/stage1/unblinding.jsonl` (required), current
`docs/bytes/stage1/heldout-release.json` if present, **all retained revisions of
those two metadata paths across all Git refs**, and an explicitly supplied
released-key directory's `release.json` if present. It never searches exports or
custody to discover records. Earlier off-path records must be reconciled by the
lead into that inventory before study use.

The commitment must itself be a commit reachable from the recorded local origin
ref and an ancestor of the analysis HEAD. The receipt's origin tip must contain
it and remain on the current origin lineage. Prediction bytes must equal the
committed regular blobs and both SHA sidecars. The committed estimator and the
prediction JSON's estimator identity must match the registered pin. Commit/push
UTC chronology must strictly precede every heldout event/release; nonempty
historical unblinding revisions must additionally descend strictly from the
commitment, so deletion or backdating cannot silently repair recorded history.
Fit-only releases are not heldout unblinding.

**Evidence limit:** no-network verification establishes reachability in the
local origin snapshot, not freshness of the live server. Git has no authenticated
push time: `pushed_utc` is labelled as an operator attestation throughout, checked
for chronology and recorded in output receipts. The lead must verify actual
push time and snapshot freshness outside this seat. This code does not prove the
absence of off-journal events or history removed from all refs. No real
commitment or real unblinding record was checked here.

The guard concerns the original registered commitment. The existing changed
**evaluating** estimator path still evaluates the original lines and prints its
provenance flags. A new commitment with an unregistered estimator is refused.
The registration's separately labelled post-agreement second commitment remains
a distinct lead-owned workflow, not permission to replace the blind original.
