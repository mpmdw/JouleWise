## For the research lead

**The idle baseline's mean power reaches the public stage-1 file as a digest.** No pre-reservation reader now
makes a number of `power_w_mean`. But stage 1's roster records each span's operational files by sha256
(`custody.files_sha256`), and `events.jsonl` is one of them, so a different mean gives a different digest in the
public stage-1 file. The reviewed twin child compares exactly that map with its own digests, so the map cannot
drop the journal without changing the child. Whether a digest of a file that holds one measured mean is within
RL-179 register row 26 is the research lead's question.

**The Check binding reads the wording of the items.** A Check's digests for a span are those labelled `manifest`
(or `manifest_sha256`, or the `SHA256SUMS` file's name) after the item names the span and before it names another
roster span. On `origin/main` today seven of the eleven roster spans have such a digest in some item (319, 334,
350/353, 362, 436, 437, 444). None of those items is the Check item the pin table names for that span, so as the
table stands every span would be held. The lead fills `check_item` from the item that prints the span's manifest,
or the Check items print it from now on (RL-194a §2: the lead's process change). I compared no digest: the real
offload manifests were not opened.

A digest of another directory that an item names after a roster span (an `hp-01` or `f2-stab` offload, say) is
read as that span's. It cannot match the span's offload manifest, so it holds the span and never binds it.
