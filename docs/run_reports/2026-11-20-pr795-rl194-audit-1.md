## RL-195: the journal's digest, the HELD state and the correction rule

Nothing about the digest changed: no masking, and the reviewed twin and its digest map are as they were. The
look's blind statement (`custody.disclosure`) gains RL-195's sentence: "The public file carries the sha256 of
each span's operational journal, which contains one measured idle-power mean; no value from it was read before

| 1.1 Before the reservation no process converts, prints or copies the mean | Every pre-reservation reader of operational JSON uses `custody_pins.operational_json`, which never converts a number under an energy-named member. The verifier and the staging process decode nothing | The `sys.setprofile` probes: `test_interim_admission.RealControllerRows.test_the_idle_baseline_s_mean_power_is_never_made_a_number`, `test_input_review...test_the_review_makes_no_number_of_the_idle_baseline_s_mean_power` (the review record also holds no float), `test_content_admission...test_no_reader_before_the_reservation_makes_a_number...` |
| 1.2 Each journal has unpublished sub-second stamps apart from the mean | The pinned controller's source (byte-identical at `b4b6aeb19`, `2d347f721` and `6e9d42f1d`), below | `RealControllerRows.test_every_controller_journal_opens_and_closes_with_its_own_clock_rows`; the stamps are absent from stage 1's output in the 1.3 test |
| 1.3 Changing only the mean moves only that journal's sha256 | Stage 1 reads only token and gate rows from `events.jsonl` (`token_stamps`, `inclusion_34._scan_events`) | `test_content_admission.Stage1.test_only_the_journal_s_digest_moves_with_the_idle_mean` |

**The citation for 1.2.** Read from the pinned source, never from a journal:

- `joulewise/controller.py:3839-3854`: `_buffer_event` stamps every row it writes with `timestamp_s=self._clock.now()`.
- `joulewise/controller.py:1662-1667`: `_run_lifecycle` writes `run_started` before anything else. Then
  `joulewise/controller.py:1742-1751`: `_stage_validate` opens the first stage (`stage_started validate`).
- `joulewise/bundle.py:1193-1205`: `finalize` appends `run_finalized`, stamped `self._clock.now()`. `_finish`
  (`controller.py:3962-3971`) calls it on the completed and the failed path alike.
- `joulewise/align/apple/r1_runtime.py:1458-1464` and `1537-1546`: the leg runtime builds a `SystemClock` and
  passes it to `run_benchmark`. `joulewise/clock.py:55-56`: `SystemClock.now()` returns `time.time()`, a wall-clock
  epoch float with sub-second digits.

So every journal of a leg holds at least the `run_started`, `stage_started validate` and `run_finalized` stamps,
none of which stage 1 reads or publishes. The baseline row's own `timestamp_s` and its `duration_s` are two
more. The rows in tests come from the pinned controller run with its mock backends, whose clock is a fake one,
so sub-second digits there are set by the test. The source is the evidence for real journals.

**A reading to confirm.** RL-195's test for 1.1 says that stage 1's public file holds no float. Stage 1's file
does hold floats: times, temperatures, fan speeds and token rates, none from energy. Stage 1 is not a process that
has opened energy, so row 26 does not bar them. I read the condition as "no float from the mean". The 1.3 test proves
that reading: with only the mean changed, the output is byte-equal once the sha256 fields are masked, and no
number in it equals the mean or a journal stamp.

### Section 2: the HELD state and the correction

- **HELD.** A span whose Check item does not print its offload manifest's digest as the span's, with every printed
  character matching, is HELD (`custody_pins.check_states`, `held_spans`). It stays in the pins and on the roster.
  Every committed stage refuses while any span is held. `check-inputs` exits 1 and names each held span with
  the item numbers and labels under which a digest is printed after the span is named, never the digest: the
  list RL-195 §2.4 asks for. `validate --final --repo` and `row --roster` refuse, and they also refuse pinned
  spans that are not exactly the roster's.
- **Correction.** `cadence_look_manifest.py correct-check --span SID --item N` (draft only) moves `check_item` to
  item N only if N names the span's offload manifest under a manifest label and every printed hex character
  matches. `check_corrected_from` keeps the item the pin table cited. Anything else refuses and the span stays
  HELD. The digest comparison happens when the lead runs it; no real digest was compared here.
- **`outer.sha256` never binds.** A digest with `outer` just before it is never read as the manifest's. It may be
  cited as the review record's `second_record`.

The same reading covers any operational file with an energy-class member in `lm-inst-01`, `lm-stab-01` and
`lm-stab-02`. Those looks are not in this PR.

## The two questions this round raised (answered by RL-195)

**The idle baseline's mean power reaches the public stage-1 file as a digest.** Stage 1's roster records each
span's operational files by sha256 (`custody.files_sha256`), `events.jsonl` among them, and the reviewed twin
compares that map. RL-195 §1 permits the plain digest on the three conditions above.

**The Check binding reads the wording of the items.** A Check's digests for a span are those labelled `manifest`
(or `manifest_sha256`, or the `SHA256SUMS` file's name) after the item names the span and before it names another
roster span. On `origin/main` today seven of the eleven roster spans have such a digest in some item (319, 334,
350/353, 362, 436, 437, 444). None of those items is the Check item the pin table names for that span, so as the
table stands every span would be held. RL-195 §2 confirms the lead's rule: `check_item` is corrected (with
`correct-check`) only to an item that prints the span's manifest with every character matching, and every other
span is HELD. I compared no digest: the real offload manifests were not opened.

A digest of another directory that an item names after a roster span (an `hp-01` or `f2-stab` offload, say) is
read as that span's. It cannot match the span's offload manifest, so it holds the span and never binds it.
