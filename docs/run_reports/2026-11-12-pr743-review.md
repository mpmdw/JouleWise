### Findings

1. **LOW. The witness checks SIGTERM only.**
   `tests/align/test_r1_round6_power.py:372-380`.
   SIGINT and SIGHUP are restored by the same loop but not asserted.
   Fix: loop the pin and the final assertion over all three signals.

2. **LOW. The same test leaves the host night lock unreleased.**
   `scripts/align_r1_rehearsal.py:1982` is skipped on the same path, so the `flock` file descriptor stays open in the test process until collection. The lock file is in the test's temporary host-state directory, so no later module is affected. No change needed in this PR.

3. **LOW. No runner-level guard (the PR body names this as a follow-up).**
   `scripts/shard_tests.py` `run_units`.
   Fix in a follow-up: snapshot the dispositions of SIGINT, SIGTERM and SIGHUP before each module, and after it restore them and mark the module failed if they changed. That catches the next leak from any module, at the module that causes it.

### Opinion: does the driver-side path need a code fix?

Not for tonight, and not for the science. It is worth a small fix at the next planned rebind of the file.

- In production, an `OSError` from the terminal-record write (for example a full disk) leaves `run()` through the `finally` as an exception. `main()` does not catch it, so the process exits with a traceback straight away. The ignored handlers and the held `flock` die with the process. The powermode restore has already run by then (`:1947-1967`), and the registration is correctly not committed.
- The only in-process caller outside tests is the PREQUAL chain check (`joulewise/align/w1_prequal.py:1447`), and each PREQUAL check runs in its own spawned probe, so a leak there is confined too.
- The defect is real as a matter of hygiene: `run()` is a function that can return to a caller with three signals ignored and the host night lock held. The fix is about five lines: put `_write_result` and `_commit_registration` in an inner `try` whose `finally` releases the lock and restores the handlers.
- Cost: `scripts/align_r1_rehearsal.py` is in `R1_EXECUTED_SOURCES` and the registration artifacts (`v4_registration.py:282`, `:362`, `:485`). Changing its bytes after an R1 night ran makes condition 13 refuse until a cited rebind. So do it with the next change that already rebinds that file, not as a stand-alone edit, and keep this PR test-only.
