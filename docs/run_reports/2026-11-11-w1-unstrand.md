## Evidence and API choices

- The pre-chain branch requires both chain markers absent, matching nonempty
  plan identity, verdict exactly REFUSED and null/absent `chain_exit_code`.
  Only those three result fields are accessed. Result bytes are hashed for the
  transport receipt, never printed. The existing process table and installed-job
  identity checks still govern both branches.
- `scripts/run_night.py:1701-1707` writes the git delivery receipt after the push;
  `:1723-1743` validates transport, plan, ref, result digest and commit before
  touching `courier.sent`. The transport part of the release check is
  `scripts/align_v4_next_arm_packet.py:171-180`: require `courier.sent` and either
  `courier.json.sent is True` or the validated delivery receipt. This helper uses
  the same alternatives. A lone sent marker is insufficient. It does not invoke
  any publisher or courier. Receipt/hash fields and the legacy `sent` boolean
  are structural; no courier payload is printed.
- `scripts/magistrate_watchdog.py:897-918` also requires a delivered REFUSED result
  for the plan and no started marker. Its further terminal/zero-capture readers
  are deliberately not called: they inspect fields beyond this brief's allowed
  three result fields. This helper is recovery, not a next-arm release decision.
- `powermode.restore_owed` (`joulewise/align/apple/powermode.py:291` onward) receives
  the existing runner, a held `HostLock`, a distinct `post_window_unstrand`
  reason, and W1 ownership when applicable. This follows the signature and owner
  pattern in `scripts/run_night.py:4422-4451`. A foreign W1 marker prevents any
  host command; R1-only debt is restored with the API's unrestricted-owner form
  after proving process absence and taking the lock.
- `scripts/run_night.py:4373-4378` supplies both marker paths. The dead-man routes
  through `_close_ac_powermode` (`:5450-5495`), which holds the lock across power
  and network restoration (`:4543-4605`). This helper likewise holds the lock
  across every host command, including when no power marker exists.
- Network debt is determined by the existing
  `_night_turned_network_time_off` (`:4525-4540`), accepting its authenticated action
  or plan-bound OFF receipt. `_restore_network_time` (`:4501-4522`) performs the
  setter and authenticated read-back. `_leave_network_time` supplies the initial
  observation. No host argv is reimplemented in shell.
- `night/unstrand.restore.json`, schema `joulewise.unstrand_restore.v1`, is opened
  exclusively before host probes/mutations. It records plan, epoch time,
  `completed|pre_chain_refusal`, found markers/mode/network state, API actions
  with return codes, success, and a boolean measuring-night deferral. It is
  flushed/fsynced and never overwritten. A deferred/failed attempt also consumes
  this write-once record; subsequent recovery needs a lead decision, not an
  automatic overwrite.
- There is no new production environment switch or argument. Tests replace the
  existing `python3` executable seam with a temporary interpreter wrapper that
  patches `make_probes().run` and the fixed host-state default. The production
  heredoc always calls `mark_production_entry("post_window_unstrand")`; a dedicated
  test proves an override is refused. Even that test patches the fixed default
  to a synthetic path, so it never probes `/Users/Shared/JouleWise`.

## New refusal messages and recording

These are textual refusal identifiers, not changes to registered cause codes.
All print to stderr. Pre-chain failures exit 1 before uninstall and write no
custody record.

| New refusal | Recording |
|---|---|
| `pre-chain result is unreadable or invalid JSON` | stderr only |
| `pre-chain result is not a JSON object` | stderr only |
| `pre-chain result belongs to a different plan` | stderr only |
| `pre-chain result verdict is GO, not REFUSED` | stderr only |
| `pre-chain result verdict is ABORTED, not REFUSED` | stderr only |
| `pre-chain result verdict is not REFUSED` (other values) | stderr only |
| `pre-chain result has a chain exit code` | stderr only |
| `pre-chain courier.sent is missing` | stderr only |
| `pre-chain result delivery is unproven` | stderr only |
| `--restore-host requires --go` | stderr, exit 2, no uninstall or restore |
| `host restore setup failed (TYPE)` | stderr, exit 1, no host actions |
| `host restore record already exists` | stderr, exit 1, existing record preserved |
| `host restore deferred to a measuring night` | stderr and record's deferral flag/actions, exit 1 |
| `host restore failed (TYPE/see restore record)` | stderr and record's error/API actions, exit 1 |

Started-without-exit, live-process, process-table-failure, other-plan-job and
