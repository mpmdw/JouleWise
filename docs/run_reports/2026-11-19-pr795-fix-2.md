## The red test

`test_writer_shapes_refuse_both_stages_before_response_reads` failed 16
subtests on hosted CI. Stage 1 did refuse each mutated input, with status 2
and no response read. It refused for another reason: the fixture rewound
`HEAD` to the inputs commit while `origin/main` already carried the stage-1
commitment, and stage 1 never runs again against a ledger that commits one
(RL-166 Q8). That gate precedes custody on purpose, so the product order is
right and the fixture was wrong. The kept change runs every stage-1 case
before the stage-1 row is registered, then every stage-2 case after it.

## Not in this round

Stage 1 reads no energy value, so a malformed value inside a trace or a
telemetry row is outside its reach by design. The reviewed child raises on
those under the reservation.

An unknown extra member of a receipt, a step or an event row is still
admitted. The generated fixtures carry one themselves (`synthetic`), as do
the reviewed child's and the audit's controls, so a closed key set would
need a ruling on synthetic receipts first. Every member the reader takes a
value from is constrained as above.

The draft PR body records exact-head hosted verification.
