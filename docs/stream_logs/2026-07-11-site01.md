# SITE-01 Decision Ledger — 2026-07-11

### SITE01-1 [packing] Bounded shards replace duplicated per-page payloads

Decision: keep every current page and its static body in the capsule, but
encode pages into bounded gzip+Base64 shards plus one shared stylesheet /
freshness archive. The server decodes and caches only the requested page shard
and the small shared archive, then reinserts the freshness fragment before the
page's closing body tag. A page shard is capped at 30,000 encoded bytes and the
first request at 32,000 decoded-byte loop iterations.

Alternatives: pagination alone (rejected because all bytes remain baked and
page shells repeat); more log trimming or GitHub-only history (rejected because
it weakens the D-051 static fallback and is unnecessary); HTML/CSS minification
(rejected as a smaller win with more semantic risk); one whole-site Base85
archive (rejected at review because its custom first-request decoder would
execute about 425,000 loop bodies against Lakebed's 50,000-instruction
allowance, even though its artifact was smaller).

Evidence: the checked-in pre-change pack was 307,507 bytes. Its 23 page
entries occupied 298,587 bytes, led by task queue 30,698, project status
27,361, council log 22,092, critique 20,762, and decision log 16,266. The
bounded-shard pack is 244,793 bytes (eight page shards; largest 29,440 bytes)
and reconstructs every packed response by reinserting the one byte-identical
freshness fragment.

### SITE01-2 [runtime shape] Routes and provenance stay synchronous

Decision: keep canonical routes, aliases, shard indexes, and the deduplicated
source/commit set outside compressed content in one `PACKED_SITE` binding. Endpoint
registration and freshness setup remain synchronous; page HTML and CSS remain
lazy. The server aliases the imported binding once to retain the documented
Lakebed bundler workaround.

Acceptance effect: every pre-change canonical path and non-reserved alias must
remain registered, source stamps must remain available to the fail-soft
freshness API, and generated server sources must contain none of the textual
validator tokens or an unbounded `for(;;)` loop.

### SITE01-3 [acceptance] Pack fails above a conservative 90%-of-cap estimate — SUPERSEDED by SITE01-4

Decision: make the default fonts-off pack fail when its estimated Lakebed
artifact exceeds 943,718 bytes, which reserves at least 10% of the 1,048,576
byte cap. Because Lakebed's inline source map embeds generated content again,
the estimate charges `content + base64(content) + 122,636` raw server bytes,
then outer Base64 and 8,192 bytes of artifact metadata. The measured fixed
base-wrapper residual is 70,355 bytes and metadata is 5,809 bytes. `--fonts`
remains explicitly for non-Lakebed hosts and does not claim this budget.

Evidence: the cached Lakebed 0.0.25 build produced a 641,540-byte raw server
bundle and an 861,197-byte stable validator artifact. That is 187,379 bytes
(17.870%) below the cap; the packer's conservative estimate for the same
244,793-byte content is 933,288 bytes. The first request decodes at most
30,054 compressed bytes in explicit byte loops before the platform's native
gzip and JSON operations.

Superseded: the estimator does not charge changes elsewhere in `server/` or
`shared/`, so it cannot establish the deploy artifact postcondition. It remains
only the explicitly labeled advisory fallback when no Lakebed executable is
available.

### SITE01-4 [acceptance] Prefer the real validator artifact; estimator fallback is advisory

Decision: when an installed or npx-cached Lakebed executable is available, the
fonts-off pack builds an anonymous artifact in an external temporary working
directory, measures the stable JSON bytes of its `artifact` member (the exact
object to which Lakebed applies the cap), and enforces the existing 943,718-byte
budget. A discovered executable that fails to build is a hard error. Only an
unavailable executable permits the SITE01-3 estimator, and that mode prints
`estimator-only advisory` rather than claiming a measured postcondition.

Alternatives: keep enlarging the estimator's fixed wrapper reserve (rejected
because arbitrary source growth outside generated content remains invisible);
measure the whole `.anonymous.json` envelope (rejected because its client
bundle wrapper is not the object Lakebed caps); invoke `npx` unconditionally
(rejected because the documented restricted-network path retries the registry
despite a usable cached executable).

Evidence: with 246,302 bytes of generated content, a validator-safe 105,000-byte
comment in a temporary `server/index.ts` left the estimator at 937,984 bytes but
Lakebed 0.0.25 built a 1,052,582-byte stable validator artifact, 4,006 bytes over
the 1,048,576-byte cap. The regression builds that temporary capsule in measured
mode and separately proves that forced estimator-only mode labels itself
advisory.
