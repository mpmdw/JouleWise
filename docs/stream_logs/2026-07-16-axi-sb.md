## AXISB-1 — Binding support semantics remain conjunctive

Decision: `supported` requires both true native B greater than one execution
and complete request-scoped observability. A Python loop over singleton calls
is classified `unsupported_for_joulewise(native_batch_execution)`. A true
batch missing any request identity, output token IDs/count, stop reason,
timestamps, or AXI-SA-compatible phase/lifecycle hooks is classified
`unsupported_for_joulewise(event_observability)`.

Why: this directly applies the binding AXI xhigh consult, D-070, and the
queue-row fences. Runtime batching and JouleWise-instrumentable batching are
not synonyms.

Evidence: `scripts/axi_sb_static_batch_spike.py:classify_observation` and
`docs/specs/axi/sb_static_batch_verdict.md` "Binding classification".

## AXISB-3 — The feasibility candidate is `BatchGenerator.next`, not the lossy convenience return

Decision: exercise the lower-level `mlx_lm.generate.BatchGenerator` response
surface. Do not classify the high-level `batch_generate` return alone as
observable enough.

Why: pinned `batch_generate` is a real batch API, but its public `BatchResponse`
contains decoded texts, aggregate stats, and optional caches only. Internally,
`BatchGenerator.next()` retains per-sequence UID, token ID, prompt progress,
and finish reason. Those are the hooks needed to construct request-indexed AXI
evidence without parsing response text.

Evidence: installed `mlx_lm/__init__.py:10`; `mlx_lm/generate.py:1237`,
`:1405`, `:1847`, `:1872`, `:1887`, `:1930`, and `:1963`, fully enumerated in
the verdict document.

## AXISB-4 — True B is observed at the model boundary

Decision: insert the complete static roster once, configure prompt and decode
capacity to B, never insert another request, and wrap the loaded model to
record every input shape. Native execution is proved only if configured and
realized B agree, at least one observed leading dimension equals requested B,
and there are B distinct runtime UIDs.

Why: an API name or B-length input list does not by itself rule out hidden
singleton iteration. The installed source calls the model with batched prompt
and decode arrays; the live shape record tests that claim at the actual model
boundary.

Evidence: installed `mlx_lm/generate.py:1160` and `:1332`; harness
`ModelCallObserver`, `insert_call_count`, `runtime_uids`, and `model_calls`
fields.

## AXISB-5 — Request events are stamped at synchronous runtime-return hooks

Decision: map each runtime UID to a predeclared `axi-sb-NNN` request ID and
take `time.perf_counter()` timestamps when `BatchGenerator.next()` returns
prompt or generation responses. Responses from one scheduler step honestly
share that return timestamp. Stop-sequence tokens are observed but marked
`committed:false`, matching pinned `batch_generate`'s exclusion of the stop
token from returned output text.

Why: the pinned response dataclasses have no native timestamp field, but the
synchronous per-UID return is the same observation seam used by the existing
single-request `stream_generate` adapter. This produces one request-scoped
event per response and retains output token IDs, ordinals, counts, hashes,
terminal reasons, and phase boundaries.

Evidence: installed `mlx_lm/generate.py:1012`, `:1237`, `:1423`, `:1430`,
`:1847`, `:1935`, and `:1945`; installed server consumption at
`mlx_lm/server.py:851`, `:858`, and `:882`.

## AXISB-6 — MLX runs only in a captured child process

Decision: keep the controller standard-library-only, remove inherited
`PYTHONPATH`, run the MLX import/load/generation worker as a child of the same
interpreter, capture both child streams, parse/forward only JSON objects, and
make `probe_outcome` the final line. Environment, Metal, model, timeout,
worker-launch, and worker-protocol failures return a structured
`runtime_unavailable` outcome with exit zero.

Why: in this sandbox the pinned MLX import itself raises
`RuntimeError: [metal::load_device] No Metal device available` and an atexit
callback writes another error to stderr. Capturing the child prevents that
runtime behavior from corrupting the JSONL evidence protocol or loading the
model after the environment gate fails.

Evidence: no-Metal smoke command using the primary pinned venv exited zero and
ended with `probe_outcome`, verdict `runtime_unavailable`, reason
`runtime_import_failed`, stage `runtime_import`. No model load or generation
was attempted.
