# Bridge Protocol v1 Implementation Ledger

Authority: `docs/contracts/bridge_protocol.md` (`bridge-protocol/v1`). This
ledger records implementation-shaping choices only; it does not restate or
amend the contract.

## BV1-1 — CLI path and invocation identity

`p[:match]` defaults to `exact`; canonical path lists are deduplicated and
sorted. `lease-acquire --invocation-id` explicitly joins the lease to the same
identifier used by `baseline` and `thread-record`; `owner_id` remains the
independent owner identity.

Evidence: `scripts/bridge`; exact/subtree conflict and invocation-attribution
checks in `tests/test_bridge.py`.

## BV1-2 — Override is an acquiring event

An allowed conflicting acquisition appends one `override` event, rather than
an `acquire` plus a second event. The override event carries the complete lease
record, the conflicting lease ids, approver, reason, and
`INDETERMINATE` policy, and is derived as active until release or abandonment.
This keeps conflict-check plus acquisition to one append inside the flock
critical section.

Evidence: `test_override_records_conflicts_and_indeterminate_policy` and
`test_overridden_snapshot_overlap_makes_scope_attribution_indeterminate`.

## BV1-3 — Snapshot pins exclude bridge-owned state

The snapshot-read pin hashes HEAD, index state, Git-visible dirty metadata, and
dirty content for task paths. `.codex-bridge/**` is excluded from that pin so
the act of recording the first lease cannot make an otherwise identical second
snapshot appear to target a different repository state. Baseline manifests
still retain the contract's raw, lossless Git outputs; a baseline invocation id
is single-use so a fresh capture cannot silently reuse its existing manifest.

Evidence: `test_snapshot_reads_overlap_only_at_same_repository_pin` and
`test_baseline_refuses_reused_invocation_id`.

## BV1-4 — Persistent-state reconstruction

Scope checking reconstructs baseline clean-file content from the captured
index object ids and reconstructs baseline dirty/untracked content from the
manifest's SHA-256 records. It compares both index and worktree state, reports
Git-visible `.codex-bridge/**` deltas as `exempt`, and checks lease intervals
that overlap the baseline-to-check window. An overridden overlap is
attribution-invalidating even when the conflicting lease is `snapshot_read`.

Evidence: the four-verdict scope tests and the bridge-internal exemption test
in `tests/test_bridge.py`.

## BV1-5 — Authorized commit ownership

For moved HEAD, the §7 cases control: unauthorized worker-owned movement is
`SCOPE_VIOLATION`; authorized movement with proven ownership is checked
normally; external, concurrent, or unexplained movement is
`ATTRIBUTION_INDETERMINATE`; and a clean final worktree never makes movement
`SCOPE_OK` by itself. For an authorized owned descendant range, the checker
walks each non-merge commit in `BASE_HEAD..HEAD` and checks the union of touched
paths, so a later revert cannot erase a violation.

Evidence: `test_unauthorized_commit_is_scope_violation_even_when_path_is_scoped`
and `test_authorized_commit_then_revert_of_out_of_scope_path_is_violation`.

## BV1-6 — Reverse-report failure boundary

The adapter strips the two validated caller header lines, prepends one
canonical header block, and injects the read-only role plus final-envelope
requirement. Successful child output is accepted only when the final two lines
form one valid, minified `bridge-report/v1` envelope with an empty `pathspec`.
Transport and envelope failures return a synthesized `FAILED` envelope.
Bounded stderr buffering is retained and used only as transport-failure detail,
not as peer advice.

Evidence: `tests/test_claude_bridge_mcp.py`.
