## A-1 [orchestrator] Codex session batching: groups 1+2 first, in one session

- **Decision:** Batch commit groups 1 (writer safety) and 2
  (finite-number invariant) into a single Codex implementation session
  producing two atomic commits; keep later groups in separate sessions.
- **Alternatives considered:** (a) one Codex session per commit group
  (7–8 sessions); (b) one session for all 7 groups.
- **Why:** Groups 1 and 2 are small, mechanically independent, and both
  sit in writer/primitive territory with crisp pins — one session
  amortizes context-loading without blurring commit atomicity. All-in-one
  risks a single reviewable unit too large to counterreview cleanly and
  one bad thread poisoning everything.
- **Confidence:** High. Would change my mind: if the combined session
  produces interleaved or non-atomic commits, later groups go strictly
  one-per-session.
- **Binds:** Later groups are sessioned by coupling, not by count;
  suite-green-after-each-commit stays the gate regardless of batching.
- **Note (post-hoc):** Superseded in part by A-6 — the sandbox cannot
  commit, so multi-group sessions force manual working-tree splitting.

### A-4 [codex session A, transcribed by orchestrator] [type: code-shape] validation.py API: predicate + parsing converter

- **Decision:** `joulewise/validation.py` exposes two primitives:
  `is_finite_number(value) -> bool` (typed-number predicate; bool is not
  numeric) and `finite_float(value, field_name) -> float` (CSV/plist/

  callers doing their own conversion.

  case (CSV/plist strings) explicit; callers wrap `ValueError` into
  their own domain errors (`BundleReadError`, `_ReduceError`,
  `SchemaError`) so no policy leaks into the dependency-free module.
- **Evidence:** Session A final message (orchestrator scratchpad
  `sessA.md`); commit `ea995e8`.
- **Confidence:** High — the diff gate confirmed no joulewise-internal
  imports and per-caller error wrapping.
- **Binds:** Groups 4 and 6 consume these primitives; no parallel
  finite-checks may be introduced.

### A-10 [design round G8, adjudicated by orchestrator] [type: code-shape] Raw-to-trace strict gate design adopted

- **Decision:** Re-derivation helper (`samples_from_raw_powermetrics`-shaped)
  lives in the powermetrics adapter module; strict orchestration stays in
  `cli.py` BEFORE the D-030 re-reduction (import-cycle note holds). Comparison
  is parsed logical row equality — exact float `==` on timestamp_s/power_w,
  exact strings on source/rail, exact row count/order — never byte-exact CSV,
  never tolerances. Anchor reconstructed as
  `plist_first_timestamp_s - metadata.device.plist_anchor_offset_s`; the
  anchor is never inferred from the artifact under test. Succeeded
  powermetrics bundles missing raw plist or a finite anchor FAIL strict;
  mock bundles skip the sub-check; failed/unsupported stay strict-skipped.
  Named `strict: raw-to-trace: ...` problem strings, D-030-style row diff.
  Old bundles with a truncated tail pass iff their CSV rows equal the
  complete-frame derivation (no diagnostic required retroactively).
- **Alternatives:** Byte-exact CSV comparison (freezes incidental
  spelling); helper in cli.py (wrong owner for timestamp/rail semantics);
  tolerance-based compare (derivation is deterministic).
- **Why:** Strict proves analytical values derive from raw evidence, not
  CSV formatting trivia; adapter owns plist semantics.
- **Evidence:** Design-round out-file (orchestrator scratchpad `desG8.md`);
  orchestrator ground-check: all 6 real bundles carry finite
  `metadata.device.plist_anchor_offset_s` + `raw/powermetrics.plist`.
- **Confidence:** High. Would change: a real bundle whose stored CSV
  legitimately differs from re-derivation for a reason the design missed
  — that becomes a blocker discussion, not a tolerance.
- **Binds:** Group 8 implementation; test pins listed in the out-file.

### A-19 [codex session G] [type: contract] Strict summary comparison handles additive nulls plus explicit summary_provenance drop

- **Decision:** `validate-bundle --strict` now compares fresh vs stored
  summaries recursively: stored keys must exactly match fresh; stored
  extras fail; fresh keys absent from stored are tolerated only when fresh
  is `null`. The one non-null exception is top-level
  `summary_provenance`: when absent from a stored legacy summary, strict
  drops the fresh provenance block per A-11.
- **Alternatives:** Keep dict equality; tolerate all fresh-missing

  generic rule apply.
- **Why:** Dict equality incorrectly fails historical bundles after
  additive optional `null` fields are introduced. A blanket additive
  tolerance would hide new non-null metric claims. `summary_provenance`
  is deliberately non-null on new summaries, so A-11's legacy drop rule
  cannot fall out of the null-only policy and needs a named exception.
- **Evidence:** `joulewise/cli.py::_strict_summary_differences`;
  `tests.test_cli_run.StrictValidateTests.test_legacy_summary_missing_additive_null_keys_passes_strict`;

### A-20 [codex session G] [type: code-shape] Workload provenance is adapter-computed and controller-carried

- **Decision:** Runtime adapters compute `RuntimeResult.workload_provenance`;
  the controller serializes it unchanged into `metadata.json`. The shared
  helper hashes canonical JSON prompt token IDs with domain
  `joulewise.prompt_token_ids.v1` and adds supplemental text SHA-256 when
  the realized prompt has text. Mock provenance uses deterministic token
  IDs and mock tokenizer identity; MLX provenance uses actual encoded
  prompt token IDs plus tokenizer/model/generator identity.
- **Alternatives:** Controller-computed provenance from config; text-only
  hash; campaign-level provenance.
- **Why:** Only the runtime adapter knows the realized generation input
  after tokenizer/generator behavior is applied. Per-bundle provenance
  preserves D-005 repetition auditability and lets campaign sameness be a
  cross-bundle hash equality check.
- **Evidence:** `joulewise/interfaces.py::RuntimeResult`;
  `joulewise/provenance.py`;

  `tests.test_mlx_runtime.MlxRuntimeTests`.
- **Confidence:** Medium-high.
  Would change: if a runtime exposes generated prompt IDs only after a
  different internal preparation path, that adapter should still compute
  the block itself and report unavailable subfields explicitly.

### A-21 [codex session H] [type: code-shape] MLX text prompts are tokenized once before generation

### A-29 [codex test-fix] [type: contract] Strict workload provenance shape is field-pinned
