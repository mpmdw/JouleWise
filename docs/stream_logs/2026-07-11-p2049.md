# Stream ledger - P2-049 analysis-manifest root resolution (2026-07-11)

Branch: `impl/p2049`. Scope: fail-closed repository-root resolution in the
analysis-manifest builder and validator, with production-shaped regression
coverage.

### P2049-1 [code-shape] Omitted repository roots use a validated lazy default

Decision: `build_slice_2m_analysis_manifest` and
`validate_analysis_manifest` use `None` as the omitted-root sentinel. When a
registry or analysis-plan path needs the default root, a private resolver
trusts the package-derived candidate only if both pinned repository markers
exist as files: `configs/analysis_registry/slice_2m_ap2.v1.json` and
`docs/contracts/analysis_plans.md`. Otherwise construction raises and
validation returns the same actionable `AnalysisManifestError` text, naming
both markers and directing the caller to pass `repository_root=Path(...)`
explicitly. An explicit root remains caller-authoritative; callers that supply
both source paths do not resolve a repository root at all.

Alternatives considered: retaining the import-time `ROOT` value as the
function default cannot distinguish an omitted root from an explicit one, so
it cannot validate only the inferred candidate. Unconditionally validating
all roots would weaken the existing explicit-root/source-path escape hatches.
Searching parents or the current working directory was rejected because it
could silently select a different checkout and recreate the wrong-tree
failure in a less obvious form.

Why: lazy sentinel resolution preserves zero-churn checkout behavior while
making installed-package behavior fail closed. Keeping resolution outside
manifest construction and canonicalization leaves schema, registry/AP byte
hashes, relative source paths, and manifest identity unchanged.

Consequence: installed callers that omit the root receive a deterministic
refusal instead of filesystem errors from a site-packages-relative tree. They
must pass the owning checkout explicitly; normal checkout callers continue to
use the validated default.
