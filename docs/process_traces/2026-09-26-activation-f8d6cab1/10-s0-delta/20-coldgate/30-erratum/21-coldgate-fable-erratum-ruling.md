## 2. Rulings on R-1 to R-5

### R-1 — UPHELD (BLOCKER). Amendment 30's witness `len(session["round_workers"])` is wrong.

P-A shows an unaltered, honestly finalized envelope with `end_stamp`, one journal row and two `round_workers` entries. Under amendment 30 as ruled it raises `CustodyUnreadable("round journal holds 1 rows; session records 2 rounds")`, and under amendment 32 that withholds the night's summary and records a custody failure that never happened. The ruling's E6 inference ("`end_stamp` on disk ⟹ row count equals `len(round_workers)`") is false because the two appends are separated by a parse that can raise (S1). Today this envelope finalizes normally and its numbers are summarised with `error` set; that is the honest record.

**Fix adopted:** the refuter's witness. S2 records `session["journal_rows"] = len(rows)` from the same `rows` list the finalization rewrite iterates, in the same `session.json` write that carries `end_stamp` (amendment 33, new). Shape (ii)'s count rule binds to that field. Shape (i) needs no witness: the refusal path writes no row by construction, so its rule is simply "zero rows". `round_workers` is no longer consulted by the helper for anything. The refuter's alternative (move the `round_workers` append) is rejected as a witness because any future edit between the two appends reopens the defect; the `journal_rows` field is computed at the instant the journal is written, from the list that is written.

Why this stays tight: deleting the file is caught by presence (unchanged); truncating to empty, removing one row, or duplicating a row changes the count against `journal_rows` (closes X6, X7); removing `journal_rows` from a completed record is `CustodyUnreadable("round count not recorded")`, because that write is the same write that carries `end_stamp`; an operator who rewrites `session.json`, the journal and the raw files consistently is out of scope under D-161, as the ruling already says.

### R-2 — UPHELD (BLOCKER). Shape (iii) must not read the provisional journal.

P-B shows the executor-produced shape (a collector killed after at least one round: `collector_exit` 124 then SIGKILL, per `:1566-1575`) raising `CustodyFailure` today, and the ruled amendment 30 keeps "the per-row digest cross-check … still runs on every row", so the false custody survives the ruling and amendment 32 promotes it to "no summary for the night". A provisional row records no digest (`new_row` `:1002`, `raw: {"paths": [], "sha256": {}}`), so there is nothing whose custody could have been lost; text 2(b)'s definition is not met.

**Fix adopted:** in shape (iii) the journal is provisional and is **not an input** to authentication: it is not opened, not counted and not cross-checked. The verdict is `evidence_missing` with the single reason `quiet span unavailable` at the span rung (amendment 21), unless rung (b) raises on the raw files first (P-B′ shows it does when the pre raw is deleted). The refuter's further recommendation is also adopted: a provisional journal that does not parse is not custody. The provisional append at `:1140` is a buffered write followed by `flush`/`fsync`; a row larger than the text buffer reaches disk in more than one `write(2)`, so a kill between them leaves a truncated last line honestly, and amendment 34 deliberately leaves the appends non-atomic. Not opening the file is not "converting a decode failure into an empty value"; the class rule is intact because no reader runs.

Residual downgrade checked: stripping `end_stamp` from a completed envelope to reach shape (iii) yields a non-pass, which text 6 blanks; no number escapes. Deleting a raw file in shape (iii) still raises from rung (b).

### R-3 — UPHELD (SHOULD-FIX, both parts), as S2 obligations plus one clause in amendment 32.

1. **Non-atomic final writes.** S2 confirms `write_json` is a bare `write_text` and the journal rewrite is `open("w")`. A kill during `:1208` leaves a truncated `session.json`, which amendment 29 rightly calls `CustodyUnreadable` (a present, unparseable container) and amendment 32 turns into no summary for the night. Amendment 34 (new) makes every `session.json` write and the finalization journal rewrite atomic (temp file in the same directory, `fsync`, `os.replace`), the pattern `record_attestation` already uses. After it, a present-but-unparseable `session.json` or finalized journal cannot be an honest collector output, and amendment 29's premise holds without exception.
2. **Crash before the first write.** The executor lists every launched collector. A collector that dies before `:1081`/`:1084` leaves an envelope directory with no `session.json`; amendment 29 would call that `CustodyUnreadable` and amendment 32 would withhold the night. Nothing was recorded, so nothing's custody was lost. The carve-out is written into amendment 32 and keyed on the executor's own witness (S3): an entry with `collector_exit != 0` whose directory holds **no** `session.json`, **no** `rounds.jsonl` (both by `lstat`) and **no** `raw/round-*` directory is excluded `collect_error` as today, without authentication. A pre raw file alone (`raw/battery_float.pre.ioreg` written before the first session write under text 5) does not defeat the carve-out: its digest was never recorded. Any other partial output, and any entry with `collector_exit == 0` and missing files (impossible honestly: exit 0 means `:1208` ran), keeps amendment 29's raise. The refuter's version of the carve-out ("no `raw/battery_float.*`") is tightened to this because it would otherwise raise on the honest pre-probe-then-crash sequence.

### R-4 — UPHELD (SHOULD-FIX). `summarize` enumerates by `rglob("rounds.jsonl")`.

P-D: a deleted journal makes the envelope invisible to `summarize`, an exclusion by omission that amendment 32 as written cannot reach ("every envelope directory the executor lists" names a list `summarize` does not have). A directory in that union lacking `session.json` raises under amendment 29; a directory with neither file is the R-3 no-output case and is legitimately not an envelope for `summarize`.
