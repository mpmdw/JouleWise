**N-1. `joulewise/arm_readiness.py:6724` `_T0_R1_TO_VALIDITY_ORIGIN_LIVENESS_NS`.**

What the constant does:
- It is ruled as (post-R1 `_fresh_probe` sites) × 45 s + 105 s = 11 × 45 + 105 = 600 s.

## Findings (implemented as ruled unless stated)

- **F-1 (test 8 premise cannot be reached at `c6814dd8`).** I checked this by running the code. Derivation sessions are bracket sessions. When the writer exits early, its own closure (`_CaptureLedgerLifecycle.abandon`, `validate_powermetrics_fiducial.py:1662-1673`) calls `abort_bracket_session`; it does not finalize the slot. Recovery `resume-finalize` finalizes only complete custody, and custody is written after the post-observation. The real writer killed at `AFTER_SAMPLER_TEARDOWN` then `repair` ends with the session `aborted` and no finalized row for the slot (DEBUG run: `state=aborted finalized=[] status=pass slots={}`). So the slot can hold no B value, and the validator's obligation (finalized rows only, per §5.5 and A-R5b "Window verdict") does not attach.
  - The test asserts this reachable outcome. It also keeps the ruled branch ("if a row is finalized, it is `evidence_missing`") for any future recovery path.
  - Consequence: a window whose writer died before the post-observation keeps its other finalized slots and can compute `pass`. The dead slot carries no battery verdict. A zero-slot session computes `pass` trivially, because it has no finalized slots to fail. It still contributes no members, and the W1 ≥ 6-valid rule catches it.
  - If the lead wants writer-death slots to taint the window, that needs a ruling. Two possible ways: treat declared slots whose custody holds `raw/battery_float.pre.ioreg` but no finalized row as `evidence_missing`, or key it on a non-`window_exhausted` abort reason.
- **F-2 (negative `update_age_s` passes).** §5.1 bounds only `update_age_s > 180`. An `UpdateTime` in the future (clock skew, or a corrupt register) therefore passes. The pre-existing `night_gate` green fixture relies on this: its `UpdateTime` is 1790373525 against a fake now of 1005. Recommend bounding at `0 ≤ age ≤ 180`, or `|age| ≤ 180`; that would also require re-stamping the green fixture.
- **F-3 (round 2's issuer broke Revision 5 precedence).** It read the disposition registry before the Revision 5 checks, so `test_acc_25g83_rev5 … test_issuer_refuses_unsealed_launch_context…` failed with "registry unreadable". Moving the block after the Revision 5 checks, which is still before the positional checks, fixed it.
- **F-4 (round 2's computed set was a superset).** It included every `--battery-confounded-session-id` in the computed set. That meant a declared non-pass session owning no foreign valid row was accepted. §5.5 clause 1 is now implemented exactly, and such a declaration refuses with "declared session is not a terminal derivation session of this registration or an A-7 foreign-row owner". The effect on science is nil either way, because that session has no valid rows.
- **F-5 (installer placement).** Rounds 1 and 2 probed first thing in `validate_install`. I moved the probe to just before `Prepared(...)`: that is the first render (`launch_context` renders every plist), and it comes after plan validation but before admission's `mkdir`. It still satisfies "before the template is rendered", the reading is fresher, and plan-validation refusals keep their precedence.
- **F-6 (issuer enforces the A-R5b replacement bound).** A second non-pass window refuses ("the epoch stops and returns to council"). §5.5's clauses do not list this; it comes from A-R5b "Replacement". Please confirm it belongs in the issuer.

Writer tests that don't use the fixture flag run the real `/usr/sbin/ioreg`. The result is recorded but does not gate. On ubuntu CI it is recorded as a probe error, and the writer continues as ruled.

Without this, re-authenticating an existing namespace was not byte-idempotent (`test_authors_exact_fifteen_valid_rows_and_is_byte_idempotent`, crash-point recovery). In production the two clocks are the same real clock.
