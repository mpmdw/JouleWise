## Disagreement with the row's framing

D1 (magistrate's call; default stated). The brief's Q1 invariant "no receipt byte moves for configs WITHOUT an expectation" is satisfiable literally only by gating the probe on `prompt_token_expectation is not None`. I recommend gating on `prompt_text is not None` instead: (i) the adapter then reports a physical fact, not a registration semantic, through the exact production realizer; (ii) `projection_input_sha256` then catches freeze→arm tokenizer drift for ANY prompt_text pack with no registration at all — a free second catcher; (iii) the only packs whose bytes differ under this gate are the `_v1–_v3` contrast packs, retired by D-167 and already derivation-stale (bench). If the literal invariant is ruled binding, the change is one condition in spec 1; everything else stands.
D2. "Defense-in-depth, not the fence" undersells it slightly: the arm re-run happens on the night stack with the night tokenizer, so it is the ONLY catcher that fires before a joule; row 01 fires after the first prefill bundle. The row's acceptance is right; its prose should say "first catcher, second fence".
D3. The kernel row says "council trigger" citing D-131, but D-131 itself carries no council clause; the trigger is the council skill's contract-bearing/hardware-adjacent rule. The PR should cite that, not D-131, so the gate is not "ruled-not-installed" again.
D4. The `text_sha256` comparison at freeze is a tautology (the adapter hashes the text it was handed) — kept only because it is the row-01 surface and costs nothing; it should not be described as physics evidence.
