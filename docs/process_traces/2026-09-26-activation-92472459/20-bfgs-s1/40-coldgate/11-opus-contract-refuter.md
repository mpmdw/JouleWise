### Findings

**SF-1 (SHOULD-FIX): amendment 38 R3 does not work for the fixtures it names.** R3 targets "a fixture that models a bundle measured before the battery check (one carrying a frozen legacy identity …)". Every frozen-legacy-identity fixture in `test_cli_run.py` / `test_audit_amplification.py` is made by the **head** controller, so it carries the MOCK marker key. The reader never consults the set for a key-present bundle (B-E1). A round-F seat following R3 literally stays RED, and the easy improvisation is to patch `_digest_bound_mock_config` or `_battery_verdict`. F-3 forbids that, so the round stalls. Replacement for R3's text:

> (R3) For a fixture that models a bundle measured before the battery check (enumerated by test name in the round-F brief; one carrying a frozen legacy identity, or a test-mutated copy of a tracked historical fixture), the shared helper first deletes the `battery_float` key from `metadata.json` (a pre-check bundle has none), then, after the test's last mutation, computes the bundle's complete digest and patches the function amendment 39's reader consults for complete-kind entries, so that it returns the production entries plus exactly that one digest; the helper asserts the patched set is the production set plus one. Every R3 test asserts `reader.battery_float_status == "unobserved_historical"`, and F-6's counterfactual for an R3 test is "patch removed → the test fails with `prospective bundle`". R3 is never used for a bundle that models a new measurement.

**SF-2 (SHOULD-FIX): amendment 38 R2 can silently change what a fixture measures.** Section A E13: the 24 `test_window_duration_margins` cases build a powermetrics bundle from a real campaign config and a real `powermetrics.plist`. The triage prescribed "MOCK config" for class B, and R2 permits it. Retargeting such a fixture to `mock` may keep every assertion green (F-4 is satisfied) while the test stops exercising the powermetrics path. Add to F-1:

> R2 is available only to a fixture whose `config.json` backend is already `mock` at `1417c0c4`; a fixture whose backend at base is not `mock` takes R1 (or R3 under its own conditions) and keeps its backend. The round's report lists each fixture's base backend beside its remedy.

**SF-3 (SHOULD-FIX): `authenticate_window_members` violates amendment 26, and no amendment of this ruling fixes it.** Section A E12: text 8's `evidence_missing` refusals (`prospective bundle`, `invalid record`, `not_reached` with an obligation) are converted into `CustodyUnreadable`, a `CustodyFailure` subclass whose docstring forbids any status meaning. The loop stops at the first such member, so a two-bad-member window names one. Amendments 37 and 39 keep those refusals as `BundleReadError`, so the conversion survives the ordered fix round. Nothing leaks, because the whole set is refused either way. But a status is reported as custody, the inverse of "custody is never a status", and the refusal does not name every member. Proposed text:

> **Amendment 42 (amends amendment 26; S1's existing scope, `bundle_read.py` and `tests/test_bfgs_window_consumers.py`).** In `authenticate_window_members`, a `BundleReadError` whose message begins `battery_float_evidence_missing:` or `battery_float_confounded:` becomes a refused entry `{label, status: <that prefix>, reasons: [<the rest of the message>], bundle_sha256: complete_bundle_sha256(path) or None if that raises}` and the loop continues; every other `BundleReadError` (unreadable or malformed `metadata.json`, `events.jsonl`, the set file) raises `CustodyUnreadable("<label>: <message>")` as today. After the loop, `WindowBatteryRefusal` names every refused entry. Tests: a window of two prospective members raises `WindowBatteryRefusal` naming both (RED at `24b79db3`: `CustodyUnreadable` naming one); a member with an unreadable `metadata.json` still raises `CustodyUnreadable` naming it.

**SF-4 (SHOULD-FIX): a member's `CustodyFailure` is unlabelled, and amendment 36's round-2 rule removes the consumer's way to label it.** B-E2: a raw-file custody failure inside the window check propagates with no member name, but text 12 says the consumer refuses "naming the member" on `CustodyFailure`. Amendment 36 tells the eight consumers not to import `battery_float`, so they cannot write `except battery_float.CustodyFailure` to add the name. > `authenticate_window_members` wraps each member's classification in `except battery_float.CustodyFailure as exc: exc.add_note(f"window member: {label}"); exc.window_member = label; raise`, re-raising the **same** object (class, message and failure list unchanged; `requires-python >= 3.11`). **SF-5 (SHOULD-FIX): an unruled production change survives the ruling.** B-E5, Section A C-4: S1 writes a synthetic `idle_drift_sentinel` stage (`{"status": "unavailable"}` plus `monotonic_ns`) into `events.jsonl` for wall_meter, NVIDIA and every other non-powermetrics, non-MOCK run.
