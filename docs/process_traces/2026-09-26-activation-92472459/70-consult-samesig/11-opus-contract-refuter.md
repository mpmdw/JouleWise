### Q-A1. Is A→B→A inside the gate's threat? **No.** It needs a coherent forger, and a permanent forgery would already achieve everything A→B→A achieves.

**What the verdict depends on.** `authenticate_quiet_session` (`battery_float.py:955-1023`) is a pure function of four files and their filesystem shape: `session.json`, `rounds.jsonl` (opened only in shapes (i) refusal and (ii) completed), `raw/battery_float.pre.ioreg` and `raw/battery_float.post.ioreg` (opened through `_raw_bytes` only for a phase whose record passes the field checks). `parse` reads no clock and no file; `update_age_s` comes from the stored `wall_time_s`. So B, the state the authenticator must see for a night that was really charging or had a lost record to pass, is a complete, self-consistent passing set: pair records whose digests match raw bytes that parse as "not charging, current below 200 mA, fresh", a journal whose row count equals `journal_rows`, and every row's `raw.sha256` equal to both pair digests. For a genuinely charging night the raw ioreg bytes themselves have to be forged.

**Who writes these files on a real night** (`a0e8e47f`):
- *The collector* writes forward only. It writes the pre raw, then the first `session.json` write, then appends journal rows, then atomically writes the final session and journal (`atomic_write_text`: temp file, fsync, `os.replace`). On the refusal path it writes the post raw, the session, then an empty journal. No step restores earlier bytes.
- *`record_attestation`* (`quiet_predicate_campaign.py:769`) runs once per envelope inside `execute`, after the collector exits and before `pilot_summary` (`:1695`, then `:1776`, in the same process, in sequence). It adds `network_time_provenance.attestation` and never touches `battery_float` or the journal. Its docstring says nothing else rewrites `session.json` after the collector exits.
- *The executor* (`execute`) reaps the collectors and then calls `pilot_summary`. It writes no envelope file. `summarize` is a harvest-time reader.
- *A surviving collector*, after a failed cleanup, would still write forward (A→B). F4 raises on that whenever the write straddles the authenticator's reads.

No honest producer performs B→A. **What the probe needed:** `unittest.mock.patch` on `battery_float.authenticate_quiet_session`, so the swap to B and the restore to A happen exactly inside the call. In the probe, B is the original passing session and A is the same session with `post` deleted. On a real machine you would need an outside process that writes a coherent passing B, wins a sub-millisecond race twice, and restores A. Anyone who can write a coherent B can leave it on disk permanently and pass every reader, because reading bytes cannot tell a forgery from the real thing. A→B→A adds nothing to that attack. The packet already places a consistent rewrite of session, journal and raws out of scope (D-161 sentence quoted above).

The authenticator opens `rounds.jsonl` and each raw file only when the session's content calls for it, so a copy step that applies those checks unconditionally is **stricter**, not equal. Executed with my fail-closed variant on 57 envelopes: 50 identical, 6 cases where one custody raise replaces another, 1 case where `evidence_missing` becomes a raise (a first-write envelope with a symlinked journal), and 0 cases that are laxer. A **shape-preserving** copy needs no duplicated logic and is exact: absent stays absent, a symlink stays a dangling symlink, a directory stays a directory, and regular files are copied through `O_NOFOLLOW` (57/57 identical; `/tmp/opsg/snapshot_proto.py`). **Replacement for the last paragraph of §A2.4:**

> **The condition that any snapshot must meet.** The copy must never make a path more readable than it is at the source. Either (i) it preserves each path's shape (absent stays absent; a symbolic link, including one at `raw/` or at the envelope directory, stays a link that the authenticator will refuse; a non-regular entry stays non-regular; regular files are copied through `O_NOFOLLOW` with an `fstat` check), which was measured verdict-identical on 57 envelopes; or (ii) it raises `CustodyUnreadable` on any link or non-regular entry among the envelope directory, `raw/` and the four paths, which is strictly stricter and never laxer. Two counterfactual rows are mandatory: a copy that follows links turns five custody failures into `pass` (symlinked `session.json`, `rounds.jsonl`, pre raw, `raw/`, and envelope directory), and a copy that creates an absent `rounds.jsonl` as empty turns a refusal envelope's `round journal missing` into `pass`. Both were executed.

### NIT-B2: amendment 48 should state how the witness names a bundle whose `metadata.json` cannot be read, and should align the existing digest-hit name check with the new naming rule

Amendment 48 makes `metadata.json`'s `run_id` a naming key, but it does not say what happens when a bundle's metadata cannot be read or has no string `run_id`. It also keeps the digest-hit check "the entry's `run_id` equals the bundle's directory name", which raises `ValueError` for an intact bundle whose directory was renamed even though its `metadata.json` `run_id` still names the entry. Executed on the corpus: 1 402 metadata files, 0 unparseable, 0 with a missing `run_id`, and **1 whose `run_id` differs from its directory name**. Neither issue fires at base. **Add to amendment 48, *Terms*:**

> If `metadata.json` cannot be parsed or has no string `run_id`, the bundle names an entry by its directory name only, and the witness prints `witness metadata_unreadable <path>`. That line does not change the exit status. On a digest hit, the name check passes when either the directory name or the `metadata.json` `run_id` equals the entry's `run_id`.

### NIT-B3: amendment 46's consequence (ii) could name the likely kill point

This is for the record, and no change to the rule. On the refusal path the only step that can block until the executor's timeout kill is `battery_read("post")`, an `ioreg` subprocess, and it runs **before** `write_json(session)`. A timeout kill therefore most likely leaves a lone pre (and possibly post) raw file with no session, which is the 32(1) carve-out, not the consequence (ii) window. That supports the ruling's "rare". **Optional sentence for 46(ii):** "The one blocking step on this path, the post battery reading, runs before the `session.json` write, so an executor timeout kill lands in the carve-out, not in this window."
