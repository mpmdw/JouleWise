**Terms used below.** *Identity epoch*: the six-field vector {os_build, hardware_model, power_policy, sampling_interval_ms, estimator_revision, pulse_protocol_id} that an issued acceptance binds. *Acceptance*: the JSON artifact whose corpus statistics set the two screens (the level screen, which is the corpus maximum, and the bracket screen, which is the corpus range). *Observation*: one 59-pulse calibration capture, written to the ledger as a reservation row followed by a finalization row. *Ledger*: the append-only hash-chained file of those rows; the *head pin* is the committed file naming the row count and last digest that consumers trust. *Session*: a ledger capability that reserves several attempts in one row while the head pin stays put. *Derivation-only*: a capture taken to build a future acceptance, never to license a measurement. *Prior set*: the acceptance's list of every ledger observation up to its cutoff row. *Corpus*: the subset of the prior set whose values the acceptance's statistics are computed from.
