Load: a 1-minute average decays by e⁻¹ per minute; even a load of 8.0 at the kill (several Sol seats running) is 8·e⁻⁴ ≈ 0.15 at t0, far under 2.0. Total quiet before the first collected byte on a real night ≈ 240 s (pre-t0) + ≈5 s (driver) + 180 s (chain settle) ≈ 425 s. The cooperative window (request at t0 − 1200 s, force at t0 − 300 s) gives a session 15 minutes to commit, push, email, stop Codex children, and exit — ample for a session that polls the request file every few minutes; a session stuck in one long tool call falls through to the force, which is what the force is for.

**Minimum I would accept, and why:** SIGKILL at or before **t0 − 180 s** — the project's own frozen post-activity settle constant (F-5), the number the chain itself treats as sufficient quiet after operator activity — with SIGTERM at least **60 s** earlier (twice the reference implementation's 30 s TERM→KILL grace, `run_night.py:330-341`), and a post-kill census re-read at least 60 s before t0 so the outcome is on disk. The proposal's t0 − 240 s / t0 − 300 s exceeds that minimum by 60 s at each step; Ed's item 7 ("5 minutes") is honoured. I would not accept SIGKILL later than t0 − 150 s (the runbook's lower settle bound).

**Conditions (MATERIAL unless noted):**
- C4-a The deadlines must be enforced by a **resident** supervisor with ≤ 10 s resolution (the shape the packet §1 describes: "a Python supervisor that exits fast unless it owns a live child"). A 300 s `StartInterval` tick alone cannot hit t0 − 300 s: a tick-quantised SIGTERM could land anywhere in [t0 − 300, t0]. A unit test must pin the resident enforcement (exhibit 04 test 11, 09 `test_owned_group_gets_term_then_kill…` are the right shape).
- C4-b The request file at t0 − 1200 s must also be written by the resident supervisor (not the next tick), and the plan list re-read at least every 60 s so a plan authored after launch moves the deadline (exhibit 04:90, 09 "A newly observed plan preempts backoff").
- C4-c The kill is proven by `wait()` on the recorded group (F-7 `_terminate_process_group` returns proof, not hope) and followed by one census whose lines are logged. No timing cures a process outside the owned group (a detached shell, a `codex` started with its own session); that residue is Q3(g)'s hold and the refusal's business, and the record must say so rather than imply the 4 minutes handles it.
- C4-d (NIT) State the numbers as seconds in code (`1200`, `300`, `240`) with a comment citing D-171 item 7, and test the ordering `request < term < kill < t0`.

## Q5 — Kill switch: GitHub branch probed by anonymous `git ls-remote --exit-code` versus a root file on `main` — **AFFIRM the branch**

So: absent ref → exit 2, present ref → exit 0, and the probe completes with every credential helper disabled — no authentication is needed or used.

**Why the branch and not the file on `main`.** A root file on `main` (exhibit 09 §2 item 6, §7 last paragraph: "Ed creates it in a pushed `main` commit to stop and deletes it in a later pushed commit to resume") moves `main`; when the canonical checkout follows, `checkout_head != plan.repo_head` refuses the night with `night_plan_stale` (`night_gate.py:599-609`; installer parity at `install_night_agent.sh:40-45`). The stop switch would then stale the very night it was meant to protect. A branch ref never touches `main` (exhibits 03 §8.3, 04 §8 item 8). Sol's `gh api …/contents/MAGISTRATE_STOP?ref=main` also depends on the machine's keyring `gh` login (exhibit 09:157-162), a second credential the design does not otherwise need.

**Authentication / rate.** None needed (executed above). The probe is one smart-HTTP `info/refs` request every 300 s (≈ 12/h); it is not a REST API call and is not subject to the 60/h unauthenticated REST limit; even under that limit it would fit. Fail-open on transport error (exhibits 03 test 7, 04 I5) is consistent with D-161 (the only adversary is Ed's own network) and must be logged as "unknown", not "not stopped".

**Conditions:** (NIT) one ref name — the packet picks `ops/stop-magistrate`; exhibit 04's `magistrate-stop` must not survive into code or the operator card.
