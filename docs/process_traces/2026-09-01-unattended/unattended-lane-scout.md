**What "agent session active" is checked AS, in code — three distinct, non-equivalent spellings, all name-matching, none load- or activity-based:**

| Site | Predicate | Failure semantics |
|---|---|---|
| `joulewise/arm_readiness_evidence_t0.py:1724` (T-0 `PROCESS_CENSUS`, the production check) | `/usr/bin/pgrep -lf "codex\|claude\|t3"` | `_expect_absent` (`:1312-1314`) requires **exit code exactly 1 and empty stdout**; anything else raises `_underivable(kind, "fresh agent census found a forbidden process")`. Same block also refuses `caffeinate`, browsers, and `powermetrics\|window-chain\|run_campaign\|tail -f\|watch`. |
| `joulewise/t0_rehearsal.py:57` + `:796-802` + `:807-856` (rehearsal gate G8, "ZERO-AGENT CAPTURE") | `_AGENT_TOKEN_RE = re.compile(r"(?:^|[/\s])(codex\|claude\|t3)(?:[/\s]\|$)", re.I)` over the joined `argv` of each census row | Requires `agent_exit_monotonic_ns < capture_started_monotonic_ns <= capture_finished_monotonic_ns`, the exiting `agent_pid` bound in the pre-launch census, and **no** agent-matching process in **any** capture-time census. |
| `scripts/quiet_mac_prep.sh:38` (operator advisory) | `pgrep -fl "codex exec\|codex mcp\|claude"` | Prints only; no exit-code enforcement. |

**Does an IDLE `claude` / T3 Code process count?** **Yes, unconditionally, under both enforcing checks.** `pgrep -lf` matches on the command line, and `_expect_absent` demands exit 1 with empty stdout; there is no CPU, load, wall-clock, or state qualifier anywhere in the predicate. A `claude` process merely sitting at a prompt refuses the T-0 `PROCESS_CENSUS` row and therefore the arm. Note also that the regexes differ in strength: the production `pgrep -lf "codex|claude|t3"` is a bare substring alternation (it will also match e.g. any path containing `t3`), while G8's regex requires a `/` or whitespace boundary — so **G8 is strictly weaker than the production check** and, per the producer-row draft's acceptance item 2 (`:59-61`), misses `codex-helper`, `claude-code`, `/usr/local/bin/codex-run`.
