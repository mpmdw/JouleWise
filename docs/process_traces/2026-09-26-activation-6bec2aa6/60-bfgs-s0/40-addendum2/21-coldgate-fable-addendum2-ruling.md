## 2. Q1 — the quiet-envelope span (Opus B-1; Sol F2; Astra R2)

### Decision

1. **One conversion, floor, used on both sides.** S0 adds `battery_float.monotonic_ns_from_s(seconds) -> int` = `math.floor(seconds × 10⁹)`, refusing `bool`, non-finite and negative input with `ValueError`. The quiet span bounds are computed with it, and S2 passes `monotonic_ns=lambda: battery_float.monotonic_ns_from_s(clock.monotonic())` to `observe`, where `clock` is the same `Clock` instance whose `stamp()` writes `start_stamp` and `end_stamp`. Opus's `ceil` on the end bound is **not** adopted.
2. **Span source.** `start = monotonic_ns_from_s(start_stamp.monotonic_before_s)`. `end = monotonic_ns_from_s(end_stamp.monotonic_after_s)` when `end_stamp` is present. When `end_stamp` is absent **and** the envelope is the exact refusal shape (`error_class == battery_float.QUIET_REFUSAL_ERROR_CLASS`, a new constant equal to the collector's `NETWORK_TIME_REFUSAL` string `"network_time_provenance"`, and `rounds.jsonl` exists and holds no row), `end = monotonic_ns_from_s(start_stamp.monotonic_after_s)`. Any other absence or malformation is `battery_float_evidence_missing` with the single reason `quiet span unavailable`.
3. **Every kind validates its span at rung (f), never raising.** A span that is not a 2-tuple of non-`bool` `int`s ≥ 0 with `end ≥ start` is `<kind> span unavailable` for quiet, bundle **and** capture alike, evaluated only after rungs (a)–(e) for both phases; equal bounds are permitted (gap-fill). `authenticate_pair` called with kind `quiet` or `bundle` and `span=None` raises `ValueError` (those kinds always owe a span; the wrappers pass the sentinel `(None, None)` when the span is unavailable).
4. **The pair's own stamps are validated at rung (f) for every kind, span or not.** Each phase's `monotonic_before_ns` and `monotonic_after_ns` must be non-`bool` `int`s ≥ 0 with `before ≤ after`, and `pre.monotonic_after_ns ≤ post.monotonic_before_ns`; otherwise `battery_float_evidence_missing` with reason `pair stamps malformed`.

### Reasons

- **Why the refusal shape passes with the start stamp as its end.** The refusal envelope measures nothing (E11: it returns before any recorder is built and contributes zero rows). Text 5 deliberately puts both reads on that path so that text 6 has no special case; the only instant the envelope stamped is `start_stamp`, so "the pair brackets the measured span" reduces to "the pair brackets the start stamp". Text 5 already places the pre read before `start = clock.stamp()` and the post read after the return point, so this is satisfiable by construction. The alternative (exempting refusal envelopes from the pair) contradicts text 5 and would make text 6 recognise envelope shapes it should not know about. E12 shows the collector's own summary code already treats "one early refusal voids the night" as a false record; ruling otherwise would re-create v1.1 blocker 1.
- **Why floor on both sides rather than floor/ceil.** With one monotone conversion `f`, `m₁ ≤ m₂` in float seconds implies `f(m₁) ≤ f(m₂)` exactly (E16: multiplication by a positive constant is monotone under IEEE round-to-nearest; floor is monotone). So `pre.after ≤ start` and `post.before ≥ end` hold whenever the underlying reads were ordered, with no rounding refusal. With `ceil` on the end bound, a post read in the same clock tick as the end stamp fails; this Mac's monotonic tick is 41.67 ns (E16), so that is not hypothetical. A gate that can refuse on a tick boundary is exactly the microscopic tolerance v1.1's sensible-gate stance rejects.
- **Why S2 must route the probe stamps through the same `Clock`.** `observe` defaults to `time.monotonic_ns()`; the collector's stamps come from `time.monotonic()` via `Clock`. They are the same hardware clock (E16) but different call paths and rounding, and under an injected test clock they would diverge entirely. Text 5's sentence "the collector's clock is passed to `observe(monotonic_ns=…)`" is made concrete: the same object, through `monotonic_ns_from_s`.
- **Why the span check is kind-wide and non-raising.** E3 and E4 show the current validity guard is bundle-only and that a malformed span raises before custody, inverting the ruled order (custody first). A reversed or malformed span is missing evidence about the measured interval; it is not a custody defect and not a programming error to be raised out of the rung order.
- **Why the pair's own stamp order is checked.** Without a span (kind capture) nothing today orders pre before post. `observe` has always written the four stamps as ints in one process, so every genuine record satisfies the check; a record that fails it was not produced as a bracket.

## 4. Q3 — capture identity binding (Sol F1; Astra R4)

### Decision

**S0 must** (round 3, kind `capture` only, all at rung (a) as `battery_float_evidence_missing`, never `CustodyFailure`):

1. `instrument_evidence.validation_id` must be a non-empty `str`; else `capture identity missing`.
2. Pre and post must agree on `session_id`, `slot` and `attempt_id` (each compared with `==`, `None` allowed); else `pair identity disagreement`. The identity passed to `authenticate_pair` is the agreed `session_id`.
3. When `attempt_id` is non-null it must equal `validation_id`; else `attempt identity mismatch`. When `attempt_id` is null, `session_id` and `slot` must also be null (the ordinary-capture shape, E13); else `partial identity`.
4. `authenticate_capture(capture_dir, *, expected: Mapping[str, str | None] | None = None)`. When `expected` is given it carries exactly the keys `attempt_id`, `session_id`, `slot`; `validation_id` must equal `expected["attempt_id"]`, and the records' `session_id`/`slot` must equal `expected["session_id"]`/`expected["slot"]` (a `None` value means "must be null"); else `ledger identity mismatch`.

**S1 must:**

5. Text 10's `_battery_exclusion_for_observation` passes `expected = {"attempt_id": observation.attempt_id, "session_id": observation.bracket_session_id, "slot": observation.bracket_slot}` **after** its evidence-digest check (`instrument_evidence.json` sha256 == `observation.artifact_sha256[...]`, else `CustodyFailure`). That digest check is the ledger-owner binding: the ledger row names the attempt and pins the bytes that contain both the pair and `validation_id`.
6. Text 11's attachment site calls `authenticate_capture(source_dir)` with no `expected` (the controller holds no ledger row); the internal checks 1–3 apply.
7. T10 gains: (e) pre/post disagreeing on `slot` refuses; (f) a bracket capture whose records name a session other than the row's `bracket_session_id` refuses; (g) an ordinary capture (null identity) with `validation_id == observation.attempt_id` passes; (h) an ordinary capture whose `validation_id` differs from the row's `attempt_id` refuses with `ledger identity mismatch`.

### Reasons

- Sol's "both attempt ids equal `validation_id`" is correct only for bracket captures (E13: `validation_id = args.attempt_id` in bracket mode). Ordinary captures write null identity by construction and a fresh `validation_id`; requiring equality there would refuse every ordinary capture ever taken (E7 is the ordinary shape). Rule 3 encodes both shapes.
- The pair cannot bind itself to a ledger owner from inside the capture directory: the owner is a ledger fact. The ledger already refuses finalization when `validation_id` disagrees with the reserved attempt (E14), and text 10 already pins the evidence bytes to the row. Passing the row's identity into the wrapper (rule 4–5) closes the loop mechanically at the one production site that has a row, without teaching `battery_float.py` about the ledger.
- Identity faults are structural (rung (a)), not custody: custody is "bytes differ from a recorded digest", and the digest check that owns it sits in S1's predicate.
