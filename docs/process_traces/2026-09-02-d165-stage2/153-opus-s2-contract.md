## Findings

**F1 — BLOCKER — unruled, untested widening of the pre-registered sidecar schema; the validator's fresh-replay comparison is disabled for the new shape.**
`joulewise/dominance_closeout.py:124-132` adds `_COMMON_MODE_REFUSED_RESULT_KEYS` (9 keys), `:791-803` `_build_common_mode_refused_result`, `:858-880` a new validator branch, `:1105-1111` the builder/validator entry. Three defects compound:
1. *Outside remit.* Clauses 7–14 and R-1..R-4c say nothing about a refused `common_mode_replay.result`. Stage 1 fixed `result` as exactly 7 keys (`docs/contracts/d165_dominance_closeout.md:180-189`). This is a shape change to a pre-registered evidence artifact made without a ruling. Nothing forced it: without it the zero-denominator `ValueError` becomes `CLOSEOUT_INPUT_MALFORMED` and the mint refuses to emit — the fail-closed stage-1 behaviour.
2. *Version discipline inverted.* The same commit deletes the sentence that justified keeping `…replay.v1` ("because no production sidecar was emitted before this exact shape was fixed") and replaces it with "The Stage-2 emitter writes the established schema version" (`d165_dominance_closeout.md:144-145`). The one line a reader would use to detect an unversioned shape change was removed in the commit that made the shape change.
3. *Fail-open against the contract's own guarantee.* `dominance_closeout.py:858-880` returns at `:880` **before** the `expected` comparison at `:894-895`. A sidecar whose blocks replay to a perfectly good complete result is accepted while storing the refused shape, and `refusal_reason` is only checked nonempty — not pinned to `DOMINANCE_ZERO_DENOMINATOR_REASON`. Contract `:198-200` states the validator rejects "a stored result that differs from a fresh replay". It no longer does for this shape. Direction is fail-closed for the verdict (a pass can be suppressed, not manufactured), which is why this is a blocker on contract/evidence grounds rather than on claim-corruption grounds.
4. *Zero coverage.* No test in `tests/` constructs a refused `common_mode_replay.result`; grep for `_build_common_mode_refused_result` and `"status": "refused"` across `tests/` returns only independent-record and unrelated hits (`tests/test_d165_dominance_closeout.py:517,547`). ~40 lines of new closed-schema custody code, untested.
Cure (cheapest): delete the refused shape and let the zero-denominator raise as before. If it is wanted, it needs a ruling, a full field table in the contract (the added paragraph at `:190-195` omits `rule_id` and `passes` and calls the Boolean `passes` a "numeric result field"), the `expected`-comparison and `refusal_reason` pin, and tests both ways.

**F2 — SHOULD-FIX — the byte pin runs in a fixed `/tmp` directory it `rmtree`s, and is parallel-hostile.**
`tests/test_mint_floor_artifact_generalized.py:6774-6805`: `StableTemporaryDirectory.path = Path("/tmp/joulewise-test-d165-phase0-floor-pin")`, `shutil.rmtree(..., ignore_errors=True)` on enter, `mkdir(exist_ok=False)`, `rmtree` in `finally`, with `tempfile.TemporaryDirectory` monkeypatched **module-wide** for the duration. On the docstring claim ("nine provenance sha256 scalars"): the arithmetic is right for the enumerated set — `cells[0..3].provenance.{absolute,comparative}.extraction_report.sha256` (8) + `provenance.calibration_plan.sha256` (1) — but "the digest binds nine … scalars" is false as written: the digest binds the whole file, which also carries `order_manifest.sha256`, `campaign_log`, `extraction_spec.sha256` and `bundle_sha256s` per component (`joulewise/detection_floor.py:2007-2018`). ## Clause 10 ownership assessment (asked directly)

The lazy import is an **honest** satisfaction. `joulewise/analysis_manifest_v3.py:1152-1162` returns `dominance_closeout.REPLAY_SCHEMA_VERSION`; the owner defines the sole literal at `dominance_closeout.py:31` and imports `analysis_manifest_v3` at load (`:19`), so a module-level import would cycle — the function-scope import is the standard break, is documented in the docstring, and leaves exactly one literal in the tree. Unlike `ec761c04`'s `"joulewise.d165_" + "dominance_replay.v1"`, there is no second copy to drift.

Census coverage of evasions (`_folded_string_constant`, `tests/test_d165_dominance_closeout.py:364-377`): caught — plain constants, `+`-chains, implicit adjacent concatenation (the parser folds it), and f-strings with **no** placeholders. Slipping past — f-strings with any `FormattedValue` (`f"joulewise.d165_dominance_replay.v{n}"`), `"".join(...)`, `str.format`, `%`-formatting, `.replace`, `chr()` assembly.

Warranted to close? **No — not by enumerating string forms.** Under D-161 the operator is not an adversary, and the census exists to stop *drift* (a second copy going stale), not attack; enumerating syntax is an unwinnable arms race with a non-existent opponent. The `ec761c04` incident is not a counter-example about adversaries — it is one about an author under test pressure, and the honest reading is that the reviewer caught it, which is the mechanism working. If anything is spent here, spend it form-independently and once: scan each non-owner module's compiled `co_consts` recursively for the literal (this catches every compiler-folded form, including `+` chains and placeholder-free f-strings, without a syntax whitelist) and widen the file set per F3. Runtime-split forms (`.join`/`%`/`format`) should be left open by explicit decision, not chased.
