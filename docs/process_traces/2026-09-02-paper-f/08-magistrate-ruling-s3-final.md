# Magistrate ruling on §3 (revised on the scout's evidence), 2026-09-03 21:30 PDT

The round-2 ruling ("a §3 question stays in the table only if a `_v5` registry row has a data-producing supplier") split the table on the wrong axis. The scout (file 06) shows, with generator lines, that the `_v5` packs collect PRIMITIVES for all four characterizations — same-condition null A/B/B/A blocks in both floor packs, reference probes at start/interior/end in every pack, and per-phase metrics — but no generator emits any characterization result field, and the registry's V5 section states "No characterization report has been issued" (KEY_FROZEN / VALUE_UNISSUED for DS-02/03/05/06). The delta re-audit's B9 (file 07) therefore stands on its own terms: the two-row table was unjustified.

Ruling R3-final-2 (supersedes R3-final in the round-2 brief): §3's characterization table keeps ALL FOUR rows, each with a status column stating in plain words (a) which primitives this campaign collects for it and where, and (b) that the characterization report itself is not issued by this campaign; the "does not collect" paragraph is rewritten to say exactly that for all four (no method prose is deleted — a later campaign applies the frozen calculations). The retensing plan's Outcome D stays: the floor packs' null blocks are calibration data that build the comparator floor, not a separate characterization campaign; §3 says so in one sentence. No number enters the table.
