**4. AUDIT.** Skeptic attacks, in order: (1) *trace → calibrated phase energy*: transfer of a 10 W-plus GPU-matmul rising edge under light CPU load to a real prefill→decode falling step with CPU/ANE mix — the paper itself calls this "an explicit assumption" three times; as designed, nothing in `_v4` tests it. (2) *floor*: Student-t at n=5–10 with a hand-set g(n), and drift containment only on held-out probes that are themselves reference members of the same window; survives if the null ladder passes because that is a real falsification test. (3) *verdict*: the claim-side bound B_claim has **no supplier** (registry row `[B_decode_claim_J]` is STOP_FILL / SUPPLIER_UNKNOWN), so the disclosed sizing sum cannot render; and Holm p-values are invoked with no test statistic defined anywhere — the pipeline produces deterministic intervals, not p-values. As designed, links 2–3 survive with fixes; link 1 does not. Cheapest closure: one *inserted-gap fiducial arm* — ~10 runs where the runtime sleeps a commanded 500 ms between prefill end and decode start, making the real workload's boundary a fittable valley; fit its edges with the existing pulse estimator and compare the residual with the pulse-derived bound. Twenty minutes of window time, no new code beyond a sleep and an event.
