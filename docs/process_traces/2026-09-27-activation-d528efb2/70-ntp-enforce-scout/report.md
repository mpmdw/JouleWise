## Binding rule and immediate finding

A3 [§§4.4–4.6](../40-sci-a2-network-time/31-addendum-ruling.md) supersedes A2's 300 s, header-only H6. H5 requires the exact OFF command to exit 0 and print `setUsingNetworkTime: Off`, with argv, exact output, exit and dual-clock receipt, at least 600 s before the first paired reading; restore ON after the last paired reading with a receipt. H6 requires one prompt whole-window syslog query from first paired reading minus 3,600 s through last paired reading plus 1 s, a `[com.apple.timed:data]` witness **older than first reading minus 180 s**, and per-capture marker search over each capture's 180 s lead through its last reading plus 1 s using the wider bounds of both clocks. Failed query, bad header, absent witness, or no query means **every** capture `network_time_unattested`; a marker in a capture interval means that capture `network_time_slew_attested`. Neither may become a calibration member, bracket endpoint, or claim-bearing capture. A3 keeps the evidence chain's immediate per-envelope query; both verdicts must pass. The command's `-getusingnetworktime` form cannot substitute for the OFF receipt (A3 §4.4).

The main design hazard is timing: the calibration writer classifies, hashes evidence, and finalizes a `valid` ledger row **during each slot**, before the post-window coverage witness can exist ([writer:2636–2705](../../../../scripts/validate_powermetrics_fiducial.py), [chain:218–290](../../../../scripts/night_chains/calibration_derivation_only.zsh)). A later H6 document alone does not revoke that row. Any implementation must put an authenticated H6 admission check at every downstream membership/binding/claim boundary, or create a reviewed pending-to-final ledger protocol. The smaller change is an immutable window-attestation artifact plus mandatory downstream admission checks; old rows remain historical and cannot be relabelled silently.

## H6 artifact and refusal contract

Proposed common read-only parser/query helper: accept explicit paired-clock bounds and a process runner; produce a write-once `window-timed-log` raw file and a canonical verdict manifest keyed by window id and capture content/attempt id. Include command argv, return code, full-output SHA-256, query wall/monotonic times, header status, category-matched witness line/timestamp, first/last paired readings, computed wall/monotonic union bounds, marker lines/count per capture, and the exact reason. Verify the raw digest and roster completeness before accepting the manifest. A missing capture row is `network_time_unattested`, never an implicit clean. Query as soon as the last capture ends and before any B read; re-query after crash is permitted only if it independently finds the witness (A3 §4.5). Parse syslog's explicit UTC offset rather than discard it: current `quiet_predicate_campaign.py:535–563` drops the offset and documents a repeated-hour ambiguity. Refuse ambiguous/malformed timestamps rather than letting a parsing failure look like zero markers. The A3 marker rule is any matching line, not merely the `timed_log_matches` grouped event count at `:569–590`.

Reuse evidence reasons `network_time_slew_attested` and `network_time_unattested` from `quiet_predicate_campaign.py:55–56,842–850`, after adding them prospectively to each route's registered vocabulary where necessary. For calibration, an H6 failure is a named invalid/excluded capture in the governed roster; the existing writer's `ordinary-invalid` and ledger `valid` classifications at `validate_powermetrics_fiducial.py:466–510,1699–1789` do **not** currently express H6. The issuer's completeness/purity checks at `calibration_bracketing.py:871–1027` must see the H6 exclusion and the registration's named mechanism. For bracket captures, use existing invalid-endpoint refusal (`calibration_bracketing.py:1320–1355`; `scripts/build_bracket_binding.py:227–258`), plus the H6-specific cause in `brackets_attempted` required by cap C7; do not build a binding from a ledger-valid but H6-failed endpoint. For evidence harvest, the two existing exclusion strings already flow into `pilot_summary`. For a claim pack, hold/refuse the **whole claim evaluation** if any claim-bearing capture lacks clean H6, while retaining per-capture cause and all attempted bracket rows. Cap R8 independently holds the whole claim window for a cell-count/deadline stop; H6 must not become an outcome-based survivor filter.

Do not route this through the four D-138-pinned estimator files unless a reviewed design proves it unavoidable: `joulewise/powermetrics_fiducial.py`, `joulewise/uncertainty_evidence.py`, `joulewise/adapters/powermetrics.py`, `joulewise/reduce.py` (`docs/decision_log.md:10361–10378`). `scripts/validate_powermetrics_fiducial.py`, `joulewise/calibration_bracketing.py`, and `joulewise/quiet_predicate_campaign.py` are not in that four-file pin set, but changing their behavior can still move protocol, source, chain and registration digests. H6 changes admission, so the prospective registration amendment and new capture/issuer rules require science/lead review, not a silent parser-only patch.
