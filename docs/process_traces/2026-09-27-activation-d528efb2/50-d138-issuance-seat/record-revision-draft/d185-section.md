**Terms, so the entry can be applied without that record.**
- A **calibration capture** is a recording of a little over three minutes of the power sampler while the machine runs 59 commanded one-second GPU load pulses. Its one number, **B** (seconds), is the largest timing uncertainty of any pulse edge plus the uncertainty of placing the capture on the wall clock.
- The **estimator** is the code that turns a capture's raw bytes into B; it lives in four files (`joulewise/powermetrics_fiducial.py`, `uncertainty_evidence.py`, `adapters/powermetrics.py`, `reduce.py`). Its search for pulse edges is limited to 165,000 evaluated regions (**cells**) per capture (**the cap**); a capture that needs more is stopped and yields no B.
- A **claim-bearing window** is a measurement session whose results may be reported as findings. **Arming** authorises a window to start. A **pack** is the frozen set of plans and pins such a window runs from. A **derivation night** is a window with no pack and no claim, whose captures exist to derive a calibration. A **hold** stops something until a named ruling lifts it.
- A **calibration file** holds the B values of its **members** (the captures the registration selected) and three numbers derived from them. The **drift** of a measurement is the change in B between the calibration captures just before and just after it. **S**, the spread of member B rounded to 1 µs, is the smallest drift allowance any measurement is charged (allowance = max(drift, S)). **C** is the largest drift that may be charged; above it the measurement is refused. Here C is the largest of R7's C, S, and t(0.995, n − 1) × s × √2 (Student's t quantile; s the members' sample standard deviation). The **level screen**, the largest member B, is the largest B a calibration capture at the start of a window may have; a larger one stops the window.
- The file is valid for one **epoch**: operating-system build, hardware model, power policy, sampling interval, estimator revision and pulse protocol. A measurement whose epoch differs in any field from the loaded file's epoch is refused as **stale** (`calibration_acceptance_bound_stale`).
- The **loader** (`load_calibration_acceptance_bound`, `joulewise/calibration_bracketing.py`) is the one function through which code reads a calibration file. It accepts a file only if the sha256 of its bytes equals a digest written in the code (a **pin**) and its content passes the **validator** (`_valid_acceptance_bound`), which checks the file's internal rules, among them that every valid capture of the registered sessions is a member or a **named exclusion** (a valid capture listed with a registered reason). The **default** is the file the loader reads when no file is named; no production caller names one, so the default judges every measurement. **Capture preflight** (the check a calibration capture makes before it records) and **bracket evaluation** (`evaluate_calibration_bracket`, which checks the captures before and after a measurement and either refuses or attaches its timing uncertainty) both read the file through the loader.
- A **candidate** is a file the preparation tool wrote, marked "not issued"; the loader refuses it. Each issued calibration file is a **generation** and names its predecessor; R7 is the seventh. **R7** (`d079_calibration_acceptance_v2_n17_r7`, 17 members, macOS build 25F84) is the default before and after this entry.
- The science gate attached **disclosures** D1–D8 (facts to be stated wherever the calibration is used), **holds** H1–H7 (conditions on later windows) and **bindings** B1–B4 (conditions on this transaction: B1 fixes the estimator files' digests, B2 forbids changing them, B3 forbids curing a failure by re-preparing the candidate, B4 makes any later cap change a re-issue).
- A **held file** is an issued calibration file listed in the code's hold table (`CLAIM_HELD_ACCEPTANCE_IDS` in `joulewise/calibration_bracketing.py`). A caller **states a non-claim purpose** by passing `allow_claim_held=True` to the loader.

The hold table is `CLAIM_HELD_ACCEPTANCE_IDS` in `joulewise/calibration_bracketing.py`; the module refuses to import if the default is in it. Route R re-sizes the cap by a rule written before the new value is computed, then shows in at least 24 captures of windows without a claim that none stops on it. Route M keeps the cap and measures, in a registered plan, whether abandoned and completed measurements differ in energy and frame length. That release is also the only change that can move the default to a 25G83 file.

The **doubling trigger** (bracket evaluation declares the file stale once the ledger's valid captures at its epoch reach twice its member count, here 24) no longer counts rows set aside by a decision the file declares. The fix lands in the same commit as items 4 and 5, because alone it would let the new file pass brackets as the default.
7. `claim_eligible: true` in the file means what design ruling §7.4 says: "these bytes are an authentic issued calibration, and its numbers may serve as the timing-uncertainty basis of a reported result. It is a property of the file. It is not permission to start a window. Permission to start a claim-bearing window is separate; H1 withholds it, and H5 to H7 condition it."

**Why.** The machine now runs macOS build 25G83. No calibration file covered that epoch, so every measurement at 25G83 is refused as stale when evaluated through the default. That is still so after this entry, because the default stays R7 while H1 holds. Two capture windows on 2026-09-27 (W1, W2; 24 captures, 12 members) produced the candidate, and the science gate and its three addenda cleared it. Issuing now registers the generation and exercises the loader repair and the promotion tool on real bytes; it does not make the file the machine's default. Issuing the candidate as it stood was impossible, because the validator refused it. The prior set holds eleven valid 25G83 rows of 2026-09-19 from sessions outside the registration (the sealed document, `configs/calibration/preregistration_d079_epoch_25g83_rev1.md`, that fixed before the captures which ones may become members), and those rows had been set aside by a written decision the validator did not know about. A worked instance: the prior set has 86 rows, 53 of them valid (30 of earlier epochs, the 12 members, the 11 set-aside rows). The validator used to refuse at the first set-aside row. It now skips the eleven and still requires the 12 valid W1/W2 rows to equal the members plus named exclusions (12 = 12 + 0).

**What this does not change.** The four estimator files and the cap: binding B1 fixes their digests (`386e8254…`, `b583f35a…`, `70f47086…`, `7b9c0d28…`; cap 165,000), and binding B2 forbids any change to them in this transaction. Also unchanged: the default (R7); R7 and the six older generations; the disposition file (`ba1ba3fc…`); the registration (`81b65f08…`); the ledger head pin (sequence 276); every existing pack.

**Options considered** (design ruling §3 and design addendum A1 §3.2).
- *Loader reads the disposition file at every load*, rejected. The issued file's bytes are already pinned, so a load-time read could add only one outcome: a correct file refused because the disposition file later gained rows for another epoch. A code table checked against the file was chosen instead.
- *Hand-edit the candidate, or re-prepare it*, rejected. Binding B3 forbids curing anything by re-preparation, the science rulings judged the bytes `dbad7cc7`, and a hand edit cannot be re-run. The promotion tool was chosen.
- *Keep `candidate_not_issued` set to false*, rejected for deleting the key: no issued file carries it.
- *Disclosures inside the `issuance` block*, rejected for `derivation_notes.issuance_record`: every issued file's `issuance` block has the same three keys, and code echoes that block.
- *Leave the pinset schema alone as a de-facto hold*, rejected: an identifier in no list has its S unchecked, which is the opposite of a hold.
- *H1 as a sentence only, or checked at the arm-time authorisation record*, rejected. A sentence is weakest at the moment of merge, and the authorisation record does not name the calibration file.
- *Move the default to the new file and hold only at the arm admission list* (the first design), rejected by design addendum A1. The admission list sees only the identifier a pack declares, but the default judges every measurement: at the first build, a window from a pack naming R7 and a manual campaign (no pack) were both judged by the held file, and only an unrelated counting defect (item 6) stopped a passing result.
- *Check the hold at every consumer with the default moved*, or *require every claim-bearing pack to declare the default*, rejected by addendum A1: both close the derivation night at 25G83, so non-claim captures, including those the cap question needs, would be screened by the held file's level screen; the second also leaves a manual campaign open. Keeping R7 as the default and gating the loader was chosen.

**Considerations.**
- *Hold cost.* H1 also stops a pack that names the new file for a rehearsal with no claim. Windows that run without a pack (derivation nights) are not affected, because the default stays R7 and the derivation night is the route for a machine whose epoch the default does not judge. The first design moved the default, which closed that route at 25G83; addendum D138-25G83-DESIGN-01-A1 reversed it for that reason.
- *What code does not close.* A measurement campaign started by hand at a 25G83 machine can still collect raw measurements, as on main. It cannot produce a result through the code routes tested, because a result needs a passed bracket and every ordinary capture at 25G83 refuses at preflight while the default is R7 (addendum A1 R-7). What is shown is only that no result can be produced through the code routes tested.
- *Doubling trigger.* The file goes stale when 12 further valid captures at 25G83 exist in the ledger. The eleven set-aside rows do not count; before addendum A1 they did, and the file would have gone stale at the first new capture.
- *Old-epoch results.* Because the default does not move, a recorded 25F84 measurement evaluated through the default gets the same answer as on main; design ruling §10 item 2 is met by identity, shown by re-running the old-epoch replay at main and at the head with byte-identical outputs (addendum A1 §6 item 1). On current main no recorded 25F84 analysis passes from recorded inputs: the calibration captures taken just before and just after the July 2026-07-29 measurement were entered into the ledger after the fact as historical imports, the current step that finds a measurement's before-and-after captures skips historical imports, and every later finalized bracket row is 25G83. The later transaction that moves the default must meet the restated condition of addendum A1 §6 item 3, including a route that names R7 explicitly for old-epoch results, with a test, before it merges. A separate tracked work item is to build that route.
- *Likely re-issue.* Issuing now registers the generation and exercises the loader repair and the promotion tool on real bytes. It does not make the file the machine's default. If the cap is re-sized (route R), binding B4 makes this file stale and forces a re-issue; the file that becomes the default at the hold's release will be a successor.
- *Network time.* The members were captured with network time ON (the macOS setting "set time automatically", under which the time daemon `timed` corrects the wall clock during captures; disclosure D8). H5 to H7 set it OFF for every later 25G83 window, attest every capture from the time daemon's log, and forbid pooling of ON-state and OFF-state members without a registered rule. Their enforcement must land before the next 25G83 window of any kind.

**Revisit triggers.** A written ruling that closes the cap question (H1 is then released by a reviewed change, which alone may move the default to a 25G83 file); any change to the four estimator files or the cap (B4: re-issue); the re-run old-epoch replay showing any difference between main and the head (the transaction then does not merge); a new disposition decision that disposes **any** row of this file's 86-row prior set, of either epoch. The file then stops loading. That failure is closed and is cured only by a re-issue.
