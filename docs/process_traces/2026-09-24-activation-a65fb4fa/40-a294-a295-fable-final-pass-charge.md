## What the change is (plain words)
A measurement night runs from a dedicated clone of the repository, the "measurement clone", pinned to one commit. When the night is armed, the arm check refuses a clone with edited or extra files. At t0, the planned start of measurement, the gate re-checked only the commit id. So a file edited or added after arming (for example an unlisted Python module that the night imports) would have run unnoticed. A294 makes the t0 gate (check row C5 in `joulewise/night_gate.py`) run `git -c core.fsmonitor=false -C <clone> --no-optional-locks status --porcelain=v1 --untracked-files=all` after the commit id matches. Any output refuses the night with the existing code `night_plan_stale`, whose operator description now names this cause. A failed or unrunnable status refuses with `night_probe_error`. The run is recorded as evidence. Two defects found in review are fixed with it. `git status` could run a configured fsmonitor hook, which could write to the clone or delay the check; it is now disabled. And a probe that timed out lost its partial output from the evidence, because it stayed as bytes (`scripts/run_night.py`). A295 is test-only: it commits a wrong measurement-window length (8999 s instead of the frozen 9000 s) into a scratch clone and proves the real prepare path refuses it. This is LIVE night-gating machinery: a false refusal would cost a measurement window; a false pass would let an unverified file run inside a night.
