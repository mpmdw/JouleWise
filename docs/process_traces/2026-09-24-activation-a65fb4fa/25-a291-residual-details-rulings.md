# 25 — A291 contract v3 (02c): magistrate rulings on residual details RD-1..RD-14

Magistrate: Opus 5.5, activation a65fb4fa. Each ruling below is REPRESENTATION: it fixes a wire format, a name, or a placement of a check, and it neither weakens nor reinterprets a ruled sentence. Where a ruling ADDS a check, the addition only strengthens. The cold Fable final pass on the A291 merge candidate reviews these rulings together with the code. These rulings bind the checker and implementer briefs alongside 02c.

- **RD-1.** An Event carries `envelope_index` (FT-8) and `block_ids`: the reporting envelope's `blocks` list in execution order at the call. This satisfies the list in 45/21 §7 (R) "(block id, observations, resulting sha256)" under FT-8's signature.
- **RD-2.** `Event.placements` is a list of integer indices into the roster's top-level `placements` list, in creation order. There are no embedded copies.
- **RD-3.** The roster keeps a top-level `placements` list, append-only, holding every placement ever made, pack-time included. Pack-time placements come first, ordered by envelope index ascending and then by position in that envelope's `blocks` list.
- **RD-4.** The PLANNED position of a parent at a `requeue_overrun` exit is the item-weighted mean of the envelope indices of the live (not voided, not terminal) placements holding its items, as 02b proposed. A parent with no live placement has no planned position and is excluded. The value is record-only (ruling 10 Q12: never refuses at requeue).
- **RD-5.** A "non-terminal parent" is a parent none of whose items has a terminal refusal. A parent "occupies" the envelopes of its and its singles' LIVE placements only; voided placements do not count.
- **RD-6.** `verify_executed_roster(registration, roster, predicted_decode_s)` keeps its ruled signature (Q16) and returns `None` or raises. A291 also ships a pure `executed_status(registration, roster, captured_window_keys)`. It calls `verify_executed_roster` first, then returns per-level `spread_exceeded`, the executed lever and `drift_exceeded`, computed as ruled. `captured_window_keys` is the set of `(block_id, attempt)` keys the reducer has windows for; A292 supplies it. Its witnesses carry the same PROVISIONAL status as the reduce column (Q16).
- **RD-7.** FT-13's `unreported_envelope` is enforced inside `verify_executed_roster` (A291), because it is a property of the roster.
- **RD-8.** A `requeue_overrun` call whose decisions are all `keep` gets a SUPPLEMENTARY witness column, `requeue_all_keep`, in addition to the thirteen ruled paths. Every invariant row has an executed violating witness there too. This strengthens (G) and does not alter its closed list.
- **RD-9.** The decision vocabulary is exactly `{keep, advance, split, reschedule, unattributed_overrun}`. The edge `single_retry → ceiling_violation` is decision `advance`, and its terminal refusal has type `ceiling_violation`. No `ceiling_violation` decision exists.
- **RD-10.** Every seal or checker refusal carries a typed code. Where a ruling names one, it is used (for example `report_order`, `invalid_elapsed`, `unattributed_overrun`, `item_ids_by_level_keys`, `unequal_level_sizes`, `unselected_arm_entry`, `unreported_envelope`). Otherwise the code is the invariant id in lower case (`inv_17`, …). FT-2's per-event count (INV-35(c)) is a seal refusal with code `inv_35c`.
- **RD-11.** `envelope.observations` records carry `decision`, as 45/21 A1 says: "observations are recorded so the seal and checker re-derive the decision". Replay strips it per FT-8 and compares.
- **RD-12.** A checker `Violation` carries `inv_id` and the refusal `code` from RD-10.
- **RD-13.** `Registration.from_mapping` refuses any model id containing `:` (code `model_id_separator`). This narrows input to keep ids unambiguous; it does not change any ruled semantics.
- **RD-14.** A block that ends in `unattributed_overrun` keeps its last `retry_stage` unchanged. Its terminal state is represented only by its items' `terminal_refusals` entries. Stage legality treats a terminal refusal as the end of the block's history.
