## 3. Mismatches and points flagged for the magistrate (not silently fixed)

1. **QPE01-NONOBSERVER-PREDICATE-01 is not a kernel task** (absent from `state_kernel.json` on main and on the
   v3 branch). "Priority just below" it was therefore read as: same priority `p1_phase_gate` (synthesis 15 calls
   that lane p1) with the next rank, 270. If you meant the next priority tier down, change `priority` to
   `p2_next_slice`; nothing else moves.
2. **The v3 branch contradicts the addendum.** `joulewise/arm_retry.py:55` on
   `origin/feat/2026-09-23-qpe01-registration-v3-nonobserver` says "D-182's zero-capture successor route does NOT
   apply and no successor is arranged". That was right before Ed's 01:06 reply. The A270 acceptance names the
   sentence for replacement; if the v3 PR is still open, you may prefer to fix it there before merge.
3. **"Captured" versus "retained".** The rule counts envelopes *captured*, and `minimum_retained` is a threshold
   on envelopes *retained* (kept after exclusions). Read literally, an abort after 9 or more captured envelopes
   licenses no successor even if fewer than 8 survive exclusion. The addendum states the literal reading
   (captured = capture ran, excluded or not) and its counter-case; it does not reinterpret.
4. **The Q1 label is night-specific.** Ruling 10's label text names `fseventsd` pid 341 and the 2026-09-22
   numbers. How it is restated for a later aborted night is not ruled; the addendum says so and points here.
   A270's acceptance asks only that the harvest record carry the Q1 label.
5. **"Same terms" imports two D-182 conditions the parenthetical omits**: the courier has delivered
   (`courier.sent`), and the aborted plan is never re-armed. The Terms paragraph lists D-182's full set,
   which is what "the same terms as a zero-capture refusal" says.
6. **Kernel `updated` left at `2026-09-22`.** `scripts/gen_state.py` prints that date in `RUN_STATE.md`'s
   generated region too, and `RUN_STATE.md` is outside this seat's write scope; raising it would make
   `--check` report drift there. Raise it (and regenerate) in the next bookkeeping commit that may touch
   `RUN_STATE.md`.
7. **`tests/test_gen_state.py` fails (1 of 75) and is outside write scope.** `test_exact_live_id_set` pins the
   live task-ID set and its count (226). Needed edit (both exist in `EXPECTED_IDS` style at lines 30–33 and
   862): add `"QPE01-ABORT-SUCCESSOR-01"` and `"FSEVENTSD-CORECAPTURED-PREDICATE-01"` to `EXPECTED_IDS`
