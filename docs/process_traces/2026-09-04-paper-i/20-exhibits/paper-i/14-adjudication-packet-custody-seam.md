### F2 — should-fix — magistrate decisions and ruling-ready disposition

#### C. Decision questions

**Q-C-1 — What is the public API shape?** Sol: one overloaded family-ref dispatcher. Opus: a role-driven reader/session with generic artifact/row/member/derive methods. Fable: public low-level bound readers plus five explicit openers. **Recommendation:** adopt Sol's closed dispatcher as `joulewise.paper_custody.open_paper_input(ref)` with five closed ref variants; keep all raw readers, role dispatch, parsing, and constructors private. This gives one non-bypassable seam without stringly typed roles.

**Q-C-2 — What makes a path/digest binding authoritative?** Sol: a producer-owned receipt independently pinned at handoff. Opus: a clean Git supply map, then authenticated traversal. Fable: clean Git bytes for governed files and owning validators for run files. **Recommendation:** adopt a two-root rule: clean `git:HEAD` blobs authorize governed files; generated files are authorized only through a producer-issued receipt whose digest is reached from a registered custody inventory. A caller's path/digest pair is never an authority, even when it matches disk.

**Q-C-3 — Are validator receipts inputs, outputs, or both?** Sol: mandatory input and corroboration. Opus: optional corroboration, never authority. Fable: output only. **Recommendation:** production refs must include a receipt binding because the charge requires validator receipts in, but the receipt is only one conjunct: independent anchor, fresh replay, and byte-exact receipt/replay agreement are all required. The verified result may return the replay census; no bare `PASS` is a capability.

**Q-C-4 — Can whole-window stop issuance proceed without `WHOLE-WINDOW-STOP-RECEIPT-01`?** Sol/Opus: no. Fable: yes, export `_validate_row` with status. **Recommendation:** no. Refactor the validator to a typed authenticity/admission result, then issue a governed receipt from it; until then the seam returns `paper_custody_receipt_unissued`.

**Q-C-5 — What crosses the seam?** Sol/Fable: `Verified[T]`; Opus: generic `Custodied[T]` mappings. **Recommendation:** five concrete frozen result types with private constructors and one immutable evidence census; ban generic containers, bytes, and prevalidated objects.

**Q-C-6 — Which refusal vocabulary governs?** The seats propose three overlapping enums. **Recommendation:** adopt the `paper_custody_*` namespace below; carry `input_role`, D-123's artifact/cell/token `scope`, and nested validator codes as non-renderable diagnostics. Exact codes, never exception text, cross the boundary.

**Q-C-7 — What is the one class-ending test?** Sol: five-family table; Opus: session-record census; Fable: full reseal plus no-output. **Recommendation:** auto-census three arms per input—raw mutation, full caller reseal under unchanged anchor, and replay/reopen replacement—with exact code and zero output.

**Q-C-8 — How broad is the landing repair?** Sol centers the four suppliers; Opus also closes the lower `load_floor_artifact` and `raw_bytes` bypasses; Fable adds authentication-surface and signature guards. **Recommendation:** include the two lower bypass closures and both static guards in the same contract landing; otherwise a supplier can route around the seam while satisfying its nominal signature.

**Q-C-9 — Is a decision-log entry required?** All seats say yes; Opus and Fable propose D-173. **Recommendation:** yes. D-173 is unallocated at this head (the log ends at D-172); it should amend 07/09 on receipt authority, clarify 08/10, and name `docs/contracts/paper_supply_custody.md` as the one normative home.

#### D. Ruling-ready text

If the recommendations above are adopted, the magistrate can install the following text substantially verbatim.

1. **One seam.** `joulewise.paper_custody` is the sole ingress for any claim-bearing or professor-facing value consumed by the D-123, gamma, transfer, or D-165 suppliers.
