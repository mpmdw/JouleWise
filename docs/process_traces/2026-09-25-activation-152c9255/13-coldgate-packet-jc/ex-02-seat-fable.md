## J1 — Choice: (c), minted on (a)'s workload; the correct count is an identity check, not a noise term

**Disagreement with the framing (MATERIAL).** The worked number ("±1 correct moves J/correct ±17 %") treats the correct count as something the instrument produces. Under the ruled design it is not. Every MATH cell decodes with one pinned seed and pinned sampler parameters and must reproduce token IDs and bytes (`01-ap5m-draft-v5.md:37`); the quiet rerun must byte-match the accuracy-run trace or the cell is withheld (`:47`); the scorer is pinned and deterministic (`:23`). So in a null ABBA block (same model, same budget, same problems, same seed) the A and B members carry the *same* bytes and the *same* correct count. The count's variance in a null is zero **by construction**, and that is the correct answer, not an understatement: the floor is the instrument's no-difference spread (CG-1 (3)); the sampling uncertainty of accuracy over problems is carried by the bootstrap interval and Holm (CG-1 (1)–(2), `01-ap5m-draft-v5.md:61,67`). A floor that randomised the count would import an n = 10 sampling error (SE/p = 0.26 at p = 0.6) into a gate applied to an n = 128 estimate (SE/p = 0.072): a floor ≈3.6× too large in that component, hiding real effects. Option (b) is not needed: nothing in the science requires abandoning J/correct.

**The unit.** The registered confirmatory contrast is already dimensionless: Δ_L = log R_L(b_high) − log R_L(b_low) with R_L = C_8B/C_1.7B and C = e/p (`01-ap5m-draft-v5.md:57,65`). Since log C = log e − log p and p is fixed by the bytes, p cancels identically in any null. The matched floor therefore lives in log-energy units and no rule ever divides joules by a count; WR-9's prohibition (`21-coldgate-fable-cgw-addendum-ruling.md:81`) is honoured, and open item Q3-7b (`03-open-questions.md`, row Q3-7b) closes: F applies to Δ_L itself, no scale conversion.

**Executable derivation rule "cg1_f_est_log.v1".**
1. Unit: `log_ratio` (natural log of gross joules). Add it to the F_est `unit` enum beside `J`; WR-3's `floor_unit == metric.unit` check then binds on `log_ratio`.
2. Null block: A1 B1 B2 A2, each member = the same s problems (s registered; assumed s = 1), same model artifact(s), same budget b_null, same seed, same prompt bytes. b_null = the registered b_high of the frozen pair (the longer arm; errs conservative for b_low cells). Problems come from the disjoint 16-problem pilot set (`01-ap5m-draft-v5.md:29`), so no test outcome is seen during calibration.
3. Block delta: δ = (ln E_B1 + ln E_B2 − ln E_A1 − ln E_A2)/2, E = gross member joules on the registered rails. This is `abba_delta` (`detection_floor.py:1449-1453`) applied to logs; the mint records the joule members too (`_OBS_KEYS`, `:2106`) so a J floor of the same window class exists for any J/attempt secondary.
4. Identity witness: each member records token count, output bytes sha256 and correct count. Any member differing from its block-mates in bytes or count ⇒ block refused `estimate_floor_members_not_byte_identical`; the refusal count is printed and feeds the byte-match ceiling (`:47`). The count is recorded, never used arithmetically.
5. Envelope mean = fsum(δ)/n_cal, n_cal = 10 (forced by v3 `:2300`, ruling C-5 at `:45`); an envelope with fewer retained blocks is excluded and listed.
6. F_est,log = g(k_cal)·(|mean_cal| + t_{0.975,k_cal−1}·s_cal/√k_cal), CG-1 verbatim (`91-claimgate-final-texts-v2.md:3`), g from `detection_floor.py:846-855` (g = 1.5 at k_cal = 5, 1 at ≥ 10). k_cal ≥ 5; register k_cal = 5 as the minimum; see the power note for why 10 is cheap insurance only for J-unit claims.
7. Claim gate: `direction_supported` iff CG-1 (1)–(2) hold on Δ̂_L (paired bootstrap over problems, energy in envelope clusters) AND |Δ̂_L| > F_est,log strictly. Registration carries `estimate_floor{artifact_id, sha256, floor_est, floor_unit:"log_ratio"}` per WR-3.
8. Which way it errs: small only if the stack is not byte-reproducible (then rule 4 fires before any claim window); large by the b_high choice; both disclosed.

## J2 — Seeds: "same model, same seed" IS the null; null blocks must not vary seeds

A null means: identical bytes in and out (model artifact, prompt, seed, sampler parameters, budget, forced-close rule), so the only thing that can differ between A and B is the instrument and the machine's state. Varying the seed across arms makes the arms different workloads (different token counts, different durations), so the null no longer measures "nothing differs": it would fold decode-length variance into a floor applied to a claim whose arms all run at one pinned seed (`01-ap5m-draft-v5.md:37`). The claim never experiences seed variation; its floor must not either. Seed sensitivity is a real scientific limitation, but of the *estimate*, not of the *instrument*: register a descriptive secondary (assumed: 3 extra seeds on the pilot's 16 problems, off-window, accuracy only) and word the claim "at the registered seed". Two facts the council must not skip: the runtime at HEAD is greedy at temperature 0 (`mlx_runtime.py:984-988`), the model-card sampler (0.6/0.95/20, `19-headline-integration-synthesis.md:29`) is lane A283, not landed; and whether seeded MLX sampling reproduces tokens on Metal is untested (`18-headline-opus-integration.md:49`). Rule 4 of J1 makes the null calibration double as that determinism witness. Executable: null blocks use the registered seed in all four members; a seed-varying null is refused `estimate_floor_cell_not_null`; the calibration report prints the byte-identity refusal rate; if it exceeds the registered ceiling the epoch has no J/correct floor and no claim window is armed.

## J3 — Cross-model contrast: the null of the contrast's own block, both models named

Physical reason: the instrument's null spread for a block is set by that block's power-time profile: anchor error ≈ ΔP at each edge × the operative bound, drift and thermal state ∝ duration, and the 8B runs ≈ 4× the joules per token (0.375 vs 0.092 J/token, planning stand-ins `research_question_bank.md:1615-1616`) over longer blocks. A contrast's null error is the union of the errors of every member that enters it. "The larger of the two same-model floors" is right only if the two models' errors were perfectly correlated (they are in different windows, so they are not); "pooled" (averaged) understates; either single model is wrong by up to √2.

Preferred (needs A291 v5 to allow both models loaded in one envelope; 0.94 + 4.3 GB of weights fits): the claim block is the four-cell block [1.7B: b_low, b_high; 8B: b_low, b_high] on one problem sub-block, δ_claim = (ln E_8B,hi − ln E_8B,lo) − (ln E_1.7B,hi − ln E_1.7B,lo); the null block is the same with b_low := b_high in every cell. Then the mint produces F_est,log for Δ_L directly, the calibration artifact records both model hashes (`model_artifact_sha256` becomes a two-entry map matching `condition_model_artifact_sha256s{a,b}` of WR-3), and N-6's `floor_est_model_rule_unruled` lifts iff the artifact's model set equals the contrast's model set.
Fallback if one loaded model per envelope stays (`01-ap5m-draft-v5.md:53`): Δ_L = D_8B − D_1.7B, each D_m a within-model budget ABBA estimated on its own k ≥ 5 envelopes; SE² = SE_8B² + SE_1.7B² (Welch df); F_Δ = F_8B + F_1.7B, two calibration artifacts, both named. Linear sum errs large by ≤ √2, immaterial at a floor ten times below the interval half-width. Executable: registration names every model artifact that enters the contrast; a floor whose model set is a strict subset refuses `estimate_floor_model_mismatch`.

## J4 — Scheduling

The ruled order is PR-L → #410 → PR-R → W1 → W2 → derivation → cold gate → successor → G2-a → calibration night (`21-coldgate-fable-acc2-addendum-ruling.md:81`; R-ORDER `20-coldgate-fable-council-ruling.md:54`), and the data side of the claim gate is acceptance → ≥ 5 J-null windows → mint → pin → this council → freeze → claim windows (`…cgw-addendum-ruling.md:83`). The J/correct nulls are a separate window class and cannot be folded into claim windows (WR-2 (v) disjointness, `:67`). They need: A283 landed, the pilot's pair (b_low, b_high) and byte-identity proof, and the frozen s. So they sit after the MATH pilot (night 3 candidate, R-ORDER (3)) and before the first MATH claim envelope.
Added quiet windows before the first claim-bearing MATH number: **5 envelopes** (two-model block) or **10** (fallback). Length per envelope: 10 blocks × 4 members × s × t_attempt; assumed 8B at b_high = 4k thinking + 256 answer ≈ 4.3k tokens at 49 tok/s ≈ 90 s, s = 1 ⇒ block ≈ 6 min, envelope ≈ 1 h; the 600 s `_v5` slot cannot hold an n_reg = 10 MATH envelope, so A291 v5 must define a ≥ 1 h MATH window class (MATERIAL). At the mechanism ceiling of 4–5 quiet windows per day this is one to two days of calibration. The dominant cost is not the calibration but the claim envelopes: k = 5 one-hour envelopes per level ⇒ ≈ 25 h of quiet capture for five levels; state that in the registration so nobody counts the floor as the bottleneck. Executable: the AP-5M v5 registration freezes only after the J/correct calibration artifact is pinned; calibration windows carry `window_class = math_scored_abba_v5` and are refused as claim envelopes by id.

## J5 — What would show this wrong, and which step detects it

1. Byte-identity failure inside null blocks above the registered ceiling ⇒ correctness IS partly stack noise; then a random-count floor (option (a) as framed) becomes necessary or the stack is fixed. Detected by J1 rule 4 at the calibration mint, before any claim window.
2. F_est,log ≥ 0.1 (assumed threshold; drift over minute-long blocks far above the 512-token experience) ⇒ the floor binds and Sim B's power is wrong. Detected by CG-4(e)'s re-simulation with the minted value, run before freeze; the registration cannot freeze until the desk power at the registered n is recomputed and committed.
3. |mean_cal| non-zero with the same sign in ≥ 4 of 5 envelopes ⇒ position (A-before-B) effect; ABBA/BAAB alternation per R-Q4(b) (`20-coldgate-fable-council-ruling.md:36`) must enter the MATH registration. Detected by the printed sign-flip diagnostic on the calibration envelopes.
4. Accuracy-run vs quiet-rerun byte mismatch above the ceiling in a claim cell ⇒ e and p come from different token sequences and C = e/p is incoherent. Detected by the per-cell ceiling check (`01-ap5m-draft-v5.md:47`), which withholds the cell.
5. Two-model blocks change the thermal profile relative to one-model claim envelopes (if the contract ends up mixed) ⇒ floor unmatched. Detected by `window_class` equality between calibration artifact and claim manifests; mismatch refuses `floor_class_mismatch`.

## Where I expect the other seats to be wrong

- Treating the correct count as instrument noise and building an (a)-style random-count floor: it imports n = 10 sampling error into an n = 128 estimate, ≈3.6× too large.
- Varying seeds across null arms "to capture correctness noise": that breaks "nothing differs" and measures workload variance, not the instrument.
- Answering J3 with "the larger of the two same-model floors": understates by up to √2; only the null of the contrast's own block shape is matched.
- Reusing the 512-token P2-015 J floor with any conversion: wrong window class; minute-long MATH blocks have unmeasured drift.
- Counting calibration windows as the schedule cost: the binding costs are the ≥ 1 h claim envelopes forced by n_reg = 10, and n = 128 vs 200, which sets power; the floor sets none of it.

## Plain summary for Ed

The energy-per-correct-answer headline needs a "noise floor": the smallest difference the power meter shows when nothing has changed. The worry was that the correct-answer count adds its own randomness to that floor. It does not: every run uses one fixed random seed and must reproduce the same output bytes, so a repeat of the same problems gives the same count. The count's genuine uncertainty comes from how many problems we test, and the statistics already handle that. So the floor is measured in energy on the real math workload, expressed as a percentage change, and never divided by a count. For the small-versus-large model comparison the floor is measured on a block that contains both models, so both are named. This adds about one day of quiet measurement; the real schedule cost is the claim windows themselves, and testing 200 problems per level instead of 128 buys more certainty than any floor choice.
