## A finding that changes the risk picture (Opus Q5.2, bench-verified by the magistrate)

`evidence_night.retained_roots` (`joulewise/evidence_night.py:723-760`) classifies an earlier plan as "retained" (armable-past) once `scripts/magistrate_watchdog.plan_span_active` returns False. Since PR #393, that happens as soon as the zero-capture release latches (`magistrate_watchdog.py:931-933`, read at 313efcca this session). **A successor can therefore already pass `check` today, with no one-successor bound and no 60 s spacing from the predecessor's `result.ended_epoch_s`.** Nothing in production writes or reads a successor count. The defect is too permissive, not only too strict. What contains it today is procedural: every arm goes through the NIGHT_HANDBACK email-then-arm procedure and a cold Fable arm verdict. **Until A277 lands, any arm that follows a released refusal must be hand-checked against D-182's existing terms:** exactly one successor per predecessor; at least 60 s after the predecessor's terminal write; a fresh plan id and notice; every observed NO stops it. This applies an existing rule by hand. It is not a new rule.

## Where they differ, and the decision

- **Where enforcement sits.** Opus: a new `successor` row in `evidence_night.check`, plus a create-once (`O_EXCL`) claim file written by `publish_install` outside the predecessor's custody (`~/night-custody/successor-claims/<predecessor plan_id>.json`), so the count survives custody removal and cannot be forged by omitting a flag. Sol: also enforce inside `night_agent_install.validate_install`, because the runbook permits a direct `install_night_agent.sh` install, which bypasses `check`. **Decision:** take Opus's shape for this lane. `check` detects a successor by scanning the retained plans, not from a caller flag, so the evidence-night route cannot disguise a successor as a first arm. The direct-installer route bypasses every `check` row, not just this one; that is a general property of the route, not A277's defect. It goes to a follow-up lane (to be registered at bookkeeping) together with Opus's derivation-route note. Sol's point is recorded as a partial dissent.
- **Facts record.** Adopt Opus's typed record with counts (not a bool), so A270 can read `envelopes_captured` without redefining any fact.
- **"No ledger session" (D-182 term; Opus Q5.4).** No disk fact covers it today; `*.consumed.json` stands in for it. The implementation seat must find where a calibration chain opens its ledger session and whether the reservation marker is always written first. If it is, the marker suffices and the seat cites the lines. If not, the seat adds the ledger check or early-returns NEEDS_RULING.
- **The old functions.** `zero_capture_successor_allowed` loses its C5-block requirement and becomes, or delegates to, the pure door-1 predicate over the facts record. `successor_arm_allowed` either becomes a thin adapter or is removed; the seat decides and justifies. `ZeroCaptureSuccessorTests` is rewritten deliberately, not deleted.
