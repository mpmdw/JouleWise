# Synthetic r2 acceptance evidence

This directory records repository-generated S10 fixtures only. It contains no
study custody or real measurement values. The driver runs from a detached
worktree of `b5/analysis-r2`; neither recompute script imports driver code.

`synthetic_run.py` is the exact scratch script executed in this session. It
uses the existing S10 `chain_fixture()` and `JoinedHarness.git_seams()`:

- Hardware/collection bytes were generated by the repository's synthetic
  fixture builders at their governed harvest pins, and are restored and
  relocated into task scratch. No old absolute archive locator is followed.
- The joined harness provides a temporary Git input repository, checkout
  identity observations, and registered-history lookup against the r2 tree.
  Thus `analysis_commit` in the synthetic record is the harness Git anchor;
  the executing analysis source is the separately recorded r2 commit/tree.
- All registered driver steps use r2 functions, serially (`workers=1`).
  There is no arithmetic, deadline, selection or refusal override. A
  read-only CPython return observer writes progress, and existing helpers
  capture public streams. The final fresh run explicitly sets VDL `on`;
  synthetic defects still raise, whereas a real blind run uses its own
  fallback policy. This is not a live-run timing benchmark.
- Independent recompute and comparison then run as separate Python processes
  on these same synthetic archives and the exact index bytes. The current
  comparator uses the default block-5 release bars.

The task's explicit synthetic-only exception covers the generated custody's
conventional `restricted` subtree. It does not grant access to any study
directory with that name. All generated input and output locators remain
inside this clone. The final invocation's TMPDIR is the worktree's
`.scratch-s10f/tmp/readiness-on`; the fixture cache, analysis custody and
subprocess outputs are all below that TMPDIR.
