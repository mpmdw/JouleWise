# COLD-INSTANCE RULING — D100-BII-BINDING-01 clause 3(c) nested-content closure (second same-signature failure)

**RULING SUMMARY.** The structural diagnosis holds: both failed formulations enumerate the *forbidden complement* of an open set and default-license everything else, which is the logical negation of "unclassifiable ⇒ void" — the second failure (unknown keys, confusable spellings, unknown scalars, workload-bearing values all LICENSED, which I re-verified cold against the live diff) is the necessary consequence of that polarity, not an implementation miss. The fix shape is C-C understood as C-A's closed admission grammar as the core — writer-set equality per D-097's ratified pattern — with a D-105 documented-decidable-superset only for leaves producer tracing proves genuinely open (my own producer probe shows `failure_reason` is enum-valued by construction, so less superset is needed than the packet feared). The kernel fence does not bar this: it forbids schema formulations offered *as capture-identity bindings*; a content-admission grammar binds what may be present, not which occurrence produced it, and its polarity (closed admitted set, default-void) is different in kind from both failed enumerations. F2 lands in the same commit with bound-and-refuse semantics (structurally non-recursive or depth-capped traversal; exceeding the bound is `SalvageAuthorizationError`, never `RecursionError`, never truncate-then-license). The fix proceeds as gate-licensed round 2 in the same commit arc — one commit plus a *fresh* focused re-audit against the acceptance predicate below — with two hard return-conditions to the decision level.

## 1. The structural diagnosis HOLDS

Formulation 1 allowlisted container *positions* and classified nothing beneath them; formulation 2 recursed but classified only against a key denylist (`lower()`-normalized spellings) and never classified values, unknown keys, or unknown scalars. I re-ran the delta audit's V4 probe against the live worktree diff (`/private/tmp/claude-501/-Users-edr-code-JouleWise/c701f4e3-95c0-4f1b-a387-854cf845264f/scratchpad/d100bii/joulewise/salvage_dangler.py`): all four shapes — workload bytes in `environment_admission.failure`, the fullwidth `ｍｏｄｅｌ＿ｏｕｔｐｕｔ` key, unknown empty-mapping child, unknown scalar child — print LICENSED. That is not a missed call site: `_mapping_field_is_workload_evidence` is reached for every one of these and returns False *correctly under its own contract*, because none of them is in the enumerated forbidden set. The predicate "unclassifiable ⇒ void" quantifies over the complement of a closed admissible set; a denylist quantifies over an enumerable subset of an *open* forbidden set (all possible spellings and carriers of workload evidence) and licenses the remainder. No enumeration of an open complement can converge — the same impossibility structure as D-097 ("with no writer emitting the enum every in-manifest marker is self-asserted — no third in-manifest formulation exists") and D-105 (exactness undecidable at sane cost). The admissible set, by contrast, is closed and small: it is exactly what the in-repo producers emit. Two rounds failed because they enumerated the wrong side of the predicate; a third enumeration of that side (C-B) would fail the same way, and the standing trigger correctly identifies this as structural.

## 2. Fix shape: adopt C-C — C-A closed admission grammar as core, D-105 superset only where producer tracing proves a leaf open; C-B is REJECTED

Metadata and event metadata validate against a closed grammar derived from producer emissions: exact admitted key set per container at every depth; explicit type/value constraint per admitted leaf; the six producer-owned `extra` scalars as already landed; no nested container beyond what the grammar admits; **anything outside the grammar voids**. The event-metadata validator already has the correct shape for keys (`set(metadata).issubset(allowed)` per event identity, no nested containers) — the round-2 work extends that polarity to the metadata mapping contents and to leaf *values*. Value constraints use writer-set equality wherever the writer emits a closed set — and my producer probe found `controller.py` emits `failure_reason` as `FailureReason.<enum>.value` (lines 1411, 1449, 1498), i.e. a closed enum, so the packet's hardest value case closes exactly. Only where a full producer trace shows a leaf genuinely open (e.g. version strings, admission observation text — *if any*) does D-105's pattern apply: an anchored, documented decidable superset with its residual recorded, never claimed exactness. The workload-evidence spelling list may remain as defense-in-depth but must carry no load.

## 3. The kernel fence does not constrain this shape — distinction on the record

The fence (`docs/process/state_kernel.json`, D100-BII-BINDING-01) reads: schema formulations may never bind **capture identity**, "telemetry rows carry no identity by construction; no third schema-shaped formulation may be proposed." Its grounds (D-106 grounds clause 4) are specific: one code path emits identical rows for measured and idle captures, so no per-file schema can distinguish *which occurrence* a file came from. That impossibility is about identity, and it is real — and it is untouched here: identity remains bound solely by interval containment and digest freeze, byte-identical per P6. Nested-content closure answers a different question — *is this content admission-shaped at all* — and that question is precisely what a writer-derived grammar CAN decide, because the producers are in-repo and their emitted set is closed. D-106 clause 3(c) itself orders a nested-content closure whose acceptance text is "unclassifiable means void," which is inherently an admission-grammar predicate. **Recorded distinction:** the fence bars schema-shaped formulations *offered as identity bindings*; the ruled shape is a content classifier whose soundness does not depend on rows carrying identity. And against the "isn't a grammar just a third enumeration?" reading: the trigger requires the fix be different *in kind* from the two failures — both failures enumerated the open forbidden complement with default-license; the grammar enumerates the closed admitted writer set with default-void. Inverted polarity over a closed set is the D-097-ratified pattern ("the reader's accepted set exactly equals the writer's emitted set"), not a third instance of the failed class.

## 4. F2: in-commit, bound-and-refuse

F2 lands in the same commit — the RecursionError escape is a refusal-contract bypass on the identical surface, and D-106 clause 3 specifies one commit for the closure. Exact semantics: the traversal must be structurally incapable of raising `RecursionError` — either iterative (explicit work stack) or carrying an explicit depth cap set to a small constant strictly greater than the grammar's maximum admitted depth. Exceeding the cap is *unclassifiable* and raises `SalvageAuthorizationError` naming the depth bound — refuse, never truncate-and-continue, never license anything at or beyond the bound, and do **not** catch `RecursionError` as a conversion (masking a crash into a refusal is the wrong mechanism; the mechanism is that unbounded recursion cannot occur). Under the closed grammar the 995-deep chain voids at its first unadmitted key anyway; the bound is defense-in-depth so that no input shape can crash the inspector before classification. The V5 probe becomes a permanent regression expecting `SalvageAuthorizationError`.
