## 2. The length read

A run's target-phase length is the end stamp minus the start stamp of that phase's `phase_start` / `phase_end`
events (`timestamp_s`) in its `events.jsonl`. That is the window the phase energy is integrated over
(`joulewise/bundle_read.py` `phase_windows`, used by `joulewise/reduce.py` for `phase_energy_j`), so P_x × T_phase is
the energy a contender adds over the same window. Prefill-p2048 runs: phase `prefill`; decode runs: phase `decode`.
Each run has exactly one start and one end event for its target phase.

The length is the exact decimal difference of the two stamp texts. The reducer's double-precision difference is
within 1.3e-7 s of it on all eight runs (one double ulp at 1.79e9 s is 2.4e-7 s).

Not used: `decode_latency_s` (last token stamp minus first) and time to first token, which the quiet kit's M15
read; they sit a few ms inside the phase window (ALPHA decode 1.99164 s against 1.99578 s).

## 4. Decisions I made

1. **The length is the phase window** of §2, not the token-stamp latency: it is the window the reported energy
   covers, and the window E_add is charged against.
2. **GAMMA takes the longest of its smoke runs per phase (the 8B run).** The registered grain is per pack and phase
   in all four places that state it (§8.5 row, S-9, S-11, D23), and "the longest, if they differ" then picks the 8B
   run. For GAMMA's 1.7B runs this line is 3.3 (decode) to 4.3 (prefill) times stricter than their own length would
   give. The per-model values are printed beside; on replay both readings remove 0 runs, so the choice changes no
   count. The refuter reached the same reading independently.
3. **P_x for the replay** is the time-weighted mean of `processor.gpu_power` plus `processor.ane_power` (mW, to W)
   over the records of the run's `raw/powermetrics_idle.plist` (`.zst` in the session archives): the admitted idle
   baseline. "Mean" follows §8.3 item 3 ("largest baseline mean 1.35 mW"). For runs with two admission attempts this
   file is byte-identical to the admitted attempt's file (checked on r1-beta `d117fq38-df-cmp-abba-ph-prefill-p2048-b07-a1`:
   attempt 1 not admitted, attempt 2 admitted, `powermetrics_idle.plist` equals attempt 2). The reading is
   bit-identical (difference 0.0 W) to the powermetrics adapter's `gpu_power` + `ane_power` rails
   (`parse_powermetrics_records` at the measurement checkout) on all eight smoke runs.
4. **Scope of the line:** every science run (decode and prefill-p2048, repeats and quads). Reference runs
   (`neg8-window-*`, GAMMA's interior references) have no pack target phase and are outside it.
5. **Printed precision:** T_phase as the stamps' difference; P* to 1e-6 W, the agreement bar below.
