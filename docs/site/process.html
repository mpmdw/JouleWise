The orchestration · one researcher, several models, everything written down

The process is a second
instrument — and it's audited too.

JouleWise is built by a human researcher directing a multi-model AI system whose workflow is itself deliberate, versioned, and self-instrumenting. Every review layer's catches are counted; layers that stop earning their keep are dropped by their own evidence rule. The point of the machinery is narrow: protect measurement claims from unchecked summaries, stale assumptions, and review-induced drift. This page is the tour — the full document and the primary sources carry the detail.

The cast

Three tiers, different eyes.

The researcher

Ed — direction & policy

Research direction, the methodology non-negotiables (raw evidence, idle subtraction, named boundaries, no unauditable claims), hardware decisions — and every process rule below, each issued as a standing instruction after an observed failure or opportunity.

The lead · Claude

Orchestration & final say

Decomposes work, adjudicates design, triages every review finding, runs every live-hardware gate, decides merges, keeps the books. Never writes the implementation — and never skips a gate. All escalation paths terminate here.

The volume · OpenAI Codex

Implementation & adversarial review

An independent second model does the heavy writing: implementation against pinned specs, fresh-instance review lenses, test writing, test auditing (never its own), and review of the lead's own consequential decisions. Different models catch different classes of defect — the attributed record shows it.

The loop

Nine steps, every session.

Intake

Read the run state, the ranked queue, the last session's report. Never re-decide what the decision log settled.

Decompose

Split into genuinely independent streams — one git worktree each — and assign each a review tier by cost of being wrong. Hardware claims need a confirmed device list; unverified contracts are stamped PROVISIONAL; measurement needs a quiet machine.

Design argument

The implementer must argue the trade-offs before coding — invited design judgment has repeatedly beaten the lead's own first proposals.

Implement + counterreview

Fresh-instance review lenses over every diff (they share no state with the writer), findings triaged by the lead with recorded dispositions, fixes applied and re-verified.

Test the tests

A dedicated amplification round writes the edge cases the implementer missed; then a writer≠reviewer audit hunts tautological, vacuous, and wrong-expectation tests.

Live gates — never delegated

The lead runs the real flow: real corpus, real CLI, real hardware. This layer keeps catching blockers whose own tests were green — because the tests encoded the same wrong assumption as the code.

Merge gate

Fresh oversight reviewers with distinct angles, then the final-head rule: any commit landing after the last review round gets one more fresh review. Its first application caught a crash path in a "trivial" late fix.

Integration review

After parallel streams merge, one review hunts the interaction defects no single-stream review can see. Its catches are definitionally unique.

Book, distill, meta-review

One session record with a verbatim process trace; a delegated consistency sweep before the final commit; lessons folded into the playbooks the same session; and when the evidence says a layer or a topology is wrong, the loop reviews itself.

Self-correction

The loop redesigned itself — with evidence.

v1 · Jul 7 AM

Per-stream lead-model orchestrators

Five parallel streams, five orchestrating subagents. Worked — expensively.

v2 · Jul 7 PM

Mid-tier directors

Cheaper directors drive the volume model; the lead goes apex-only. The session's own trace caught the flaw: directors stall at every round boundary (the "wake gap") — two fleet-wide stalls, logged with root cause.

C-009 · Jul 7

Signed cross-model consensus

Two blind analyses by the second model vs. the lead's blind position, one conferral round, a signed consensus: the lead drives pipeline streams directly; directors only where genuine mid-stream judgment is needed. The same review overturned two of the lead's own record-keeping schemas.

C-010 · Jul 8

Validated

First full session under the new topology: four streams, resume through merge, zero coordination stalls, zero manual interventions. The consensus is now the stamped default.

Two ledgers watch the process itself

Per-layer yield: every review layer's unique catches, attributed and tallied per session. Zero unique catches for two sessions → the layer is dropped. One already has been.

Delegation calibration: every delegated unit gets a row — task altitude, outcome (assigned by the lead after the gate, never self-reported), and rework minutes, with prompt-defects separated from model-defects. Delegation boundaries move on this evidence, not intuition.

Rules that make history trustworthy

History is immutable: ledger entries and dated records are never rewritten — wrong decisions get SUPERSEDED entries on top, so the mistake and its correction are both permanent record.

Single-writer-per-fact: every number lives in exactly one home; prose summaries carry as-of dates and defer to the checklist matrices. A delegated consistency sweep hunts drift before every bookkeeping commit.
