How much energy does
a machine spend on a thought?

JouleWise is a benchmark harness that measures the energy of large-language-model inference on real, local hardware — joule by joule, token by token — and packages every measurement as a self-contained evidence bundle that anyone can re-derive from raw telemetry. You don't have to trust the summaries: the validator recomputes them from the evidence.

The idea

Energy is the spine. Everything else must be auditable.

Every benchmark run produces a run bundle: the typed config that requested it, the raw power telemetry exactly as the meter emitted it, the token-level event log, and the derived summary — all in one directory. The core rule of the project is that summaries are never trusted, they are re-derived: a strict validator recomputes the power trace from the raw meter output, recomputes the summary from the trace and events, and refuses any bundle where stored numbers disagree with recorded evidence.

Measurements subtract each machine's idle baseline, name their measurement boundary (what the meter can and cannot see), and record provenance down to a hash of the exact token IDs the model was fed — so "same workload" is a checkable claim, not a promise.

Guaranteed capstone

Auditable local LLM energy measurement

The harness itself plus the Apple-Silicon characterization it already executes: per-model, per-workload energy with confidence intervals, contamination detection, and full re-derivability. This exists today and grows with every campaign.

measuring now
Differentiating study

Split inference: does dividing the thought save energy?

Run prefill on one machine and decode on another, shipping the model's working memory (the KV cache) between them. Under what conditions does the split beat either machine running alone — and what does the crossover cost in latency? The feasibility rung is already proven: a saved cache resumes token-identically in a fresh process.

feasibility proven · hardware pending
First findings

The big model costs time, not watts.

Two confounded points are not a law — the project's own docs say so loudly. But the first cross-model comparison is already interesting: a model 80× larger drew nearly the same decode power. It just held the machine longer per token.

Energy per token rose ≈6.7× while decode power rose ≈17% — on these two points, inference energy behaves like a fixed-plus-marginal cost, not a power problem.

Consistency with the Q4 model on two confounded points, not a demonstrated scaling law; the two-model baseline campaign (next step) begins the controlled version. Full numbers on the results page.

How it's built

The process is the second instrument.

This project is developed by one researcher directing a multi-model AI system — an orchestrating lead model, an independent second model doing implementation and adversarial review, and a review pipeline in which every claim, decision, and dissent is written down: 36 binding design decisions, a ten-entry council deliberation log, per-stream decision ledgers committed with the code they justify, and per-review-layer catch records that decide — by evidence — which review layers live and die.

In one recent overnight session the system resumed four parallel work streams, ran ~26 delegated implementation and review sessions, caught ~30 attributed catches across nine distinct review layers — including two wire-protocol contracts that were confidently wrong — and merged all four pull requests with the test suite growing 415 → 546.
