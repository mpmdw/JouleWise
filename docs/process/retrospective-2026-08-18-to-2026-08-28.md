## Summary

Between August 18 (run report 2026-08-18) and August 28 (RUN_STATE T27), JouleWise moved from a working but unstable measurement instrument to a thoroughly challenged one, without yet starting the claim-bearing campaign. A measurement window is a quiet period when Ed's Mac is reserved for energy measurements; a transaction is the scripted sequence that freezes inputs—records their exact bytes and cryptographic digests—runs the measurements, and produces data the paper may claim. The third-generation transaction package, called `_v3` (RUN_STATE T17), expired before use, so future claim-bearing work belongs to a new fourth-generation package, called `_v4` (run report 2026-08-22). Fresh-checkout rehearsals, independent reviews, and literal readings of the operator instructions exposed defects in sequencing, path identity, statistical pre-registration, collection metadata, finalization, continuous integration, and the orchestration loop. Progress is not an energy result: many ways of wasting a costly campaign now fail before measurement. The remaining sequence is the statistical cure and reviewed-pin refresh, estate 11, then the live mini-run of about twenty minutes (PR #209; RUN_STATE T27); that run must reach final analysis and answer for a measured-data reason rather than a missing contract input.

## The issues

### Expired evidence compelled a new transaction family

The physical cause was time, not corrupt bytes. Qualification evidence had a twenty-four-hour lifetime (run report 2026-08-20 T17), and the project did not reach a quiet measurement window before that lifetime ended. The process cause was that qualification, registry rulings, repairs, and freeze work took longer than the evidence horizon while the plan still treated `_v3` as runnable. The expiry replay check found the lapse mechanically, and the lead refused to extend or reinterpret the old evidence. Its cost was the loss of the prepared `_v3` campaign opportunity and a complete new-family transaction; the record does not assign a smaller number of days or pull requests to the lapse alone. The cure was to close the old path without changing its frozen bytes and move every future claim-bearing input to `_v4`, whose minting authority was granted on August 22 (run report 2026-08-22). This preserved replay of the old family at its historical checkout instead of pretending current code could validate it.

### Fresh-checkout rehearsals stopped on real defects

An estate is a scripted clone-and-prove rehearsal against a fresh repository checkout, with no claim-bearing measurement. Ten estates were cut; the first nine stopped on real defects and the tenth completed (run report 2026-08-25). Each stop identified a concrete failure:

- The first estate (run report 2026-08-25) froze all packages before committing any of them, so the second freeze saw a dirty checkout. The cure interleaved one package's freeze with its commit.
- The second estate (run report 2026-08-25) found that the authentication author could not derive required inventory extras. The projected authentication contract was repaired (PR #178; git log).
- The third estate (run report 2026-08-25) showed that the shell expanded the clone-path variable too early and tried to open a script at the filesystem root. The run instructions were corrected on main.
- The fourth estate (run report 2026-08-25) showed that backticks in the correction comment executed as shell syntax; even the cure violated the instruction's own quoting rule. The comment was corrected on main.
- The fifth estate (run report 2026-08-25) reached the first successful package mint, then found that the publication-marker builder demanded a successor digest that could not yet exist. The builder/validator boundary was repaired (PR #184; git log).
- The sixth estate (run report 2026-08-25) found both a circular record order and a missing human-confirmed digest at every consumer. The attempt was struck, meaning its positive results could not be carried forward as proof, and the record-order and supply-line repairs landed (PRs #186–#188; git log).
- The seventh estate (run report 2026-08-25) found that moving identical package bytes to a new checkout changed an absolute folder name and caused every freeze replay marked as a new case (`new_case`) to refuse. That attempt was also struck; successor replay comparison was repaired (PR #192; git log).
- The eighth estate (run report 2026-08-25) stopped because the preceding repair shifted source line numbers that the rehearsal had pinned. The anchor map was refreshed (PR #193; git log).
- The ninth estate (run report 2026-08-25) found six bad-input tests whose intended checks were hidden behind earlier refusals. Five probes were reshaped to reach their targets; the sixth was replaced because its intended gate was unreachable by design (PR #194; run report 2026-08-25).
- The tenth estate (run report 2026-08-25) completed every block with no failures, including the repaired probes and post-mint comparison.

The cost was ten fresh clones and nine repair cycles (run report 2026-08-25); no live window was spent. The exact assignment of the two shell failures to the third and fourth estates rests on transcripts and an instruction comment rather than one explicit summary statement (run report 2026-08-25).

## Lessons

### Sweep decisions for installation, not merely for prose

Mechanism: extract every decision sentence requiring code, configuration, an instruction, or a test; locate the producer of the affected bytes; run the mistake case; and require refusal before costly work. Count a rule as installed only when the artifact and producer-side check both exist. Across the specified decision range, this inspected 460 clauses, found 122 without producer-side enforcement, and shortlisted thirteen numbered items plus subfinding S9-01b—fourteen listed findings, although the related Git subject calls it a “13-item shortlist” (ruled-not-installed sweep SHORTLIST; PR #210 git subject). The worked example is the statistical family: the validator existed, but no production caller invoked it. Running this before each transaction catches reviewed decisions never connected to execution.

### Use independent blind reviews when a design premise controls a campaign

Mechanism: use three seats—bounded, single-purpose model reviews (D-157)—and give the same question and sources independently to Sol, and to Opus and Fable (the Anthropic models). Hide earlier answers; then have the lead compare file-and-line claims and rule. The statistical review found the same generator, validator, and consumer facts across all three (D-157). The smoke-corpus review corrected an impossible synthetic-data plan: no current path produced a claim-consumable synthetic bundle without production changes (D-160). This catches shared assumptions only when a reviewer executes the path or proves it cannot execute.

### Test each defensive refusal against plausible mistakes

Mechanism: for every hard refusal, determine whether it catches a plausible operator mistake or only deliberate action (D-161). Keep refusal if the mistake could change physics, evidence, pre-registration, or recoverability; otherwise retire it or warn after the transaction. Historical pin equality protects pre-registration and stays hard, while current-side equality blocked Ed's reviewed regeneration and moves to a reviewed refresh route (D-161). This catches controls whose cost exceeds the stated risk.

### Close the wake gap with a durable completion signal

A wake gap is when a bounded model session finishes or dies but the coordinator is not resumed to harvest it. Mechanism: Codex runs use status and output files when available; pushed branches and worktrees are the durable recovery source (checkpoint 2026-08-27 PM). The coordinator must foreground-poll the status file; monitors do not resume the director automatically (DIRECTOR-BRIEF). A restart checks preserved branches before re-briefing (checkpoint 2026-08-27). The worked failure is the August 22 thread that left about 1,700 lines uncommitted; preservation saved it, but later review determined completeness (RUN_STATE T20). This catches silent completion, transport death, and context exhaustion without treating preserved work as verified.
