## Summary

JouleWise measures the energy a language model consumes on a laptop and attributes it to phases of inference. The paper depends on reproducing those measurements from a fresh repository copy; the ten days below tested that ability.

Between August 18 (run report 2026-08-18) and August 28 (RUN_STATE T27), JouleWise moved from a working but unstable instrument to a thoroughly challenged one without starting the claim-bearing campaign, the roughly 168-hour measurement period reported in the paper. A measurement window reserves Ed's quiet Mac for energy measurements. A transaction seals inputs by recording their exact bytes and cryptographic digests, runs measurements, and produces usable data. A digest is a short fingerprint computed from bytes. A package is a sealed campaign directory of workload, configuration, and custody files; it records model identities and weight digests rather than containing the model files.

The third package generation, `_v3`, expired before use, so claim-bearing work moved to `_v4` (RUN_STATE T17 — `RUN_STATE.md` is the running status file; T-numbers are successive checkpoints; run report 2026-08-22). Rehearsals use a repository downloaded from scratch, called a fresh checkout. They and independent reviews exposed failures in step order, folder names mistaken for content, statistical pre-registration—declaring comparisons and rules before collection—information recorded beside measurements, final sealing, continuous integration—the hosted automation that runs configured checks on configured events such as pushes and pull requests—and the loop that hands work to model sessions for implementation and review.

Progress is not an energy result: many campaign-wasting defects now stop before measurement. Remaining are the statistical fix, re-approval of the pinned file list—the reviewed files whose bytes must not change—the eleventh fresh-copy rehearsal, called estate 11, and a live mini-run of about twenty minutes (pull request #209; RUN_STATE T27 — a pull request is a proposed batch of changes submitted for review; it may or may not be merged). The mini-run must reach analysis; any refusal must come from measurements, not a missing file, argument, or fingerprint.

### A ruled statistical design had never reached the generator

The plan required one test family—the group of hypothesis tests sharing one false-positive budget—with two comparisons: prefill, when a language model reads the prompt, and decode, when it emits one token at a time. A Holm correction, which tightens thresholds when several tests share that budget, held the two-test family to a 5 percent chance of any false positive. The production script instead emitted only a size-one decode test, left the prefill test and its instrument-detection-floor reference empty, and omitted the test family block. The detection floor is the required attribution-and-uncertainty threshold, including the required drift allowance; it is not merely the meter-noise threshold. A correct validator existed but nothing called it while minting or sealing (D-139 A2; D-157).

A human found the contradiction; three reviews verified it in code. Without the two-test correction, the family-wise false-positive rate can be about 9.75 percent under two independent null tests. Final analysis refuses a declared test missing from the pre-registered plan, so absent prefill would stop the project only after 168 hours. The cure installs both comparisons and detection-floor references, regenerates packages, and validates at mint; this requires estate 11. Estimated cost was half to one delegated day, ten minutes of Ed's time, and re-sealing three local model packages, moving the earliest night from August 28 to August 29 or 30. The pinned-file refresh remained (pull request #209; RUN_STATE T27).

## Lessons

### Sweep decisions for implementation, not merely prose

Extract every decision sentence requiring code, configuration, instructions, or tests; locate the producer of the affected bytes; run the mistake case; and require refusal before costly work. A rule is implemented only when both the required file or record and its producing check exist. The audit covered decisions D-117 through D-157 plus unattributed rulings from the same era. It inspected 460 clauses and found 122 without producer-side enforcement (ruled-not-installed sweep METHOD; FINDINGS-TABLE). The statistical test family is the example: the validator existed, but no production caller invoked it. Running this audit before each transaction catches reviewed decisions never connected to execution.

### Use independent reviews when a design premise controls a campaign

Give the same bounded question and sources independently to Sol and to Opus and Fable, two Anthropic language models. Hide earlier answers, then have the lead session compare source-backed claims and rule. The reviews used Sol, Opus, and Fable independently for cross-model diversity; the record does not quantify its effect on blind spots. All three reviews found the same generator, validator, and downstream facts in the statistical case. Review of the smoke workload set also corrected an impossible plan: no existing code could generate fake measurements in a form analysis would accept without changing the production code it was meant to test (D-157; D-160).

### Test each defensive refusal against plausible mistakes

For every hard refusal, ask whether it catches a plausible operator error or only deliberate action. Keep it when a mistake could change physics, evidence, pre-registration, or recoverability; otherwise retire it or warn after the transaction. Requiring previously sealed historical package bytes to match their recorded fingerprints exactly protects the pre-registered plan from later editing, so that check remains hard. Current-generation equality instead blocked reviewed regeneration and moves to a reviewed refresh route (D-161).

### Close the wake gap with a durable completion signal

A wake gap occurs when a delegated run finishes but the model session overseeing it is not re-invoked. Codex runs use status and output files when available. More reliable recovery comes from its preserved branch and worktree—a separate repository copy attached to that branch (checkpoint 2026-08-27 PM). That session must repeatedly check status in the foreground; the main loop is still guaranteed a wake (DIRECTOR-BRIEF). A restart checks preserved branches before issuing the work again.

The August 22 example left about 1,700 uncommitted lines. The work was saved, but whether it was complete had to be established by reading it afterward: preservation is not verification (RUN_STATE T20). This catches silent completion, connection death, and text-capacity exhaustion without treating saved work as verified.
